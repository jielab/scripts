6,086 个条目中，6,042 个有主染色体位置，11 个仅有替代序列位置，33 个缺失。

蛋白 cis 标记只接受 GRCh38，使用 `POS ± 500,000 bp`；队列字段的分号别名（包括 `.1` 后缀）按名称精确匹配。
UKB 的 `.Cardiometabolic/.Inflammation/.Neurology/.Oncology` 面板后缀（含 `_II`）可回退到原蛋白名称。
图状态保存名称表路径、SHA256 和队列；修改坐标表后会重新生成图。

## 2026-11-05：按表型提交 REGENIE

从登录节点提交 `gwas.sh regenie --pheno-name bmi,height,ldl --type qt` 时，默认生成三个独立 LSF 作业。
每个作业只运行一个表型，保留 Step 1 → 并行 Step 2 染色体 → 汇总的依赖和原结果目录。
作业名为 `regenie.[type].[pheno]`，例如 `regenie.qt.bmi`、`regenie.bt.bald12`；不附加分析目录。
`--type auto` 按现有表型规则推断名称。
`--phenotypes` / `--traits` 和 `run_regenie` 别名同样支持。非法或重复表型在提交前拒绝。

`--jobs` 仍表示每个表型内部的染色体并发；新增 `--pheno-jobs N` 限制同时运行的表型作业数，默认允许全部独立调度。
CPU/RAM 参数均为**每个表型作业**的预算：默认每个作业计算使用最多 24 线程，队列 33 按站点规则预约 40 slots、160 GiB。
三个表型同时运行时共预约 120 slots、480 GiB；队列有足够资源时可缩短总等待完成的时间，不保证线性加速。
规划输出显示每作业预算和最大并发数；手动执行保存计划时使用它打印的 `--jobs-N` 参数保持该并发上限。
公共 allele counts / extract 的检查、生成和计划写入受共享锁保护；准备完成后释放锁，各表型独立计算。
染色体选择日志按 job ID 分开。已有运行中的作业继续原顺序；`--submit local` 或已有 LSF allocation 中的调用也保持串行表型，不嵌套提交。

本改动保持原来每表型的样本筛选和独立模型；没有切换到 REGENIE 多表型批处理模式。
多表型批处理可以复用部分计算，但需要另行评估缺失值与 `--strict` 的样本选择规则。

## 2026-11-04：UKB 与 REGENIE

路径由相邻 `0f/0os.sh` 决定；R 的路径适配器为 `0f/0os.R`。`phe4gwas` 默认输出 `$DIR_UKB/ukb.phe`。
`bash gwas.sh -h` 显示当前环境可复制的命令，默认提交 HPC；本地执行显式加 `--submit local`。
UKB 默认协变量为 age、sex、PC1–PC4；独立 CIMT 协变量文件默认使用其中所有非 ID 列。
`bald --type ordinal` 使用 `--qt --force-qt` 检验 1–4 分的线性趋势，不是有序 logistic 回归。
二分类使用 0/1 和 approximate Firth；生存分析明确传入持续时间与 0/1 事件列。

chrX 使用原 imputed PGEN，按 `--grch` 设置 `--par-region b37/b38`；不更改基因型剂量，不删除 PAR。
`--sex male` 同时传给两个步骤。REGENIE 默认要求完整的 1–22、X；有意只分析部分染色体时显式指定 `--chr`。运行前一次列出缺失、空文件及 `.filepart` 未完成传输，失败时不启动 GWAS 工具。
拟合前检查 FAM/PSAM 性别一致性、样本交集和 PVAR 的 X/PAR 标记；错误会停止。
这项检查不能证明 PGEN 本身的编码正确。默认剂量补偿要求男性非 PAR X 为 0–2 标度。
具体参数见 [REGENIE 官方说明](https://rgcgithub.github.io/regenie/options/)。
本地 REGENIE v4.1.gz 合成数据测试包含男性单倍体非 PAR 输入及两端 PAR，两个步骤筛选 160 名男性，20 个 X 位点全部产生结果。

## 运行层更新

- 入口和 Python helper 不再依赖写死的 `/mnt/d/scripts`、`/mnt/f`。从实际代码位置加载相邻 `0f/`，参考和软件路径遵循统一 local/HPC 配置。
- 新增 `--submit auto|local|hpc`；`auto` 检测 `bsub` 或 `LSB_JOBID`。HPC 登录节点只写计划并提交；数据扫描、GRCh 检测、格式化和统计分析都在计算节点执行。
- REGENIE 的 HPC 提交按表型拆分 allocation；其它 pipeline 保持一个 allocation。原染色体并发、REGENIE Step 1→Step 2→汇总、PGS 评分→合并和结果复用逻辑保留。`--jobs` 是作业内并发数。
- CPU/RAM 预算覆盖并发进程；format 的 PLINK clump/COJO 准备、GCTA、PGS/EAF 使用明确线程/工作内存参数。已有 LSF allocation 会检查 CPU 数，不嵌套提交。
- format 协调器用共享目录锁；临时目录用节点名和随机后缀，避免误删另一节点同 PID 的目录。
- 旧 `--submit-bsub TRUE` 映射到统一 HPC 调度。旧 `format --data-root` / `--dir-data-root` 保留默认 `files/`、`software/` 和 sentinel SNP 表的位置语义；代码 helper 从实际安装位置加载。

本次没有更改等位基因方向、37→38 转换算法、筛选阈值或 REGENIE/SAIGE 统计模型。`--hm3 FALSE` 仍保留完整 GWAS；`.thin.gz` 仍是独立绘图副本。

## 示例

### local 格式化

```bash
cd /mnt/d/scripts/gwas
bash format.sh format --submit local \
  --dir-raw /mnt/d/Downloads --dir-out /mnt/f/gwas/main --label main \
  --grch auto --hm3 FALSE --thin TRUE --jobs 2 --run-cmd TRUE
```

原始数据明确全部为 37 且需要转 38 时，改用 `--grch 37 --liftover TRUE`；已经是 38 用 `--grch 38`，不再 lift。
原 `<project>/<category>/<trait>/{gwas,magma,pgs,qc}` 布局保持。

### HPC 计划与提交

```bash
cd /work/sph-huangj/scripts/gwas

# 不读取原始数据，只生成 plan.json 和 .cmd，不提交。
bash format.sh format --submit hpc --plan-only \
  --dir-raw /work/sph-huangj/data/gwas/raw --dir-out /work/sph-huangj/data/gwas/main \
  --label main --grch auto --hm3 FALSE --jobs 4 \
  --queue short --cores 40 --memory-gb 160 --hours 120

# 正式提交；需要等待成功完成时加 --wait TRUE。
bash format.sh format --submit hpc --run-cmd TRUE \
  --dir-raw /work/sph-huangj/data/gwas/raw --dir-out /work/sph-huangj/data/gwas/main \
  --label main --grch auto --hm3 FALSE --jobs 4 \
  --queue short --cores 40 --memory-gb 160 --hours 120
```

short 至少 40 slots 沿用仓库站点约定；其它站点/队列明确指定资源。
`--memory-gb` 是整项作业预算；`--memory-scope site_host|host|task` 控制 LSF rusage 的站点约定，默认 site_host 与本仓库一致。
format 的工具默认 `--tool-threads 2 --tool-memory-mb 8192`，PGS 默认每进程 8192 MiB；总预算覆盖 `--jobs` 个并发工具与余量。

### REGENIE 与准备步骤

```bash
# local：每进程 4 线程、24,000 MiB，最多 2 条染色体并行。
bash gwas.sh regenie --submit local --grch 37 \
  --pheno-name height --type qt --threads 4 --jobs 2 --memory 24000

# HPC：三个独立表型作业，最多两个表型同时运行；每表型最多 4 条染色体并行。
bash gwas.sh regenie --submit hpc --grch 37 \
  --pheno-name bmi,height,ldl --type qt --pheno-jobs 2 --threads 4 --jobs 4 --memory 24000 \
  --queue short --cores 40 --memory-gb 160 --hours 120 --wait TRUE

bash gwas.sh acount --submit hpc --grch 37 --threads 4 --jobs 4 --plan-only
```

sparseGRM 同样支持两种模式。`--memory` 是单个 PLINK 的 MiB；与整项 `--memory-gb` 不同。
GWAS 默认 queue 33、`--jobs 6 --threads 4`，每个作业最多使用 24 计算线程，按站点规则申请 40 slots / 160 GiB。超出队列预算时明确报错，不自动换队列；需要时显式选择 `--queue auto` 或其它队列。96 GiB 工作站宜明确指定 `--jobs 2`。

## 计划、失败与复用

- 两种模式的 `--plan-only` 都只生成外层计划，不扫描数据。
- HPC 的 format/gwas `--run-cmd FALSE` 或 LDSC `--run FALSE` 也只生成外层计划。计划里的 worker 是完整的可执行请求；程序打印运行这份计划的命令。
- local 保留原 `--run-cmd FALSE` 的内部命令生成行为，可能检查输入，但不运行关联工具。
- 每个计划有独立目录、日志、状态和提交 receipt。失败提交不盲目重试，先核实 receipt 是否已有真实 Job ID。
- 新调度目录不代表重算；科学结果/缓存按原规则复用。更新代码后重生 `.cmd`，保持原数据、缓存及输出目录。
- 不要在任务仍读取旧脚本时原地替换它使用的代码。`--replace TRUE` 仍代表用户明确要求重算；本次包不自动启用它。
