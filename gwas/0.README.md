## gwas — usage notes

Run the public script with `-h` for minimal usage and an example with options. These examples are alternatives; complete workflows, prerequisites and detailed options follow.

### gwas.sh — detailed reference

```text
cd /mnt/d/scripts/gwas

# Requires /mnt/d/data/ukb/common/ukb.phe; phenotype preparation: ../ukb/phe.sh -h.
./gwas.sh prep_gwas --grch 37 --sparse-grm TRUE --threads 4 --jobs 8
./gwas.sh prep_regenie --grch 37 --threads 4 --jobs 8
./gwas.sh run_regenie --grch 37 --pheno-name height,bald,bald12,cvd_cad.Yt2e,cvd_cad.t2e,cvd_cad.adu --threads 4 --jobs 8
```

`gwas.sh` 的默认分析结果目录为 `/mnt/d/analysis/gwas/self/common`。

### format.sh — detailed reference

耗时生成、可复用的标准化汇总数据仍保存到 `/mnt/f/gwas/<label>`。
命令文件、运行日志、协调状态和默认工作缓存保存到
`/mnt/d/analysis/gwas/format/<label>`；可用 `GWAS_WORK_ROOT` 显式指定工作目录。
旧 `.project` 下的完成状态仍可读取，已有正式结果不会因工作目录变更而重算。
Shiny LD 浏览缓存使用一个 `ld_cache.sqlite`，坐标缓存使用 `positions-GRCh37.npz`
或 `positions-GRCh38.npz`，文件内部保留完整输入身份校验。

```text

Combine modules with commas, for example: format,liftover.

Project and execution:
  --dir-raw DIR --raw-file FILE --gwas NAME[,NAME] --label LABEL
  --dir-out DIR                Default: /mnt/f/gwas/<label>
  --category common           Output: <project>/<category>/<trait>/{gwas,magma,pgs,qc}
  --dir-clean DIR             Restrict to one trait's gwas folder
  --grch auto|37|38           Detect the build per GWAS by default
  --chr-prefix TEXT          Strip a literal leading CHR prefix; default ""
                            Legacy automatic stripping of "chr" remains supported.
  --col-map SOURCE:TARGET,...  Override automatic header aliases; repeatable
                            Targets: SNP,CHR,POS,EA,NEA,EAF,N,BETA,SE,P,LOG10P
                            Example: --col-map 'effectAllele:EA,otherAllele:NEA'
                            Source names match literally, ignoring case; missing,
                            ambiguous, or repeated mappings are errors.
                            SNP may be absent: CHR:POS:EA:NEA supplies an initial ID.
  --jobs 4 --replace FALSE --run-cmd FALSE --foreground TRUE --submit-bsub FALSE
    Resume checks output file names only, without reading data or indexes.
    Use --replace TRUE to recompute after changing analysis settings.
  --delete-raw FALSE          Delete raw only after all requested modules succeed
  --rsid TRUE --rsid-unmatched drop|keep
    Convert non-rsIDs using build-specific dbSNP CHR/POS and both alleles.
    Default drop: unresolved rows go to qc/[trait].rsid.unresolved.tsv.gz.
  --dbsnp FILE --rsid-cache DIR  Optional mapping reference/cache overrides
    Mapping results are reused in blocks of 100,000 rows only after checking all
    SNP/CHR/POS/EA/NEA values and their order. Trait statistics are never cached.
    Changed blocks reuse the position cache and query only new dbSNP positions.
    Nearby requested coordinates share tabix intervals; only exact positions
    are recorded in the cache. Concurrent workers build each map once.
    qc/[trait].rsid.tsv reports block_cache_hit_rows and block_cache_miss_rows.
  --local-io AUTO|TRUE|FALSE   AUTO uses local scratch/caches for local WSL runs
  --local-cache DIR           Default: /tmp/gwas-cache-<uid>/format (references/rsIDs)

    --fill-eaf TRUE caches indexed chromosome frequencies under references/eaf;
    reference files, PLINK binary, and population keep-file identify each cache.
    EAF construction defaults to 2 threads / 2048 MB per builder; override with
    GWAS_EAF_THREADS / GWAS_EAF_MEMORY_MB.
    lead lazily copies full clumping (.pgen/.pvar[.zst]/.psam) and COJO
    (.bed/.bim/.fam) panels to references/lead-genotypes, and population keep
    files to references/lead-keep. Only chromosomes with candidates are copied.
    Compact BGZF/CSI coordinate indexes and ambiguous-ID lists are shared in
    references/lead/index-v3. Each reference is scanned once per version;
    later traits query only their candidate positions. File locks and atomic
    publication protect concurrent builders; path/size/nanosecond mtime changes
    select a new cache generation. --replace TRUE does not rebuild valid caches.
    --local-io FALSE still reuses coordinate indexes in the project work cache,
    but reads the original genotype files. All three lead analyses are retained.
    Existing project rsID caches are imported once; explicit --rsid-cache wins.
    GWAS_POST_TMP_BASE overrides the default /tmp/gwas-post-<uid>/<project>/<steps>.
  --sample-info FILE          TSV: phenocode,num_samples or num_cases,num_controls;
                              also accepts GWAS,N. Optional grch=37/38 column
                              supplies each build with --grch auto. Fills missing N.
  Explicit magma requests run by default unless --run-cmd is supplied.

Key analysis settings (all defaults are editable below in this script):
  --hm3 FALSE --p-hm3 1e-3 --fill-eaf FALSE --fill-n [NUMBER] --n-total NUMBER
  --thin TRUE --thin-chr-max 10000
    --hm3 FALSE: [gwas].gz keeps all standardized SNPs.
    --hm3 TRUE: [gwas].gz keeps HM3 SNPs or P < --p-hm3 (default 1e-3).
    --thin TRUE independently creates [gwas].thin.gz, even with --hm3 FALSE:
      HM3 or P < 1e-3 -> thinP0 on P > 1e-3 -> strict per-chromosome cap.
    With --hm3 TRUE --thin TRUE, --p-hm3 must be at least 1e-3.
    If P<=1e-3 alone exceeds the cap, retain the strongest signals and record counts.
    Thin writes [gwas].thin.gz, .tbi and .done; --replace FALSE reuses valid results.
    The standalone thin module processes existing standardized GWAS, without raw files.
    mplot reuses existing thin data regardless of .done paths, even with --replace TRUE.

    Generated GCTA COJO commands include --diff-freq 1.0, allowing the full
    frequency difference between summary statistics and the LD reference.

    PGS then writes a header-only result and a completion marker.

  --magma-ref PREFIX --gene-loc FILE --synonyms FILE --window 0,0 --sample-size NUMBER
```

### compare.sh — detailed reference

```text
Usage: compare.sh compare|ldsc|shiny [options]

Shared options:
  --dir-project, --dir-gwas DIR  Discover <DIR>/<category>/<trait>/gwas/<trait>.gz
  --gwas-files A.gz,B.gz        Explicit inputs; use this OR a project directory
  --category common            Project category (default: common)
  --anchor NAME                Put this project trait first
  --grch 37|38                 Compare build (default: input build) / initial shiny build (default: 37)
  --require-grch 37|38         Require finalized inputs in this build
  --dir-output, --dir-out DIR  Default: /mnt/d/analysis/gwas/<module>
  --check-only TRUE|FALSE      Write input manifest without starting a module (FALSE)

compare options (first GWAS versus each follower):
  --labels A,B                 Optional labels matching input order
  --compare-beta TRUE|FALSE    Effect-size comparison (TRUE)
  --compare-EAF TRUE|FALSE     Allele-frequency comparison (TRUE)
  --p-threshold 5e-8           Significant-variant threshold
  --significant first|either|both  Significance selector (first)

ldsc options:
  --dir-ldsc-software DIR      LDSC checkout (default: /mnt/d/software/ldsc)
  --conda PATH --conda-env NAME Conda executable and environment (ldsc)
  --python PATH               Explicit LDSC interpreter; bypass conda
  --merge-alleles FILE         HM3 allele list
  --ref-ld-chr PREFIX          Reference LD scores; preserve trailing / or dot
  --w-ld-chr PREFIX            Regression weights
  --N NUMBER                  Explicit fallback when input has no N column
  --missing-n error|skip       Missing sample-size policy (error)
  --run-munge TRUE|FALSE       TRUE: prepare caches; FALSE: use adjacent sumstats.gz (TRUE)
  --run-h2 TRUE|FALSE          Estimate heritability (TRUE)
  --run-rg TRUE|FALSE          Estimate genetic correlations (TRUE)
  --run TRUE|FALSE             Execute LDSC; FALSE writes commands only (TRUE)

shiny options (interactive Shiny Manhattan tracks and LD block boundaries):
  --labels CSV                Optional track labels in input order
  --races CSV                 Optional ancestry labels; default: filename suffix
  --dir-block DIR             [race].[37|38].bed files (default: /mnt/f/LD/block)
  --dir-ld DIR                PRS-CSx HDF5 root (default: /mnt/f/LD/csx)
  --ld-python PATH            Python with h5py/numpy/pandas (default: ~/anaconda3/bin/python)
  --ld-max-snps 300           Shared display SNP limit for the five LD panels (2–1000)
  --port 3841 --host 127.0.0.1 Local Shiny server address
  --launch-browser FALSE      Open a browser automatically (TRUE|FALSE)
  --max-points 12000           Maximum displayed points per track; zoom for detail
  --p-threshold 5e-8           Significance guide line
  --dir-chain DIR             UCSC chains (default: /mnt/d/files/liftOver)
  --liftover-bin PATH          Default: /mnt/d/software/bin/liftOver
  --dir-reference DIR          Indexed BGZF FASTA under 37/ and 38/ (default: /mnt/f/gen/1hgp)
  --dir-gene DIR               glist.37.bed / glist.38.bed (default: /mnt/d/files)
  shiny prefers adjacent .thin.gz files when available; compare/ldsc use full GWAS.
  Shiny inputs must share one source build. The GRCh selector converts cached
  viewing copies together; source GWAS files are never rewritten.

Examples:
cd /mnt/d/scripts/gwas
gwas_root=/mnt/f/gwas/4grid/common

# 1. All 15 GWAS: height.EUR versus the other 14, using only SNPs with
# P <= 5e-8 in height.EUR. Inputs must share a build for CHR/POS matching.
# For mixed builds, add --grch 38 to align cached comparison copies.
# Output: 14 *.BETA.png and 14 *.EAF.png, plus harmonized data and QC tables.
./compare.sh compare \
  --dir-project "${gwas_root%/*}" --category "${gwas_root##*/}" --anchor height.EUR \
  --compare-beta TRUE --compare-EAF TRUE \
  --p-threshold 5e-8 --significant first \
  --dir-output /mnt/d/analysis/gwas/4grid/compare

# 2. All 15 GWAS: h2 and all 105 pairwise genetic correlations, with rg.png.
# Reuse <trait>/gwas/<trait>.sumstats.gz beside each <trait>.gz; do not munge.
# Every adjacent sumstats file must already exist and contain SNP A1 A2 Z N.
# The configured LD-score reference is shared by all inputs; it is not
# selected by ancestry. Override --ref-ld-chr/--w-ld-chr when appropriate.
./compare.sh ldsc \
  --dir-project "${gwas_root%/*}" --category "${gwas_root##*/}" \
  --run-munge FALSE --run-h2 TRUE --run-rg TRUE --run TRUE \
  --dir-output /mnt/d/analysis/gwas/4grid/ldsc

# 3. R Shiny: the same six height tracks (EUR, AFR, EAS, HIS, SAS, ALL).
# Generate .thin.gz first using format.sh thin (see its examples).
# Hover over a plot and use the camera button to download a PNG.
trait=height
gwas_files=()
for race in EUR AFR EAS HIS SAS ALL; do
  gwas_files+=("$gwas_root/$trait.$race/gwas/$trait.$race.thin.gz")
done
gwas_csv=$(IFS=,; echo "${gwas_files[*]}")
./compare.sh shiny \
  --gwas-files "$gwas_csv" \
  --dir-block /mnt/f/LD/block --dir-ld /mnt/f/LD/csx --port 3841 \
  --dir-output "/mnt/d/analysis/gwas/4grid/shiny/$trait"
```

## GWAS

三个根目录入口与辅助代码一一对应。默认参数及命令示例见各入口的 `--help`。

GPU 审查（2026-10-11）：计算由 REGENIE、PLINK2、SAIGE 等上游程序执行，
当前包装脚本保持 CPU 路径，不增加无实际计算后端的 `--gpu` 参数。
GPU 版本需要单独验证统计内核，不能替代现有二分类 SPA/Firth 行为。

| 模块 | Shell | Python | R |
|---|---|---|---|
| GWAS | `gwas.sh`、`f/gwas.f.sh` | `f/gwas.py` | `f/gwas.inputs.R` |
| 比较、LDSC | `compare.sh`、`f/compare.f.sh` | `f/compare.py` | `f/compare.R` |
| 格式化、后处理 | `format.sh`、`f/format.f.sh` | `f/format.py` | `f/format.R` |

`gwas.py merge` 合并 PLINK/REGENIE/SAIGE 结果，其余子命令负责计划、执行和缓存。`compare.py` 包含 compare/ldsc/shiny 流程，以及 ldsc-run、ldsc-summary、ld-blocks 工具。`format.py` 包含 liftover、h2、magma-ids、yap2018-mpb。`compare.R` 使用 compare/ldsc 模式；`format.R` 使用 thin/mplot 模式。

Shell 格式化流程、任务生成、执行及 BGZF/tabix 索引函数集中在 `f/format.f.sh`。该文件供主入口和生成的任务加载；`--base`、`--worker` 是内部加载模式。LE8 通过 `source .../format.f.sh --index` 只加载索引函数，不启动格式化流程。

`f/format.resume.sh` 在生成任务前批量读取输出目录的文件名，支持 `format/thin/magma/lead/mplot` 及其组合。`--replace FALSE` 下，仅凭所请求模块的结果文件、索引和完成标记名称是否齐全判断，输出 `SKIP existing done`；不读取这些文件的内容，不检查大小、时间戳、参数、指纹或压缩文件完整性，也不调用 tabix。lead 以 `.awk.snp`、`.clump.done`、`.cojo.done` 和已清理的工作目录判断，因此正常的空选择结果也能跳过。文件名不齐全时进入原流程。修改分析参数后需要重算时使用 `--replace TRUE`；liftover、删除原始文件等请求继续走原流程。该检查单独存放，避免改动格式化代码本身的旧 rsID 指纹。

`format` 默认 `--rsid TRUE --rsid-unmatched drop`：已有 rsID 保留；其他 ID 按声明的 GRCh 版本、位置和两条等位基因匹配 dbSNP，不改变效应方向。无法唯一匹配的完整标准化行写入 `common/<trait>/qc/<trait>.rsid.unresolved.tsv.gz`，统计写入 `<trait>.rsid.tsv`。`--rsid-unmatched keep` 保留未匹配的原 ID；`--rsid FALSE` 完全跳过转换。更改筛选策略时可用 `--replace TRUE` 从原始数据重新生成。

`--hm3 TRUE` 先保留 HM3 rsID/坐标或 `P < --p-hm3` 的候选，再转换 ID，并以转换后的 HM3 rsID 或 P 值确认最终保留项。默认阈值为 `1e-3`，不是全基因组显著阈值 `5e-8`。dbSNP 的 BGZF/tabix 副本和按位置查询的结果共用工作缓存目录（非本地模式为 `/mnt/d/analysis/gwas/format/<label>/rsid/`，WSL 本地模式见下文），不同 GWAS 只补查新坐标，包含未匹配结果的缓存；首次使用每个版本需要准备参考索引。`--dbsnp FILE`、`--rsid-cache DIR` 可指定其他参考和共享缓存位置。

rsID 转换按 100,000 行分块，一次扫描标准化输入。每块对完整、有序的 `SNP/CHR/POS/EA/NEA` 计算 SHA-256，并按 GRCh、dbSNP 路径/大小/修改时间隔离。命中 `blocks-v1/` 时直接读取映射，不再逐行访问 SQLite 或解析 dbSNP 等位基因；原 ID、坐标、等位基因或行顺序变化会触发重新解析，仍复用已有位置缓存。`BETA/SE/P/EAF/N` 等性状统计量不进入缓存，HM3/P 筛选和未匹配项的 drop/keep 策略每次重新执行。不同任务通过锁和原子重命名共享结果，损坏的块会重建；QC 中记录 `block_cache_hit_rows`、`block_cache_miss_rows`。该优化减少映射计算，不免除原始文件读取、排序、压缩等工作。

第一次补查位置时，把同一个 16,384 bp 区间内的请求合并后交给 tabix，避免密集位点反复读取同一数据块；返回结果仍按精确请求坐标筛选，额外区间记录不会进入位置缓存。首次 dbSNP BGZF/tabix 索引和缺失位置由持锁的任务构建，其他任务复用结果，无需对每个 GWAS 扫描整个 dbSNP。

WSL 本机运行默认 `--local-io AUTO`：排序和 SQLite 临时文件放在 `/tmp/gwas-post-<uid>/<project-key>/<steps>/`，rsID 缓存放在 `/tmp/gwas-cache-<uid>/format/projects/<project-key>/rsid/`，MAGMA/HM3 参考放在同一缓存根目录的 `references/`。原始数据和最终结果仍位于原项目。旧项目 rsID 缓存首次使用时在持锁后复制，复制件通过 SQLite 检查并恢复中断事务；不覆盖已有的本地缓存。缓存命中的查询直接持共享锁，只有缺失位置才申请写锁并补查。已完成全套请求模块的 GWAS 在复制参考文件之前即跳过，不因这些性能修改重新计算。

`--local-cache DIR` 可修改缓存根目录，`GWAS_POST_TMP_BASE` 可覆盖临时目录；选择 WSL 本地文件系统才能避免 `/mnt/f` 的跨系统访问开销。默认缓存位于 `/tmp`，存在时可复用，清理后会按需重建。显式 `--rsid-cache DIR` 始终优先，不自动搬动用户指定的缓存。`--local-io FALSE` 保留原来的项目内缓存/临时目录，非 WSL 或 bsub 提交默认也保留原行为。修改目录配置只影响之后生成和启动的任务。当前 rsID 缓存仍保留写锁以保护并发补查；不会通过关闭 SQLite 同步或移除锁来加速。

decode/scotland 批量命令显式使用 `--local-io TRUE --local-cache "$HOME/.cache/gwas/format"`，使 Linux 本地缓存能跨运行保留；仅临时文件位于 `/tmp`。`--fill-eaf TRUE` 使用 `references/eaf/v1/<fingerprint>/` 缓存全染色体 1KG 频率，按参考 `.pgen/.pvar/.psam`、PLINK 程序和人群 keep 文件的路径/大小/修改时间隔离；不同人群或参考更新会自动建立新的缓存。每个染色体、人群只运行一次 PLINK `--freq`，以文件锁和最后写入的完成标记保护构建，后续只查询有缺失 EAF 的坐标；已有有效 EAF 保持不变。构建默认使用 2 线程、2048 MB，可通过 `GWAS_EAF_THREADS`、`GWAS_EAF_MEMORY_MB` 调整。lead 的参考索引同样放在本地 `references/lead/`，EAF 临时查询使用任务的本地 scratch。非本地模式将两类缓存放在 `project_work/eaf` 和 `project_work/<category>/lead_reference`。

`lead` 保留距离筛选、PLINK clumping 和 GCTA COJO 三种分析。`--local-io TRUE` 还会按染色体、在首次出现候选 SNP 时，把完整的 `.pgen/.pvar[.zst]/.psam`（及外置 `.pgen.pgi`）和 `.bed/.bim/.fam` 复制到 `references/lead-genotypes/`，人群 keep 文件单独放在 `references/lead-keep/`；不同性状和人群可以共享完整 pfile。PLINK/GCTA 命令使用缓存后的前缀，原基因型顺序和内容不变。参考坐标及等位基因另建紧凑 BGZF/CSI 索引，位于 `references/lead/index-v3/`，后续按候选坐标查询，不再逐性状扫描完整 PVAR/BIM。索引统一 `chrX/X/23` 等染色体写法，保留重复位点和多等位记录；clumping 的重复 ID/多等位 ID 排除表与坐标索引一同构建、复用。参考的真实路径、大小或纳秒级修改时间变化会生成新缓存；并发构建使用文件锁，所有文件完成后原子发布，中断或失败不会留下可用的半成品。首次运行需承担复制和建索引成本，后续包括 `--replace TRUE` 重算时都复用有效缓存。`--local-io FALSE` 不复制基因型，仍在项目工作目录复用坐标索引。

任务生成阶段对每套 clump/COJO 参考和人群 keep 文件仅验证一次，避免几千次重复目录扫描。保留默认 `--replace FALSE` 即可续跑：全部所选模块已完成的性状按文件名直接跳过；如果仅剩 lead/绘图，且格式化完成记录仍有效，复用原来的 N/EAF/rsID 和索引，不重新补频率或重写标准化 GWAS。修改分析参数或参考数据后希望重算已有完整结果时，显式使用 `--replace TRUE`。本地缓存优化只影响重新生成的任务脚本；旧批次需要先停止，再用原命令重新提交。

列识别函数是 `0f/phenotype.sh` 的 `phe_header_names()`，由 `gwas_clean_header_names()` 调用，支持 CKB 的 `EA_FREQ → EAF`、`AA/A2 → NEA`。`--sample-info FILE` 接受 `phenocode,num_samples,num_cases,num_controls` 或 `GWAS,N` 的 TSV，逐性状补充缺失 N，已有有效 N 保留。可选 `grch` 列用于检查显式版本，或在 `--grch auto` 时提供版本；样本量和版本冲突会在启动任务前报错。

`--col-map 'effectAllele:EA,otherAllele:NEA'` 可覆盖自动列名识别，可重复传入或用逗号连接。源列名按字面匹配、忽略大小写，目标限定为 `SNP CHR POS EA NEA EAF N BETA SE P LOG10P`；缺失、歧义或重复的显式映射会报错。默认别名已补充 `rsids`、`effectAllele`、`otherAllele`、`minus_log10_pval`、`AF1`。缺失 SNP 列时可从独立的坐标和等位基因列生成临时 ID，再补 rsID。`--chr-prefix TEXT` 默认为空，按字面去除 CHR 开头的指定前缀；保留原有自动去除 `chr` 的兼容行为。

deCODE 使用 GRCh38；选择 `rsids:SNP` 后忽略冗余的 `Name`。本项目按用户的后续分析用途，显式使用 `--col-map 'ImpMAF:EAF' --fill-eaf FALSE`，将原始 `ImpMAF` 原值写入标准化表的 EAF 列，不做效应等位基因方向转换；列名不表示该值已成为真正的 EAF。首次替换此前使用 1KG 补频率的结果时加 `--replace TRUE`，完成后续跑改回 FALSE。Scotland 使用 GRCh37、`AF1:EAF`；本地前 5,000 个变异与 1KG GRCh37 有 4,886 个坐标及双等位基因匹配，与 GRCh38 仅 38 个匹配。两组命令见 [相关说明](#overview)，均使用 `--hm3 TRUE --thin FALSE --add-panel none`；修改筛选参数后用 `--replace TRUE` 重算。deCODE 直接运行 `format,lead,mplot --grch 38 --liftover FALSE`。Scotland 先运行 `format,liftover --grch 37 --liftover TRUE`，全部成功后再运行 `lead,mplot --grch 38 --liftover FALSE`，使下游参考与转换后的坐标一致；仅在 `format,lead,mplot` 后加 `--liftover TRUE` 不会执行 liftover 模块。结果输出到各自的 `common/` 和 `mplot/`，不生成 thin、MAGMA 或 cis 结果。未匹配 rsID 的行通过命令中的 `--rsid-unmatched keep` 保留并记录 QC。mplot 保留原有内部绘图采样，不生成 `.thin.gz`；组合调用先完成 lead/COJO，再生成图和显著结果表。

COJO 在参考匹配后、按参考 ID 去重前，排除缺失或超出 [0,1] 的 EAF 候选，将原值及原因写入 `qc/<trait>.<chr>.cojo_eaf_excluded.tsv`；其余有效候选继续运行，不再因一条坏记录跳过整条染色体。生成的 GCTA 命令统一加入 `--diff-freq 1.0`，允许汇总数据与 LD 参考的等位基因频率相差 1.0，避免 MAF/EAF 方向差异触发频率差异过滤；该参数不转换频率方向。标准化 GWAS、clump 和绘图输入不受这个 COJO 过滤影响。同一参考 ID 同时有有效和缺失频率的记录时，保留有效记录中 P 值最小的一条。若所有参考匹配候选均因 EAF 被排除，完成标记明确记录 `no_usable_variants_after_eaf_qc`；其他 GCTA 异常仍报错，不伪装为成功。

CKB 已按原始版本拆成 `/mnt/f/gwas/ckb_37`、`/mnt/f/gwas/ckb_38` 两个项目，各自包含 `raw0/`、`raw/`、`ckb_decrypt.sh` 和本版本的 `phenotypes.tsv`。解密脚本接受空格或 Tab 分隔，输出到各项目自己的 `raw/[gwas].gz`。自动扫描 GWAS 时跳过 `decryption_report_*.tsv` 解密报告（含 `.gz`、`.bgz` 压缩版本），保留普通 TSV 数据输入。分析分别指定 `--dir-raw /mnt/f/gwas/ckb_37/raw --dir-out /mnt/f/gwas/ckb_37 --label ckb_37 --grch 37 --sample-info /mnt/f/gwas/ckb_37/phenotypes.tsv`，或对应的 `ckb_38`/`38` 参数；模块及执行参数为 `format,magma,lead,mplot --hm3 TRUE --run-cmd TRUE --foreground TRUE --jobs 4`，不含 PGS。输出分别位于两个项目的 `common/`、`mplot/`。

三个 AWK 文件按归属命名为 `gwas.extract.awk`、`format.hm3.awk`、`format.thin.awk`。Shiny 仍在 `shiny/`；临时验证和测试放在 `/tmp`。没有旧文件名转发脚本。

## Shiny GWAS block browser

Start with `./compare.sh shiny`; its `--help` contains a complete height
example, including `trait`, `gwas_files` and `gwas_csv`. Defaults and CLI settings
remain in `compare.sh`. This directory contains:

- `app.R`: launcher, configuration, reference setup and cache worker entry point.
- `ui.R`: Overview / Blockview navigation, shared IGV header and panels.
- `server.R`: viewport state, interactions and asynchronous workers.
- `data.R`, `plot.R`: GWAS chromosome caches, BED lookup and Manhattan tracks.
- `ld.py`, `ld.R`: PRS-CSx HDF5 reader and population LD heatmaps.
- `ref.R`, `www/`: local FASTA range requests, JavaScript, CSS and bundled IGV.

Keep the launching terminal open; Ctrl+C stops the server. The default URL is
http://127.0.0.1:3841. Use the shell entry point to supply the inputs and defaults;
`ui.R` and `server.R` are sourced by `app.R`.

<a id="doc-shiny-readme--inputs-and-thinning"></a>

### Inputs and thinning

Inputs require standardized `CHR`, `POS`, `P`, with optional `SNP` and `LOG10P`.
Build metadata comes from `file.gz.grch` or the project's `qc/trait.grch`. All
inputs must have the same source build. Labels default to the filename, ignoring
`.thin.gz`; ancestry is its final dot-separated component. `--races CSV`
overrides that label explicitly.

When a full GWAS path is supplied, an adjacent `.thin.gz` takes precedence if it
exists. The viewer checks its generation metadata and refuses stale sidecars.
It still accepts full GWAS when no thin file exists. Generate sidecars with
`format.sh thin` or `thin,mplot`; see that script's complete batch example
for `4grid`, `main`, `met`, and `prot`.

`format` defaults to `--thin TRUE --thin-chr-max 10000`. Independently,
`--hm3 FALSE` keeps the standardized full `.gz`; `--hm3 TRUE` keeps the union of HM3
and P < 1e-3 in that file (threshold: `--p-hm3 1e-3`). Both modes support
`--thin TRUE` or `--thin FALSE`. Reference paths use `--hm3-file` and `--hm3-pos`.
The thin helper independently selects
HM3 SNPs (rsID or build-specific position) and all P < 1e-3 candidates, calls
the actual shared `phenotype.R::thinP0` to prune P > 1e-3 background, and imposes the
per-chromosome total cap. If signals alone exceed that cap, strongest signals
win; `LOG10P` breaks underflow ties. The sidecar preserves original columns and
writes only `[gwas].thin.gz` and `[gwas].thin.gz.tbi`. Each requested thin run
regenerates both files to honor current inputs and settings, and removes legacy
thin `.grch`, `.n.tsv`, and `.meta.rds` sidecars after success. Build metadata
comes from the project’s `qc/trait.grch`; Shiny checks source modification time
for stale thin inputs. `--thin FALSE` disables generation; it does not delete
previous sidecars. Statistical analysis modules continue to use `[gwas].gz`, whose filtering is controlled by `--hm3`.
Mplot uses the sidecar for drawing, and the full GWAS for hit reports/cis flags.

At display time, `--max-points 12000` also limits each track using position-bin
peaks plus background samples. Track captions distinguish actual **shown** points
from all input variants in the current region. Zoom queries the current input
cache again; a thin input cannot restore variants removed during thinning.
Track y scales are independent, and finite `LOG10P` preserves P underflow.

<a id="doc-shiny-readme--overview-and-blockview"></a>

### Overview and Blockview

Overview contains the GRCh dropdown and All / 1–22 / X chromosome bar. IGV,
region entry, zoom and pan share one viewport. Hover anywhere within a track's
BED-covered region to see `block: AFR 123`. Double-click opens Blockview:
IGV, all GWAS tracks, then EUR / AFR / EAS / SAS / AMR LD heatmaps.

The initial region is the selected block plus **one preceding and one following
block**, on that same chromosome. At chromosome ends it contains fewer blocks.
The selected block is shaded. Zoom and IGV changes update both GWAS and LD;
“所选 block ＋ 相邻 blocks” restores the initial region. Returning to Overview
restores its last viewport. Changing GRCh clears the selected block because
BED IDs are build-specific.

Only `[race].[grch].bed` supplies boundaries. Missing files/chromosomes produce
no boundaries and no inferred IDs; HIS is not automatically relabeled AMR.
BED intervals are zero-based half-open: START < GWAS POS <= END. IDs are
one-based row numbers after sorting the complete BED by chromosome/start/end,
across all chromosomes, independently per ancestry and build. All-chromosome
views omit boundary lines but still support block lookup. GRCh37 EAS/SAS use the
published ASN data. Reference provenance and excluded upstream intervals are
recorded under the block directory. `python3 f/ld_blocks.py` reproduces those
references without overwriting different existing BEDs.

<a id="doc-shiny-readme--ld-reference"></a>

### LD reference

`--dir-ld /mnt/f/LD/csx` contains `ldblk_1kg_EUR`, `ldblk_1kg_AFR`,
`ldblk_1kg_EAS`, `ldblk_1kg_SAS`, `ldblk_1kg_AMR` and
`snpinfo_mult_1kg_hm3`. The SNP information file provides GRCh37 coordinates.
For GRCh38, reference SNP positions are actually mapped through hg19ToHg38;
unmapped/non-primary positions are excluded. LD values remain those of the
same 1KG reference genotypes.

The reader follows the [official PRS-CSx HDF5 schema](https://github.com/getian107/PRScsx/blob/master/parse_genet.py):
each `blk_*` contains `snplist` and `ldblk`. HDF5 block IDs do not correspond to
BED block IDs. Matrices are matched by SNP ID and source chromosome, normalized
by their diagonal and shown as r². Missing SNPs and cross-HDF5-block pairs are
white (unknown), never fabricated zeros. Allele sign flips do not change r².

All populations use the same physical coordinate axes and SNP subset. At most
`--ld-max-snps 300` SNPs are sampled evenly along the ordered reference positions
(range 2–1000). Captions give available and displayed counts. Missing population
files and autosome-only reference coverage are reported in their panels.

<a id="doc-shiny-readme--caches-and-dependencies"></a>

### Caches and dependencies

Outputs include `shiny.inputs.json`, `cache/grch37/track_NN/`, corresponding
GRCh38 caches, `cache/ld/` SNP indexes/region matrices, and worker logs. Build
switches convert GWAS viewing copies using the configured UCSC chain; source
GWAS are unchanged and all tracks switch together once ready. Keep separate
output directories for different GWAS collections.

R packages: `shiny`, `bslib`, `plotly`, `htmlwidgets`, `data.table`, `jsonlite`,
`processx`. `--ld-python` defaults to `~/anaconda3/bin/python` and requires
`h5py`, `numpy`, `pandas`. Shell tools: Python 3, gzip/pigz, flock, liftOver,
bgzip/tabix. IGV JS and its license are bundled in `www/vendor/`. Indexed
`37/GRCH37.fasta.gz` / `38/GRCH38.fasta.gz` under `--dir-reference`
(default `/mnt/f/gen/1hgp`) supply local sequence tracks. These must be BGZF
compressed with `bgzip`, with matching `.fai` and `.gzi` indexes. IGV receives
compressed byte ranges and both indexes; it decompresses only the required blocks.
The Python allele reader also uses the GZI block index, with a bounded block cache
and Python's standard library. Ordinary gzip cannot replace these references.
Optional
`glist.37.bed` / `glist.38.bed` supply gene tracks.
