# ld

LD 分析流程，支持 local/HPC。先核对参考人群、基因组版本、输入与资源配置。

在本目录查看参数和示例：

```bash
bash ld.sh -h
```

路径优先使用命令行覆盖；共享默认配置位于 `../0f/0os.sh`。

GRCh38 在 HPC 上默认写入 `/scratch/2026-11-05/sph-huangj/analysis/ld`，
每条染色体的临时 LD 文件也放在这个目录下。输入基因型仍位于 `/work`。
`--date-scratch` 可以选择另一日期；`--dir-out` 可以显式覆盖输出目录。
scratch 的个人配额为 5 TiB，不能用整个文件系统的空闲空间代替个人可用量；
脚本会检查 Lustre 用户和组配额。全量 LD 的位点对数量很大，
重跑前应确认剩余配额，并可用 `--jobs-N 1` 控制临时文件的并发。

按 2026-11-05 管理员建议，队列 33 每节点为 40 核、192 GiB 内存。
取 CPU 和内存占比的较大值，按四分之一节点向上取整，申请 10、20、30 或 40 核。
LD 默认申请 160 GiB，因此自动申请单节点 40 核；合并作业为 4 GiB、10 核。
`-n`/`LD_SLOTS` 指调度槽位，PLINK 线程数由 `THREADS` 单独控制。

```bash
LD_MEMORY_GIB=160 ./ld.sh --grch 38 --chr 1-22 -q 33 -n 40
```

每个染色体作业生成的 bsub 参数为：

```text
-q 33 -n 40 -M 160GB -W 120:00 -R "span[hosts=1] rusage[mem=160GB/host]"
```

需要保留较少 CPU 槽位时，管理员推荐大内存队列：

```bash
LD_MEMORY_GIB=160 ./ld.sh --grch 38 --chr 1-22 -q v4-3t -n 5
# 也可选择 -q v3-6t -n 5
```

`ld.sh` 自动提交染色体作业及依赖它们成功完成的合并作业。
`--write-cmd` 仅生成命令文件，适合提交前核对参数。
修改脚本只影响之后生成和提交的作业；已提交作业保留原资源申请。
