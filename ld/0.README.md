# 1KG Phase 3 祖源与 universal LD blocks：一次运行的独立复现

本目录依据 McManus 等的论文 **A unifying statistical framework to discover disease genes from GWASs**（Cell Genomics, 2023, DOI: [10.1016/j.xgen.2023.100264](https://doi.org/10.1016/j.xgen.2023.100264)）及 **Methods S1**，从本地 1KG Phase 3、GRCh37 phased VCF 计算 AFR、EAS、EUR、SAS 和 universal LD blocks。

这是公开方法的独立实现。作者原始代码及预计算坐标未用于逐坐标对照，因此输出不宣称与作者文件完全相同。有限 D 网格上的边界稳定性也不自动等于无距离限制问题的数学证明。

<a id="overview--1-只运行一个命令"></a>

## 1. 只运行一个命令

在 `ld/` 目录执行：

```bash
/mnt/d/scripts/ld/ld.sh
```

默认输出为 `/mnt/f/analysis/ld`，主要结果位于其下的 `rebuild_v2/`。重跑会验证并复用本版已完成的 PGEN、分块和已通过检查的染色体选参结果。

2026-10-23 已将 D 盘的现有 PGEN、分块、选参结果和运行配置复制并核验到 F 盘，更新了缓存凭据中的位置及其关联摘要；chr22、chr1 可继续复用，chr2 四个群体只缺 40 Mb 档位。D 盘原目录保留作备份，历史性能报告仍在原位置。以后通过同一个 `./ld.sh` 入口写入 F 盘。

一次命令会依次完成：

1. 检查程序、panel、VCF、样本及 phased genotype 数据。
2. 优先核验并复用 chr22 已通过的选参结果；尚未通过时计算多个 D 的祖源分块及各档 universal blocks。
3. 检查完整边界稳定性、输入与输出有效性，以及与论文计数的差异。
4. 自动选择通过检查的最小 D，或沿用已验证的 D；屏幕打印 `SELECTED chr22: D=...` 或 `REUSE validated chromosome chr22`，随后打印 `PILOT PASSED`。
5. 自动继续其余常染色体；复用已通过的染色体，仅对尚未通过或缓存失效的染色体使用当前 D 网格。
6. 所有要求的染色体通过后，汇总祖源及 universal BED，写入 `COMPLETE.json`。

**不需要先执行 pilot，再人工选择 D，最后执行第二条命令。** `./ld.sh`、`./ld.sh run`、`./ld.sh all` 是同一个完整流程。旧版的独立 `pilot`、`population`、`consensus` 等入口不再是本版运行方式；也不再接受手工 `D_KB`。

也可以限定本次计算范围：

```bash
./ld.sh --chr 2         # 只处理 chr2
./ld.sh --chr 2-21      # 跳过 chr1 和 chr22 的新计算
./ld.sh --chr 2,3,6     # 指定多条染色体
```

`--chr` 优先于环境变量 `CHRS`，也支持 `--chr=2-21`。省略该参数时仍默认处理 1–22。范围不包含 chr22 时，只核验并复用已存在的 chr22 pilot 来确定起始 D；若没有有效 pilot 则停止提示，不自动计算被排除的 chr22。子集运行仍输出 `.SUBSET.bed`，不会把未包含的染色体包装成全基因组结果。

发现不完整 LD、异常基因型、无效区间、D 尚未稳定或明显的计数偏离时，程序停止并打印原因，不继续输出本次成功标记。

<a id="overview--2-输入与依赖"></a>

## 2. 输入与依赖

适用环境为 Linux 或 WSL，使用 Bash、Python 3.11 或更新版本、支持 C++17 的 `g++`、Zstandard 开发库（`zstd.h` / `libzstd`，编译链接 `-lzstd`），以及支持以下选项的 PLINK2：`--r2-phased`、`--indep-pairphase`、`--missing variant-only`。不需要 R 或额外 Python 第三方库。

默认输入：

```text
VCF_DIR=/mnt/f/gen/1kg/37/vcf
PANEL=/mnt/f/gen/1kg/37/samples.txt
```

VCF 文件应为 `chr1.vcf.gz` 至 `chr22.vcf.gz`，并有相应 `.vcf.gz.tbi`。本版只处理常染色体；chr22 始终用于 pilot（范围排除 chr22 时要求已有有效 pilot）。panel 应含 `sample` 和 `super_pop` 列，且样本 ID 与 VCF 一致。

| 群体 | 人数 | 常染色体单倍型数 N |
|---|---:|---:|
| AFR | 661 | 1,322 |
| EAS | 504 | 1,008 |
| EUR | 503 | 1,006 |
| SAS | 489 | 978 |

过滤保留群体内 MAF ≥0.05 的双等位记录，不额外加 `--snps-only`，也不因为记录处于 LD block 间隙就删除。PGEN 保留相位。使用固定 N 的目标函数要求完整基因型，因此发现缺失基因型或相位检查失败时停止。

相位检查会调用 `--indep-pairphase`，但这里只把它用作检查；产生的 prune 列表会删除，**不会用该列表筛除变异**。

<a id="overview--3-怎样自动选择-d"></a>

## 3. 怎样自动选择 D

通用默认 `PILOT_MAX_D_KB=20000`，会把基础网格扩展到 20 Mb。未设置分析专用默认值时，待计算染色体使用的网格如下，单位为 kb：

```text
250,500,1000,2000,5000,10000,20000
```

当前 `/mnt/f/analysis/ld/ld.runtime.env` 已将本分析的上限保存为 **40,000 kb**。直接运行 `./ld.sh` 即可：核验并复用已通过的 chr22、chr1，chr2 及其他尚未通过的染色体使用扩展后的网格；既有有效分块继续复用。调用者显式设置环境变量仍可覆盖这个默认值。

每个 D 都有完整的 AFR/EAS/EUR/SAS 祖源区间、universal BED 和 consensus cuts。程序比较这些坐标的完整列表，不只比较数量。

默认选择条件为：候选 D 与网格中所有更大 D 的完整边界一致，而且至少有 **两个更大 D** 的确认。例如 D=5,000、10,000、20,000 kb 的全部结果一致，且网格后面没有其他不一致档位，才可选择 5,000 kb。只有 5,000 与 10,000 kb 相同，在默认规则下还不足以选择 5,000 kb，还需检查 20,000 kb。

有一种可明确解除距离限制的例外：若比较所覆盖的某个 D 已不小于该染色体四个群体各自的 `最后变异位置 − 第一变异位置`，则该档计算允许整个保留变异范围处于同一个候选块中。与它相同的较小 D 结果可以通过全跨度对照确认，未必需要两个更大档位。

除上述全跨度检查外，“已稳定”指本实现采用的有限网格经验标准。不要把它解释为对所有更大 D 均不改变的定理。

<a id="overview--如果-20-mb-仍不足"></a>

### 如果 20 Mb 仍不足

程序会停止。可以扩大计算预算后重新运行同一个完整入口：

```bash
PILOT_MAX_D_KB=40000 /mnt/d/scripts/ld/ld.sh
```

在默认网格基础上，这会增加 40,000 kb；更大的上限按倍增扩展，最后一档精确取上限。新增档位只用于尚未通过或缓存失效的染色体，已经通过检查的染色体保留原先的验证范围。已经通过新版 receipt 检查的分块会复用，只补算缺少的 D。**不会因为希望得到论文中的某个块数而自动调节 D。**

例如 chr2 在 5,000 → 10,000 kb 时边界改变，而 10,000 → 20,000 kb 时不变，意味着 10,000 kb 只有一次更大 D 的确认，尚未满足默认的两次确认。`same_boundaries_as_previous=1` 只说明与上一档一致，不表示整个稳定性检查已经通过。若 40,000 kb 的边界也一致，10,000 kb 才能通过这一检查；chr22、chr1 在原网格上已通过且复核有效时，不生成新的 40,000 kb LD 表。

复用不是只检查 `selected/chrN.json` 是否存在。程序核验当前输入、PGEN 和原网格中全部分块的 receipt／输出哈希，重新计算小型 consensus 并核对保存的 BED、cuts 和诊断，再按当前规则复核完整边界与参考计数。仅允许沿用当前网格的完整前缀；修改基础网格、收紧或放宽验证设置、输入变化或结果损坏导致复核失败时，所选染色体回到当前网格检查；被排除的 chr22 则停止提示。复用不改写原选参记录或报告，也不宣称该染色体已在新上限通过验证。需要主动扩大某个已通过染色体的验证范围时，可先移走对应的 `selected/chrN.json`，再运行包含它的同一个入口；原分块缓存仍会核验复用。

停止提示会报告相同边界的末尾 D 序列、已有／所需确认次数，并提前提示最新一档是否还超出参考计数阈值。例如 universal=143、本地参考计数=161 时，偏差为 11.18%，超过默认 10%；若扩大 D 后结果不变，仍会因参考计数检查而停止。扩大 D 只增加稳定性证据，不保证整个流程通过。

chr22 的选参只确定后续检查的起始 D。其他染色体使用不小于该 D 的网格重复稳定性检查，各染色体可以选择不同的 D；遇到尚未稳定的染色体仍会停止。不能由 chr22 的收敛推断 chr6 等染色体也收敛。

<a id="overview--论文块数的角色"></a>

### 论文块数的角色

`reference/published_counts.tsv` 保存论文参考计数，包括 chr22 的 AFR/EAS/EUR/SAS/universal = **172/182/130/166/53**。

`counts_match` 仅表示计数完全相同，不参与 D 的排序。边界稳定后，另有默认 **10% 最大相对计数差**的工程保护：四个群体或 universal 中任一计数相对论文偏离超过 10%，程序停止，要求检查数据版本、过滤、相位和边界解释。

10% 是本实现的异常检查阈值，不是论文中的统计检验或理论保证。它既不证明坐标相同，也不能让不稳定的 D 通过。`REFERENCE_MAX_REL_DEVIATION` 可显式更改，但不应为让当前结果“过关”而盲目放宽。

<a id="overview--4-祖源分块实际优化什么"></a>

## 4. 祖源分块实际优化什么

对同一块中的不同变异对，累加：

```text
score(i,j) = phased_r²(i,j) − [1/(N−1) + 0.0025]
```

其中 N 为单倍型数，`0.0025 = 0.05²` 为论文的分辨率项。自配对和对称重复项不改变最优划分，因而使用 `i < j` 的唯一配对。

动态规划在以下约束下求全局最优：变异按坐标连续成块、每个保留记录恰好属于一个块，以及块首尾距离不超过 D。D 同时决定需要计算的 LD 配对范围和允许搜索的最大块跨度。某个选中块短于 D，并不能单独证明扩大 D 无影响。

新版要求完整 `strict` LD，保留包括 r²=0 在内的配对。PLINK2 命令使用：

```text
--r2-phased yes-really cols=id
--ld-window 1000000000
--ld-window-kb <最大所需D>
--ld-window-r2 -1
```

PLINK2 的 `--ld-window-r2 0` 已经包含精确零值；这里使用 `-1` 还会让未定义的 NaN 配对进入输出，供 C++ 显式报错，避免先被阈值过滤。C++ 会按 PVAR 顺序逐行核对 within-D 配对：缺行、重复配对、未知 ID、排序错误、非有限或越界 r² 都会报错，不能把未计算或丢失的 LD 静默当成 0。

每个群体／染色体仅生成一份最大所需 D 的 LD 表；C++ 反向读表一次，同时计算本次缺少的所有 D。表中临时使用较短的编号 ID 来降低文本体积，不改变 PGEN 顺序、坐标、REF/ALT 或基因型。计算保留低内存动态规划形式，不需要把整个 LD 矩阵放入 RAM。

<a id="overview--相同-pos-的多条双等位记录"></a>

### 相同 POS 的多条双等位记录

论文的形式化算法假定坐标函数是单射，即不同顶点坐标不同。真实 VCF 在排除单条 multiallelic 记录之后，仍可能有不同双等位记录共享 POS。

本版默认 `COINCIDENT_POLICY=group`：保留所有这些记录及其配对权重，但不允许在相同坐标内部切开。它是对真实输入的明确扩展，不能称为论文已规定的处理；不会随机保留其中一条，也不会给重复坐标加假位置。

如果需要严格遵循论文的唯一坐标前提，可设置 `COINCIDENT_POLICY=error`，遇到同 POS 即停止。两种模式都会把同位点记录数写进 QC。

<a id="overview--5-universal-cuts-的修订和公开方法的解释边界"></a>

## 5. universal cuts 的修订和公开方法的解释边界

Methods S1 e1 明确指出，MAF 等过滤会使部分变异落在祖源 block 之间。因此，祖源 BED 是保留变异支持的区间，本版**不先填平这些间隙，也不把各块边界改成 midpoint**。

公开补充方法 e6–e7 将 block 的左端称为 `start point s_b`，右端称为 `endpoint e_b`。本版把候选 endpoint 域明确解释为右端集合 `{e_b}`。对于候选 p：

```text
C_p = {b: s_b < p ≤ e_b}
cut = [p, max{e_b: b ∈ C_p}]
```

仅当 `C_p` 非空且 cut 宽度 ≤2,000 bp 时生成候选。随后优先最大化互不接触的 cut 数量，次优最小化总 cut 宽度。每个选中 cut 都再次检查不会完整穿越一个输入 block。

需要明确区分三件事：

1. **2 kb 是 cut 宽度上限，不是 LD block 最小长度。** 不删除或合并合法短块。
2. **零宽 cut 本身合法。** 问题在于旧代码在 `C_p` 为空时自行令 `e=p`，给原文未定义的情况补造候选。
3. 右端集合的术语解释，以及 `C_p` 为空时跳过的退化约定，尚未通过作者受限源码核实。新版诊断同时计算“起点与右端都作为候选，但仍要求非空 C_p”的另一解释，记录其数量，避免掩盖这个复现边界；不根据谁更接近 53 来选择解释。

左端 `s_min` 仅作为 terminal metadata，不计入候选 cut 优化。输出采用标准 0-based、half-open BED：正宽 cut `[s,e]` 左块止于 s、右块起于 e，中间位置保留为 cut gap；零宽 cut 的坐标归左块。由此得到无重叠的 core intervals，**不是从染色体坐标 0 到末端的无缝覆盖**。下游如需填满所有位置，应把那一步明确视为另一个坐标映射规则。

<a id="overview--6-输出重跑与旧文件复用"></a>

## 6. 输出、重跑与旧文件复用

新版结果写入 `OUT/rebuild_v2/`。运行和停止状态只打印到终端，不生成迁移清单、`RUN_STATUS.json` 或重复的 `ALL.37.bed.json`。保留必要科学 QC、复用 receipt 和一份包含结果哈希的 `COMPLETE.json`。完成记录通过相对路径及 SHA256 引用各染色体选参记录，选参记录同样引用 consensus 诊断，不重复复制整份 QC。主要文件：

| 路径（相对 `OUT/rebuild_v2/`） | 含义 |
|---|---|
| `pilot/chr22.strict.summary.tsv` | pilot 各 D 计数和完整边界变化 |
| `pilot/chrN.strict.summary.tsv` | 其他染色体的同类检查 |
| `selected/chrN.json` | 各染色体自动选定的 D、检查依据及诊断 |
| `pop_blocks/POP/strict/D*kb/` | 新版祖源 BED、QC、receipt |
| `consensus/strict/D*kb/` | universal BED、cuts、诊断 JSON |
| `AFR.37.bed` 等 | 全部要求染色体通过后汇总的祖源文件 |
| `ALL.37.bed` | 全 22 条常染色体 universal 文件 |
| `COMPLETE.json` | 方法记录、各染色体选参依据及最终 BED 哈希；仅全部检查通过后生成 |
| `logs/` | 保留的程序日志 |

显式设置 `--chr` 或 `CHRS` 只处理子集时，仍先核验 chr22 pilot；排除 chr22 时不会新建 pilot。汇总输出使用 `.SUBSET.bed`，避免与完整基因组混淆。

**不需要删除旧 `analysis/ld`。** `OUT/pgen/` 下的旧 PGEN 在已知旧 receipt、输入路径、文件大小与时间戳等均通过核对后，可以复用，并补做新版相位及缺失检查。不满足条件的 PGEN 会按当前输入重建。新版 receipt 匹配时可继续复用；不把任意同名文件当作有效缓存。

旧祖源 partitions 没有新版的完整配对验证，不能直接作为通过新版检查的结果；它们保留供对照，新版分块写入独立目录。新版有效 partition receipt 包含算法版本、PGEN 来源、D、同位点策略和输出哈希，LD 临时表删除后仍可复用这些已验证的小文件。

2026-10-21 的读取优化扩大了倒序读取缓冲，并为流水线生成的数值 ID 三列表增加专用解析路径；目标函数、`long double` 精度、累加顺序及平局规则保持原样。缓存兼容表只允许已验证的旧源码哈希用于这一个具体优化版本；其他参数、PGEN 来源和 BED/QC 哈希仍须全部匹配。旧 receipt 保留真实生成版本，不会被改写成新版来源。后续未知源码修改不会自动继承这一兼容性。

重跑时只有取得全部输出锁后，才会使旧 `COMPLETE.json` 失效；原有汇总 BED 可保留供查阅，但只有本次重新生成的 `COMPLETE.json` 与对应哈希可证明当前运行成功。不要只凭某个 `ALL.37.bed` 仍在目录中就判断重跑完成。

<a id="overview--7-超大临时文件的处理"></a>

## 7. 超大临时文件的处理

默认 `LD_STORAGE=blocked-zstd`：PLINK 的原始文本通过 Linux 本地 FIFO 直接送入压缩器，在 `LD_TMP_DIR` 生成一份带索引的 `ld.vcor.ldz`。每个 4 MiB 原始字节块独立采用 Zstandard level 1 无损压缩并带帧校验，索引及完成尾标另有完整性检查。C++ 使用上限 32 MiB 的压缩字节缓存合并读取，再按索引倒序解压小块，不创建整份解压文本，不改变 r² 字符、浮点解析、累加顺序、D 或 DP。PLINK 与压缩器均成功退出后才把 `.partial` 原子改名为完成文件；任一失败即停止两端。

每个群体／染色体的最大 D 只生成一份临时表，本次所需各 D 全部计算并通过 QC、保存输出及 receipt 后，立即删除这份 LD 表，再进入下一个群体。**超过 100 GB 的文件同样立即删除；不会等全基因组结束才清理。**

普通报错、Ctrl+C、可捕获的终止信号都会退出子进程并清理本次私有临时目录，留下小型日志。断电或 `kill -9` 无法即时执行清理；下次使用同一 `OUT`／`LD_TMP_DIR` 启动时，在取得全部输出锁之后清理带本程序 owner 标记的残留目录，不扫描删除无关数据。

维护时如已在私有临时目录之外保全完整的 PLINK 表及 `LD_READY.json`，可显式设置 `LD_RESUME_DIR=保全目录` 恢复分块。此入口核对输出根目录、群体、染色体、D、PLINK 二进制、PGEN receipt、数值 PVAR、LD 选项、预期配对数，以及表的大小、修改时间和首尾摘要；不会再次生成 LD 表。首尾摘要不是全表哈希，分块程序仍须逐行完成严格配对检查。恢复期间失败或中断会保留外部表；只有全部缺少的 D 分块通过 QC 并保存 receipt 后才标记已消费；默认同时删除表。若外部 `LD_READY.json` 明确带有 `preserve_table: true`，原始表始终保留。维护交接可通过 `PARTITIONS_READY.json` 接收成功退出的旧分块子进程：核验输入 receipt、精确允许的生产者源代码哈希、各档完整参数和 BED/QC 哈希，重新检查完整位点覆盖后复用，保留原始生产者哈希。没有成功分块凭据时，尚未完成的 DP 从头读取保全表。

`LD_TMP_DIR` 通用默认是 `OUT/tmp`；入口会先读取可选的 `OUT/ld.runtime.env`，以保留该分析的启动设置。文件应使用环境变量默认值写法，优先保留调用者显式设置。当前 `/mnt/f/analysis/ld/ld.runtime.env` 已保存 F 盘临时目录、压缩模式和 40 Mb 上限；EAS chr1 保全检查点已消费，默认 `LD_RESUME_DIR` 为空，归档原表仍保留，因此本分析以后直接运行 `./ld.sh` 即沿用这些设置。

程序固定先获取旧位置 `OUT/.ld.lock` 的兼容锁，再获取新位置 `OUT/work/.ld.lock` 的锁，并持有至整个流程退出。任一锁被占用即报告冲突路径并退出，不等待；第二把锁获取失败时自动释放第一把，分析状态、缓存和临时目录保持不变。只有两把锁全部取得后，才会撤销旧完成标记、清理残留和准备分析。两个路径若通过符号链接或硬链接指向同一 inode，只加锁一次。正常结束、异常和中断均关闭锁句柄，但不删除或替换锁文件；保留旧位置是为了与旧版入口互斥。子进程保持在同一终端会话内，主进程负责终止和回收。

设置 `LD_STORAGE=plain` 可回退到原有纯文本存储路径，数值结果与压缩路径相同。纯文本模式生成 LD 表前，程序根据实际位点和窗口统计全部配对，计算纯文本 `.vcor` 的严格体积下限：两个数值 ID、分隔符、至少一个字符的 r² 和换行。若空闲空间不足以容纳这个下限再加 `MIN_FREE_GB` 预留，直接停止，不启动 PLINK2 LD 计算。实际 r² 通常不止一个字符，所以通过下限检查仍不能保证空间足够。单个表也可能需要相当长的计算时间。

压缩模式不把未知压缩比当作容量保证，运行期间同样监控空间。默认在命令运行期间每约 3 秒检查一次空间，低于 5 GB 时停止子进程并清理临时输出。报错会显示检测目录、**清理前**的空闲空间及当时 `.vcor` 的体积。`MIN_FREE_GB` 是空闲空间预留，不是任务只需要的空间；这里的 GB 均为十进制 10⁹ 字节。

**退出后空间很多，不代表运行期间空间足够。** `Temporary files removed` 出现在 `STOP` 之前，是因为异常退出时先执行清理，再打印停止原因，数百 GB 的临时表可能已经被删除。应查看 `LD_TMP_DIR` 所在盘，而不只是输入或最终输出所在盘。例如，本地 AFR chr1 的 738,034 个位点在 20 Mb 窗口内有 43,714,406,386 对，纯文本表至少约 775 GB，实际还会更大。

可将临时目录放到有足够空间的盘后继续运行，例如：

```bash
LD_TMP_DIR=/mnt/f/analysis/ld/tmp /mnt/d/scripts/ld/ld.sh
```

此设置只改变临时文件位置，`OUT` 及已验证的 PGEN、分块缓存继续复用。不要通过降低 `MIN_FREE_GB` 来绕过表本身的容量需求。

本版不接受 `KEEP_VCOR=1`，避免旧配置意外保留超大表。
