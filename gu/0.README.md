## Unified local / HPC entry (2026-11-01)

The maintained source is the same in `D:/scripts` and `/work/sph-huangj/scripts`.
Shared platform settings: `../0f/0os.sh`; shared command runner: `../0f/submit_jobs.py`.
Use `submit=local jobs_N=4 ./ENTRY` or `submit=hpc jobs_N=8 ./ENTRY`.
`--submit local|hpc`, `--jobs-N 1..8`, and `--wait TRUE|FALSE` are also accepted.
For metag, bare `--submit` still means submit the generated plan.
Local .cmd files run in a bounded process pool and wait; failed commands stop new local work.
HPC records real JOBIDs and uses explicit dependencies. Missing bjobs entries never imply success.
GU/LD support `--wait TRUE`; metag retains its stage dependency graph (local stages wait automatically).
`jobs_N` controls local .cmd concurrency and GU/LD HPC concurrency; metag HPC array resources remain in hpc.yml.

## UKB CPU IBDmix：013–049

先检查已有软件，不需要每次重装：

```bash
cd /work/sph-huangj/scripts.HPC/gu
./install.sh --check-ibdmix
source ./f/runtime.env
./gu.sh ibdmix --GPU FALSE --grch 37 --target ukb --chr 1-22,X \
  --dir-target "$GU_REF_ROOT/ukb/37/imp/chr" \
  --dir-out "$GU_ANALYSIS_BASE/ukb" --postfix '[013-049]' \
  --keep-psam "$GU_REF_ROOT/ukb/37/imp/chr1.psam,10000,[013-049]" --keep-males
```

登录节点执行以上命令会生成 37 个 `.cmd`，逐个独立 `bsub` 提交，不是 job array。
每个作业运行该批次的全部指定染色体，默认 `--jobs 1` 顺序运行染色体。
默认 CPU（可省略 `--GPU FALSE`），队列 short、40 slots、32G 内存、144 小时；
可通过 `--queue`、`--slots`、`--memory-cap`、`--walltime` 调整。
内存 reservation 沿用现有 HPC 配置的每作业方式；若集群按 slot 累加，应调整提交设置。

添加 `--run-cmd FALSE` 只生成文件，不调用 bsub，不做基因型转换或推断。
命令与日志放在 `ukb.jobs/ibdmix-*/`，每次调用创建独立目录。
实际输出分别为 `ukb013` … `ukb049`，不会覆盖本机输出。
提交记录为 `submissions.jsonl`；若提交中断，先查该记录和 `bjobs`，不要直接重提整个范围。
不要重复提交仍在运行的相同批次。已完成兼容结果沿用原有缓存逻辑。

PSAM 先按原始行顺序分成 10000 人的块，再应用 `--keep-males`，与本机算法一致。
本次 HPC `chr1.psam` 有 487409 个样本：049 的原始块为 7409 人，再筛男性。
`'[013-051]'` 语法也支持，但当前 PSAM 没有 050、051，提交前会报错。

范围与列表：`--postfix '[013-015]'` 或 `--postfix '013,015'`；
`--keep-psam` 使用 `FILE,10000,[013-015]` 或 `FILE,10000,[013,015]`。
范围/列表必须一一对应；方括号请加引号，防止 shell 文件名展开。
对比 CPU/GPU 时还应确认两端 PSAM 样本顺序、输入与过滤参数相同；重新运行 013 本身不能保证这些相同。

## 安装与高级调度入口

`install.sh` 负责软件安装及检查。只有 `--check-ibdmix` 报缺失时才需要修复/安装相关依赖。
完整检查：`./install.sh --check`；参考输入检查：`./install.sh --check-references`。
完整安装 `./install.sh --GPU FALSE`；计算节点离线构建使用已有 `f/install-hpc.sh` 流程。
ARG/Threads 的安装与 IBDmix 独立，本次无需运行 `--arg`。
HPC 不要求 R/Shiny；保留源码供本机使用。

`gu-hpc.sh` 原本只是 `f/hpc.py` 的薄入口。现统一使用：

```bash
./gu.sh hpc --help
./gu.sh hpc plan ibdmix --help
./gu.sh hpc submit RUN_DIR
./gu.sh hpc status RUN_DIR
```

高级 plan/submit 流程保留原有输入快照、校验、重试和汇总功能；
旧 `gu-hpc.sh` 仅为兼容转发，不再作为推荐入口。
普通 UKB 批次使用上面的 `gu.sh ibdmix` 即可，无须手工 plan。
安装与调度职责分别保留在 install.sh 和 gu.sh。

`--date-scratch YYYY-MM-DD` 可更换 scratch 日期；续跑需使用相同日期。
默认日期固定为 2026-10-31，显式 `--dir-out` 优先。无需从 /data 创建软链接。
