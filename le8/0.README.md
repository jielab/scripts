# LE8 FINAL

统一入口为 `./le8.sh`，`--Y` 接受逗号分隔的多个疾病。省略模块时依次执行 C1–C5；只运行 C1 时显式写 `c1_correlate`。各疾病、各组学依次完成并保存，某个疾病失败不会丢弃其他疾病已经发布的结果。

## 结果目录

分析根目录下各疾病文件夹保存原始结果，共享文件集中放在：

| 目录 | 内容 | 是否可删除 |
|---|---|---|
| `reports/c1/` | 跨疾病 PGS 汇总、可用性、关联明细和可靠性汇总 | 可删除；C1 批次结束会从各疾病结果重新生成，不重新拟合 |
| `logs/locks/` | 并发汇总和冻结划分校验的锁文件 | 没有相关任务运行时可删除，下次会自动创建；运行时保留 |
| `logs/freeze/` | 固定训练/测试名单、亲缘分组及校验记录 | 保留；它们是保证样本划分一致和旧结果可复用的研究输入，不是可清理日志 |
| `logs/exclusions/` | 因样本支持不足而整项跳过的疾病/组学层、原因和输入校验 | 建议保留；清理 C1 结果后仍可直接跳过，相同数据不会重新准备队列 |

原根目录 `_protocol` 迁移到 `logs/freeze` 后，程序兼容旧结果中的路径引用，不修改冻结文件和旧模型合同。尚未迁移的旧分析目录仍可读取原 `_protocol`。这里只整理根目录的共享文件；各疾病内部的 `_LOCAL_ONLY` 仍保存模型、个体预测或准备队列，不能当作锁文件目录删除。

## C1 架构

C1 依次执行 R 关联分析、共享队列准备、风险模型和评估。默认主模型为 glmnet、LightGBM、保留病例的 ABM、全分子谱 ABM、既往患病支持模型；见 `config/c1_methods.json`。`abm_legacy`、`molecular_deviation`、`abm_deep` 是显式选择的敏感性方法，见 `config/c1_methods_sensitivity.json`。

`--device auto|cpu|cuda` 只选择支持加速的方法如何执行；它不改变科学方法。此修订不改变风险模型的 K、PCA、半径、特征构造、调参网格或深度网络结构。

## 旧模型复用

`--replace FALSE` 为默认值。准备好的队列按数据和分组合同复用，忽略旧版源代码指纹字段。风险模型按明确的模型合同版本、科学参数和输入识别；文档、绘图、报告或评估代码的修改不会使风险模型失效。

原生 C1 关联结果还必须匹配当前关联方法版本，并包含 prevalent 拟合方法审计；旧版关联结果即使文件完整，也会重新计算。此检查不使已核验的风险模型失效。

`_LOCAL_ONLY/model_reuse.json` 是可自动生成的加速记录。没有记录时，程序扫描旧模型目录，核验完成文件校验值、模型参数、各角色人数和 ID 顺序、测试/校准集家庭分组及特征顺序。既往患病和深度模型还需核对其冻结配置。旧模型目录、签名和完成标记保持原样；兼容性不足则不能当作已完成的相同模型。

`f/c1_unified_models.py` 等五个极小的文件是历史 pickle 的导入别名，不包含重复算法，需保留。新模型另外保存 `censoring_model_LOCAL_ONLY.joblib`；旧模型仍能从原文件读取删失估计器，不为此重新训练。

## 分开控制重跑范围

四个开关分别控制一个 C1 阶段；未指定的开关继承 `--replace`：

| 开关 | 控制内容 |
|---|---|
| `--replace-association` | R 关联分析 |
| `--replace-models` | 风险模型拟合 |
| `--replace-evaluation` | 通用模型评估 |
| `--replace-reliability` | P0/P1/P2 可靠性评估 |

推荐最终重跑方式，重算关联与评估并复用已完成风险模型：

```bash
cd /mnt/d/scripts/le8
./le8.sh c1_correlate \
  --Y cvd_cad,cvd_htn,ra,sle2,copd,epilepsy,ad,cvd_abaneu,mi \
  --biom prot --device auto --cores 8 --memory-limit-gb 16 \
  --replace-association TRUE --replace-models FALSE \
  --replace-evaluation TRUE --replace-reliability TRUE
```

经典命令仍可直接运行；它会复用符合条件的结果，缺少的阶段才执行：

```bash
./le8.sh c1_correlate --Y ra,sle2,ad,epilepsy,mi,cvd_afib \
  --biom prot --cores 8 --memory-limit-gb 16
```

C1 默认 `--pgs FALSE`，跳过全队列 PGS 关联扫描及配对 PGS 模型。需要开启时显式加 `--pgs TRUE`；未运行的结果标记 `skipped_by_request`，估计为 NA，已有完成结果和 PGS 断点继续保留。当前三个 ABM 主模型不依赖这段扫描；可选的 `molecular_deviation` 需要原始 PGS 输入，但不依赖扫描结果。

之前以 `--pgs FALSE` 完成的批次，保持 `--replace FALSE` 并显式加 `--pgs TRUE` 即可补做 PGS，复用符合合同的实测组学扫描和风险模型。环境变量 `C1_PGS_MODE` 可覆盖默认值，显式 `--pgs TRUE` 优先于环境变量。该开关不影响独立的 `pgs_focus`。当前 PGS 的 R Cox/Logistic 拟合没有 GPU 后端，`--device cuda` 不会加速这段扫描。

PGS 输入唯一固定为 `/mnt/f/gwas/<prot|met>/pgs/<prot|met>.pgs.gz`。C1、C2、C4、final 和 molecular_deviation 统一读取该文件，缺失或为空直接报错；不使用 RDS、环境变量指定文件或旧缓存作为替代。原生 `.SCORE_SUM` 列名和完整数值精度均保留。

2026-10-29 评分修复：PLINK 只读取 `BETA_SUM` / `SCORE1_SUM` 加权列；缺失基因型采用目标样本频率均值插补，保存实际使用变异及缺失审计。只提取权重中的 SNP 后计算频率，避免扫描无关变异；单个 PLINK 工作区默认 8192 MiB，可由 `PGS_PLINK_MEMORY_MB` 指定。该值不是进程树总内存上限，真实 UKB 重评分建议先用 `--jobs 1`。不因 IV 数量少而删除蛋白，不自动重做 COJO。

Reliability 的 P0/P1/P2 现使用 calibration 冻结的分数及 EID hash 并列边界，test 只应用冻结规则。仍须报告 test 实际 coverage；本修复不保证预测增益，不改变预定 risk bins、AURC 范围或风险模型调参。

现在 C1 在任何关联/PGS 拟合前检查样本支持。`--min-cases-with-biom 50`（也接受 `--min_cases_with_biom`；环境变量 `C1_MIN_CASES_WITH_BIOM`）要求有该组学数据的开发集中，预测窗口内已知发病病例至少 50；不读取冻结测试集结局。调参、校准等所需分区仍各自至少需要 20 个病例和 20 个对照，可靠性审核分区还需至少 100 个已知结局。先检查不含 QC 的人数上界，已不足则连宽组学矩阵都不加载；上界通过后再检查技术 QC。

按当前项目的整项排除规则，只要任一所需分区或总病例门槛不足，该疾病/组学层的关联、PGS、预测和评估全部跳过，记录 `skipped_insufficient_scope_support` 后继续下一项，正常跳过不导致批次失败。原因和输入校验保存在 `logs/exclusions/<Y>.<biom>.json`。清理该层 C1 结果后，输入和门槛不变时仍直接跳过；输入、样本划分或门槛改变会重新检查。旧结果中的 `skipped_insufficient_development_support`、`insufficient_primary_reliability_support` 也表示样本支持不足，不能靠 `--replace TRUE` 增加样本。这是整项排除的分析策略，不等于其他队列得到的所有关联估计均无效。

启用 PGS 全扫描时，程序先把评分表无损暂存为逐列 RDS，拟合时按需读取，避免评分全表与模型工作内存同时常驻；临时列在该阶段结束或普通错误退出时清理。临时磁盘需容纳解压后的评分表。

PGS 默认缓存六类模型的固定样本筛选及协变量设计矩阵，再调用同样的 Cox/Logistic 拟合核心；保留 Efron ties、标准化、FDR、分离时的 brglm2 回退和原逐特征断点。缺失评分、特殊设计或拟合警告会回退到原流程。`C1_PGS_FAST=FALSE` 可切回原路径作核对。优化路径根据实际样本数和设计矩阵列数估算 worker 内存（至少 2 GiB，另保留父进程、fork 副本和安全余量），在 16 GiB 内允许更多并发；原路径仍默认预留 8 GiB。显式 `--cpu-task-memory-gib` 优先，进程树硬内存限制保持有效。

PGS 阶段还会将前一步 PWAS/MWAS 的实测组学矩阵无损暂存并释放，只保留同组学样本 ID，结束后恢复供后续分析和绘图使用；临时磁盘还需容纳该矩阵。这样可降低父进程占用，避免在 16 GiB 下因实测矩阵仍常驻而无法容纳一个 PGS worker。模型、样本和断点签名不变；若释放后仍不足，内存预检仍会报错。

若日志出现退出码 247/SIGKILL，先检查内核 OOM 记录。默认 `--replace FALSE` 会复用 `/tmp/le8-cache` 中匹配的 PWAS 和逐特征 PGS 断点，直接重跑原命令即可续算；不要清理这些缓存或加 `--replace TRUE`。PGS 串行扫描会定期报告已验证的特征数。

只评估可靠性，绝不调用风险模型拟合：

```bash
./le8.sh c1_reliability --Y cvd_htn,copd --biom prot \
  --bootstrap 1000 --risk-bins 50 --replace TRUE --cores 8
```

新疾病与显式敏感性分析：

```bash
./le8.sh c1_correlate --Y NEW_TRAIT --biom prot \
  --config config/c1_methods.json --device auto --cores 8 --replace-models FALSE
./le8.sh c1_correlate --Y NEW_TRAIT --biom prot \
  --config config/c1_methods_sensitivity.json --device auto --cores 8
```

增加 `--dry-run` 可查看计划，`--preflight` 检查依赖与配置；真实队列字段和分组在准备阶段验证。疾病病例或对照数不足会明确记录 unavailable/insufficient support，不把未估计结果当作阴性，也不伪造预测结果。错误与部分完成状态会保留在日志和各疾病的 `C1_FINAL_INDEX.json`。

Twin ABM 额外要求 `tune_gate` 每类至少达到配置中的 `min_events`。仅这一角色不足时，受影响的 ABM 方法保存 `UNAVAILABLE.json` 和 `development_support.tsv`，其他可用模型继续拟合和评估，最终标为部分完成。常规模型的支持度回退不用于放宽 ABM 门槛。意外错误仍会在批次结束时返回非零状态，但不会跳过同一疾病的后续组学。

## P0/P1/P2 与冻结协议

三个可靠性头始终使用同一个冻结 glmnet 风险值：P0 仅使用风险；P1 增加真实的 incident 分子支持诊断；P2 再加入 prevalent 支持、参考人数及其分母。可靠性头只在 `calibration_audit` 上学习；阈值、风险分层边界和测试集选择掩码先冻结，再读取测试结局。

缺少诊断值不会补零。P0 和 P1 都可用才标记 `completed_primary_P1_vs_P0`；P2 可以单独不可用。NaN 按缺失处理，形状错误、负数或无穷诊断不能静默进入特征。

主要结果位于 `<trait>/<layer>/c1_correlate/reliability/FINAL/`：

- `reliability_increment_50.tsv`：直接的 P1−P0 与 P2−P1 标准化选择集损失差，负数表示改善。两组使用共同有数据的风险层及共同参考权重，报告所覆盖的参考权重比例。
- `aurc_contrasts.tsv`：按预先声明的目标覆盖率网格 0.10–1.00 积分，避免不同实际覆盖率区间相减。
- `risk_coverage.tsv`：保留实际覆盖率及偏差；50% 目标偏差超过 0.03 会提示校准问题。
- `support_trend.tsv`：连续 `log1p(eligible_match_count)` 和 `log1p(family_ess)`，控制冻结风险层的固定效应。主要分析不用秩四分位，不按行顺序拆分相同支持值。
- `risk_standardized_selection.tsv`：选择与未选择的补充对比。
- `reliability_status.tsv`、`reliability_prevalent_support_audit.tsv`：可用性和历史来源审计。

配对比较使用同一家庭重抽样。区间以固定风险模型和可靠性头为条件，不包括完整重训的不确定性；有效重抽样至少达到请求次数的 80% 且不少于 20 次。公开表格不包含个体 ID。

`config/c1_reliability_protocol.json` 固定主要层、疾病、比较、覆盖率和风险分层；其校验值记入可靠性合同，只影响可靠性复用。HTN 为 discovery；COPD 只有在有明确的既往未查看测试结果记录时才能标为 locked replication，否则为 inspection unverified。不能因为文件存在或不存在就宣称从未查看过结果。

跨疾病表为分析根目录下的 `reports/c1/c1_reliability_cross_trait_summary.prot.tsv`。C1 和 Final 报告优先使用新可靠性表，呈现总体 glmnet、P0、P1、主对比、P2、次对比、连续趋势及发现/复现状态。历史 ABM 结果仅作为补充保留。

## Final 的可选 PGS 汇总

`c1_correlate` 批次结束时也会汇总分析根目录下所有已有疾病的 PGS，在 `reports/c1/` 输出 `c1_pgs_cross_trait_summary.<layer>.tsv/.html`、`c1_pgs_cross_trait_status.<layer>.tsv` 和 `c1_pgs_cross_trait_associations.<layer>.tsv`。`--pgs FALSE` 禁止新拟合，但重建关联输出时仍保留已保存的 PGS 扫描及配对结果；汇总缺失的 PGS 只记录可用性。

`./le8.sh final` 按实际保存的结果汇总 PGS，不受 C1 的 `--pgs` 设置影响，也不重新拟合 PGS。已完成的 incident、prevalent、attained-age 扫描分别保留全遗传队列和同组学子集的统计数、原始 FDR 和关联估计；已有配对 PGS/分解结果仍按原来源纳入。

输出位于 `<analysis-root>/final/`：`final.pgs_summary.csv`、`final.pgs_associations.csv`、`final.pgs_status.csv`；研究问题报告及浏览索引同时保存 `final.questions.pgs_saved_*.csv`。未运行、文件缺失、空表或全 NA 占位表只记录可用性，不纳入 PGS 统计或遗传–实测比较，不视为阴性结果，也不会因缺少可选 PGS 表而报错。已有结果表不会被 Final 修改。

## 关联分析与停止规则

Prevalent logistic 首先使用 MLE。完全/准完全分离或不收敛时用 `brglm2::brglmFit` 的 AS_mean 回退，保留 `fit_method`。`c1.prevalent_fit_audit.csv` 按分析、拟合方法及状态汇总；未测得的 incident/prevalent 关联与阴性关联分开标记。

禁止查看测试结果后调整 K、PCA、半径、覆盖率或网络结构，也不根据 P2 结果追加 prevalent v2/v3。HTN 成功且真正锁定的 COPD 复现才支持通用方法；只有 HTN 成功则报告探索性结果。两者 P1−P0 均失败时停止 ABM 优化，转为多疾病时间/incident–prevalent 蛋白组研究；两者 P2−P1 均失败时终止 prevalent-support 假设。

## 回归检查

使用 LE8 Python 环境执行：

```bash
python -m pytest -q -p no:cacheprovider tests
Rscript tests/test_logistic_separation.R
Rscript tests/test_directionality_missingness.R
Rscript tests/test_pgs_disk_columns.R
```

测试使用合成数据和临时目录，不启动真实疾病分析。涵盖阳性/零效应、支持度相同值、诊断缺失、主状态、共同 AURC 网格、配对对比、旧模型和 pickle 复用、R 分离回退与仅评估时模型文件不变。

PGS 精度由 `gwas/format.sh pgs` 的合并阶段统一保留。LE8 不再提供 `pgs-merge`、`deviation merge-pgs`、`--remerge-pgs` 或 `--pgs-root`，不读取旧 `_pgs_fullprecision` 缓存。旧缓存不会被自动删除。

`pgs_focus` 仅分析现成的组学 PGS，不再运行 cis/trans、去 MHC 等基因型重评分分支。PGS 评分统一由 GWAS 工具生成。
