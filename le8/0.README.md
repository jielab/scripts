# le8

LE8 疾病与组学分析。`le8.sh` 默认运行 C1–C5；C1 默认比较 glmnet、LightGBM、abm_count 和单独标注的 abm_deep 敏感性模型。支持 local/HPC，先用 `--plan-only` 预览；计划须在实际运行机器生成。计数支持不足时拒绝，完整人群评价保留先验回退。

在本目录查看参数和示例：

```bash
bash install.sh -h
bash le8.sh -h
```

路径优先使用命令行覆盖；共享默认配置位于 `../0f/0os.sh`。
`2test/` 保留回归测试或入口自检依赖，不要作为缓存删除。

## CPU → GPU → CPU 调度

```bash
./le8.sh --Y cvd_cad --biom prot,met --plan-only
./le8.sh --Y cvd_cad --biom prot,met
```

在 HPC 上，含 `abm_deep` 的 C1 为每个 trait × biom 生成三个 job：

| 阶段 | 资源 | 内容 |
| --- | --- | --- |
| `cpu_prepare_models` | `--queue`，无 GPU | 准备冻结输入、关联分析、glmnet/LightGBM/abm_count 等 CPU 方法 |
| `gpu_abm_deep` | `--gpu-queue`，一张 GPU | 只拟合并投影 abm_deep |
| `cpu_evaluation` | `--queue`，无 GPU | 全方法统一评估、可靠性分析；最后完成的 scope 汇总 |

例如 `le8.c1_correlate.ad.prot.cpu_prepare_models` →
`le8.c1_correlate.ad.prot.gpu_abm_deep` → `le8.c1_correlate.ad.prot.cpu_evaluation`。
LSF 使用 `done(job_id)` 依赖，worker 还会检查上游成功状态。阶段失败时停止本阶段，
下游保持阻塞；病例不足等已定义的科学不可用状态继续按原规则记录，不冒充程序失败。
六个 trait/biom scope 生成 18 个 `.cmd`，无需在登录节点等待或启动模型。

`logs/c1_stages/<batch>/<trait>.<biom>/` 保存冻结输入的路径/校验和与分开的
CPU/GPU 模型回执。后续阶段校验并复用同一份输入；CPU 评估只读取本次阶段回执
指向的已冻结预测，保留其实际训练设备，不检查 CUDA、不重新拟合，也不回退到旧结果。
最后完成科学分析的 CPU job 执行跨 scope 汇总，不额外提交汇总 job。

`c1_correlate` 只执行 C1，不会自动运行 C2–C5；不指定模块才使用默认 C1–C5。
其他模块按相邻阶段的 CPU/GPU 资源分组；资源相同的纯 CPU scope 仍可合为一个 job。
已有计划保留原结构，要采用新调度必须生成新计划。

病例不足按具体模型、分层、时间窗或基因记录 skip/unavailable；保留原统计门槛，
不再用预测模型的病例门槛排除关联分析、整个 biom 或 trait。
`--min-cases-with-biom` 仅用于预测方法。旧的整组 exclusion 日志不再阻止运行。
原有的稀少病例拟合保护继续生效；C4 的有效冻结 panel 和 LE8 重构不依赖疾病风险拟合成功。
没有有限疾病 P 值时不生成疾病排序 panel；本次不可用的模型也不会被历史拟合或可靠性汇总替代。

`logs/scopes/<trait>.<biom>.<phase>.json` 记录拆分阶段的退出码；具体跳过原因保存在
各模块的 status、support、fit_diagnostics 等表中。`--resume-plan` 只继续原计划的
提交/等待，不会重试失败任务；修复失败原因后需生成新计划，成功科学结果仍可校验复用。

HPC 默认 GPU 队列为 `2v100-32-e5`（2026-11-06 经 queueinfo/bqueues 核对），可用
`--gpu-queue` 覆盖。abm_count 使用 CPU；abm_deep 在 HPC 默认使用所申请的 GPU。
队列状态会变化，默认值不保证立即 RUN。该队列单节点 24 核、256GB RAM、
两张 32GB V100。以下 CPU 阶段请求 `33` 队列 20 核、96GB 内存，GPU 阶段请求
12 核、96GB 主机内存和一张 GPU；`--gpu-cores` 独立于 CPU 阶段的 `--cores`。
提交前应结合 `queueinfo -l`、`bqueues` 和节点可用内存重新核对资源。

```bash
./le8.sh c1_correlate --Y ad,amr,asthma --biom prot,met \
  --submit hpc --jobs-N 6 --wait FALSE \
  --queue 33 --gpu-queue 2v100-32-e5 --device cuda --cores 20 --gpu-cores 12 \
  --memory-limit-gb 96 --gpu-memory-limit-gb 96 --hours 72 \
  --methods glmnet,lightgbm,abm_count,abm_deep --replace FALSE
```

可先追加 `--plan-only` 检查 18 个 `.cmd`；避免与同一 trait/biom 的旧任务同时执行。

疾病 GWAS 尚未生成时，C2 的 MR/反向 MR/MR-link-2/DANDELION 及 C3 共定位记录
`unavailable_genetic_inputs`；C2 的个体 PGS 分解仍独立尝试，C1/C4/C5 继续。
部分完成状态不会被当作完整遗传分析缓存；补齐 GWAS/QTL 后再次运行会重新检查。
细胞图谱和已发表 CIGMA 默认读取 `${DIR_ANNOT}/le8/cellage/atlas.csv` 和
`${DIR_ANNOT}/le8/cigma/chen2026/cigma.results.csv`。缺少可选 PGS/h2 仅影响对应部分。

依据 `le8_review_AF_MI_20261102_4a4420a.txt`，本轮仅修正
`f/c1.correlate.R::plot_risk_window_scan` 的注释、subtitle、纵轴及 caption：

### 方法版本与结论边界

- 审查所述旧默认（7490bfe）为 glmnet、lightgbm、abm_case_preserving、
  abm_profile、abm_prevalent；2026-11-02 默认（4a4420a；配置版本
  `LE8-C1-primary-2026-11-02-v1`）为 glmnet、lightgbm、abm_count。
  本地 AF / MI、prot / met 的 FINAL 索引仍为旧方法；不能改名或作为新 abm_count 的验证。
- abm_count 是分子 PCA 邻域的 IPCW 局部事件率、family ESS 收缩与固定支持阈值/
  abstention，keep_fraction=1，无 query regression head 或概率校准器。
  旧 donor-pruning / fitted-head 方法作为显式敏感性选项保留。
- P0/P1/P2 固定同一个 glmnet 风险预测，仅改变可靠性排序/筛选。
  P1 使用 glmnet 自身的 incident support diagnostics；默认方法清单不含
  abm_prevalent 时 P2 为 unavailable，不能静默混入历史模型。
  P1 阳性不等于 abm_count 获得验证。
- 保留现有协议：HTN 为 discovery；COPD 只有证明此前未查看结果才可作为
  replication candidate。AF 是跨 trait 检索后的 exploratory 候选，不能回填为
  预设验证终点；同一 UKB 的 prot / met 不构成外部人群验证。
  AF 原始 AURC 改善不等于同风险组成下可靠性改善，须保留风险标准化阴性比较。
- MI / AF 的 incident–prevalent 反向关联可作为描述性动机；当前 cohort 元数据
  未记录治疗协变量，不能解释为已证实机制、个体纵向翻转或保护作用改变。

2/5/10 年 landmark 重新列为缺失分析。
