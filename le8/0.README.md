## le8 — usage notes

> **Unified C1 (2026-10-22):** [C1_FINAL.md](#doc-c1-final) is the authoritative guide for the single public `c1_correlate` entry, scientific method selection, case protection, evaluation, and independent `--device auto|cpu|cuda` option. The `c1_abm` / `c1_abm_GPU` entries and execution/cache descriptions below document compatibility or historical paths; use the new guide for the current C1 protocol. The upstream reference body is retained below.

Current C1 defaults: `glmnet,lightgbm,abm_case_preserving,abm_profile,abm_prevalent,abm_legacy,molecular_deviation,abm_deep`, `config/c1_methods.json`, `config/c1_history.json`, `--device auto`, `--association run`, 8 cores and a 32 GiB process-tree memory cap. Default configuration paths are resolved from the script directory; explicit options override them. For a fresh analysis, run:

```bash
./le8.sh c1_correlate \
  --Y ra,sle2,ad,epilepsy,mi,cvd_afib,cvd_abaneu,cvd_htn,copd,asthma,masld,amr \
  --biom prot,met
```

An absent results directory starts a fresh analysis, including the family roster. Subsequent identical runs can resume verified completed results; `--replace TRUE` explicitly refits selected stages.

Run the public script with `-h` for minimal usage and an example with options. These examples are alternatives; complete workflows, prerequisites and detailed options follow.

<a id="overview--c1-comparison-interpretation"></a>

### C1 comparison interpretation

Pairwise deltas use identical EIDs. Compact comparisons use a common finite-score mask across displayed arms. Harrell C and 10-year IPCW AUC are reported separately from Uno C. Family bootstrap shares multiplicities across arms; IPCW additionally uses frozen training censoring weights. Unavailable probability losses remain missing. Preserve completed fits, frozen predictions, KING grouping and the original outer roster when rebuilding reports.

<a id="overview--project-output-conventions"></a>

### Project output conventions

- LE8 的公共调度、读写和临时续跑核验集中在 `f/0.common.py`，队列输入及运行衔接在 `f/0.host.py`，独立资源调度保留 `f/0.resources.py`。ABM、分子偏离和汇总分别由 `abm.py`、`deviation.py`、`final.py` 实现。`config/abm.json` 与 `config/deviation_{prot,met}.json` 是默认运行参数，整理代码时保持其内容不变。已完成 C1 的核验记录只放 `/tmp/le8-completed/`，文件状态改变或记录不存在时重新执行原有结果检查。
- C4 自定义时钟通过环境变量 `C4_CLOCK_MANIFEST` 指定 TSV，列为 `clock`、`source`、`variable`。同一 `clock` 只能使用一种来源：`all`、`img` 或 `omics`，且至少有三个实际可用变量。例如肾脏时钟可列出 `all` 中的 `creatinine`、`cystatin_c`、`eGFR`，前提是这些列确实存在。不设置该变量时，仍按原流程处理全局组学、可用的表型系统及脑影像时钟。
- LE8 的综合结果直接放在 `final/`，不另建 `overview/`，不生成结果目录的 README。C4 固定预算验证并入 `c4_connect/`，按对应图片分配工作簿；验证对象使用 `c4.validation.rds`，避免覆盖连接分析的 `c4.res.rds`。
- LE8 通过 `le8.sh` 在 `/tmp` 展开交换数据、执行分析和重绘，成功后发布结果。当前结果工作簿同时保存可复用的汇总导出，因此应保留；个体数据仍单独保存为按内容命名的 RDS。
- LE8 工作簿可以正常查看。Excel 等软件重新保存可能移除程序用于恢复精确数据的内部内容；需要编辑展示版时另存到其他目录。具体入口和选项见 `le8/le8.sh --help`。

<a id="overview--optional-input-schemas"></a>

### Optional input schemas
- C4 自定义时钟通过环境变量 `C4_CLOCK_MANIFEST` 指定 TSV，列为 `clock`、`source`、`variable`。同一 `clock` 只能使用一种来源：`all`、`img` 或 `omics`，且至少有三个实际可用变量。例如肾脏时钟可列出 `all` 中的 `creatinine`、`cystatin_c`、`eGFR`，前提是这些列确实存在。不设置该变量时，仍按原流程处理全局组学、可用的表型系统及脑影像时钟。
- 显式 PGS 映射由 `--pgs-mapping` 指定，列为 `pgs_column`、`feature`，例如 `L_VLDL_TG.pct.SCORE_SUM` 对应 `L_VLDL_TG.pct`。
- 客观终点数据由 `--objective-file` 指定。`known_cad_at_index` 表示采样时已知 CAD（0=无，1=有，缺失=未知）；`index_date` 为分子采样日期；`objective_date` 为独立判读的冠脉检查日期；`objective_cad` 为按预先定义标准判定的 0/1 客观病变终点；`objective_modality` 使用 `CCTA` 或 `INVASIVE_CORONARY_ANGIOGRAPHY`，`CAC_CT` 仅用于独立钙化任务。两次日期不同时需要 `intervening_cad` 和 `intervening_treatment`，0 分别表示期间无 CAD 事件、无相关新治疗或治疗改变。


外部任务执行器的续跑记录合并到工作目录中的 `run_status.json`，不再为每个任务
生成长哈希名称的完成 JSON，也不再额外写 `progress.json`。日志使用任务序号和
可读任务名；原有完成凭据仍支持读取。`ALL_COMPLETE.json` 保留为整体完成标记。

## LE8 C1 FINAL：统一方法、病例保护与个体可预测性

本版基于 `jielab/scripts` 的提交 `40a884324f30219f865e8a7a49ac9708a913e742`（2026-10-22 核对），保留该版本的 R glmnet 并行、缓存兼容性及家系 roster 修复。没有修改 `grid`；仅沿用其 `--device auto|cpu|cuda` 接口。

**公开的 C1 分析模块只有 `c1_correlate`。** 统计关联、传统预测、个体参考预测及历史病例迁移属于这个模块中的不同方法。内部 R/Python 辅助文件继续保留，以便复用已有实现及读取历史结果。

<a id="doc-c1-final--1-默认分析方案"></a>

### 1. 默认分析方案

默认方法为 `glmnet,lightgbm,abm_case_preserving,abm_profile,abm_prevalent,abm_legacy,molecular_deviation,abm_deep`，按用户要求同时运行五种主方法及 legacy、分子偏离度、deep 比较。`abm_lenient` 仍需显式选择。疾病和组学层由 `--Y`、`--biom` 决定，对两者的所有组合运行；不会自动遍历参数网格。各方法的科学定义和病例政策保持如下区分。

| 方法 | 实际算法与任务 | 训练病例政策 |
| --- | --- | --- |
| `glmnet` | 实际 R glmnet 的固定时间窗、IPCW logistic LASSO；同一 build/tune/calibration/test 协议 | 不按预测损失删病例 |
| `lightgbm` | 同一队列和目标上的 LightGBM；在 tune_model 选择模型 | 不按预测损失删病例 |
| `abm_case_preserving` | 局部分子 twins；默认以 `twin_clean` 为主概率；保留原有受监督匹配空间作参照 | `keep_fraction=1`，保留所有技术 QC 合格且目标可观测的参考行 |
| `abm_profile` | 全部分子特征进入 build 拟合的 PCA 匹配空间，避免先用单一全局回归筛掉弱边际信号 | 同上；不会因为病例难预测而删除 |
| `abm_prevalent` | 从 development/build 家系的 prevalent 分子原型提取历史相似性；在 incident 样本上学习其增量价值 | 历史病例不加入 incident 风险集或风险分母 |
| `abm_lenient` | 可选敏感性；默认只允许清理约 2% 的合格非事件对照 | 所有随访事件病例保留，包括时间窗之后的事件 |
| `abm_legacy` | 原有按模型损失清理参考库的方法；只作历史敏感性 | 可能移除病例，明确披露，不作为新主方法 |
| `abm_deep` | 默认包含的 feature-token Transformer 与学习表征中的个体参考支持度 | 不按损失删病例；CPU/CUDA 使用同一网络实现 |
| `molecular_deviation` | 默认包含的原有分子偏离度分析 | 维持其独立分析定义 |

`glmnet` 是统一评价协议下受 Pradeep 工作启发的实现，并非声称逐项复现原论文。旧 R 关联和旧 prediction 输出仍是历史/补充结果，不能与新主分析在不同队列、时间窗和指标上直接排名。

新 ABM 中的病例保护是指：技术 QC 合格的已观察到随访事件者，不能因高 OOF loss 被删除或软权重降为低质量。时间窗之后发生事件的患者仍保留，但在当前时间窗的标签仍是未发生事件。技术 QC、提前删失导致目标未知，与基于预测损失删人分别审计。

`abm_profile` 为多种分子组合留下学习空间；PCA、局部邻域或深度网络均不保证已经识别全部患病路径，也不证明路径具有因果意义。

<a id="doc-c1-final--2-生产命令"></a>

### 2. 生产命令

在现有 LE8 生产环境和脚本目录中运行。默认使用现有 `Rscript`、LE8 Python 环境、`/mnt/d/data/ukb`、`/mnt/d/analysis/le8` 及既有 UKB 家系来源。可用 `LE8_REPORT_PYTHON`/`ABM_PYTHON` 指定 Python、`--r-bin` 指定 Rscript；无需为此重建整个环境。依赖以 `environment.yml` 为准。

默认自动加载脚本目录下的 `config/c1_methods.json` 和 `config/c1_history.json`，使用 `--device auto --association run --cores 8 --memory-limit-gb 32`。只需指定模块、疾病及组学层：

```bash
cd /mnt/d/scripts/le8
./le8.sh c1_correlate \
  --Y ra,sle2,ad,epilepsy,mi,cvd_afib,cvd_abaneu,cvd_htn,copd,asthma,masld,amr \
  --biom prot,met
```

结果目录不存在时，从头准备输入、家系名单、关联和模型。之后相同命令默认可续跑已校验的结果；需要强制重新拟合时显式使用 `--replace TRUE`。下面为缩小范围的检查和运行示例。

若在 `DONE ... PWAS/MWAS` 之后的 PGS 阶段发生内存终止，保留结果和 `/tmp/le8-cache`，用原命令续跑且不要加 `--replace TRUE`。输入和分析设置未变时会复用已完成的关联扫描，PGS 则按每个指标的六模型检查点续跑。PGS 会先准备窄表型表，再读入分数；按指标提取匹配行，避免复制整张分数表。`--memory-limit-gb` 同时用于进程树上限和子进程资源设置；`--pgs-workers 1` 可限制拟合并行，但不能消除分数文件本身的加载内存。

原生 C1 关联按疾病、组学层依次启动独立 R 进程，每层完成后立即校验并记录结果。双层运行会输出 `C1 layer isolation`，随后分别显示 `biom=prot` 和 `biom=met`，避免蛋白 PGS 保留的堆内存延续到代谢物阶段。若出现 `Insufficient declared RAM even for one worker`，表示连串行拟合的内存估算都超过预算；仅设置 `--pgs-workers 1` 无法绕过该检查。估算中的父进程占用包含 RSS 和 swap；本次分层修复保留原有内存保护和数值缓存。

```bash
cd /mnt/d/scripts/le8

# 只展示科学参数、数据范围与设备策略，不拟合、不创建结果目录。
bash ./le8.sh c1_correlate --Y cvd_cad --biom prot,met --config config/c1_methods.json --device auto --dry-run
bash ./le8.sh c1_correlate --Y ra --biom prot --config config/c1_methods.json --device auto --dry-run

# 检查方法依赖。完整数据内容在准备队列时验证。
bash ./le8.sh c1_correlate --Y cvd_cad --biom prot,met --config config/c1_methods.json --device auto --preflight
bash ./le8.sh c1_correlate --Y ra --biom prot --config config/c1_methods.json --device auto --preflight

# 指定范围的完整默认方案；同一指纹且文件校验通过的结果会复用。
bash ./le8.sh c1_correlate --Y cvd_cad --biom prot,met --config config/c1_methods.json --history-config config/c1_history.json --device auto --cores 8 --replace FALSE
bash ./le8.sh c1_correlate --Y ra --biom prot --config config/c1_methods.json --history-config config/c1_history.json --device auto --cores 8 --replace FALSE
```

`--association run` 是默认值，调用原生 R 关联阶段。`--association auto` 从真实 host 输入启动时运行关联，从 `--prepared-source` 或 demo 启动时跳过关联；这类输入应显式选择 `auto` 或 `skip`。`--association skip` 适用于只运行预测方法的任务。原生关联只调用内部 `c1_correlate` 阶段，不自动再拟合一套旧 prediction。

没有改变 C2—C5 的公共模块。无模块参数的 `bash ./le8.sh` 仍会继续 C2—C5；本轮仅 C1 的工作应明确写 `c1_correlate`。

<a id="doc-c1-final--3-方法参数与-cpucuda-分开"></a>

### 3. 方法参数与 CPU/CUDA 分开

- `--methods` 指定方法列表，优先于方法配置中的列表。
- `--config` 指定科学方法计划，默认 `config/c1_methods.json`；显式指定其他计划时使用该文件的方法列表。
- `--abm-config` 指定共同基础参数，默认 `config/abm.json`；旧的平面 ABM JSON 也可以由 `--config` 读取。
- `--history-config` 指定历史域假设，默认 `config/c1_history.json`。
- `--deep-config` 指定深度网络参数，默认沿用历史文件名 `config/abm_GPU.json`；该文件名不再决定设备。
- `--device auto|cpu|cuda` 只决定支持加速的引擎的执行设备。当前 glmnet、LightGBM、普通 twin 和历史原型引擎实际运行 CPU，并记录原因。`abm_deep` 的 auto 在 CUDA 可用时使用 CUDA，否则运行 CPU；显式不可用的 cuda 会报错。

按需创建一个有明确假设的计划，例如改变 profile 的 K，并保持半径标定参考 K 固定：

```json
{
  "methods": ["glmnet", "lightgbm", "abm_case_preserving", "abm_profile", "abm_prevalent"],
  "overrides": {
    "abm_profile": {"k": 128, "radius_k_ref": 64, "dimensions": 24}
  }
}
```

把文件保存为 `config/c1_profile_k128.json` 后，先用 `--config config/c1_profile_k128.json --dry-run` 检查。不要为了挑最高测试 AUC 而自动遍历参数。共同的 horizon、assay feature_missing 和 sample_missing 是研究协议；不能在同一比较中悄悄按方法改变。新病例保护方法也不能通过 override 改回损失删病例。

限定方法或指定设备的示例；显式 `--methods` 会覆盖默认方法列表：

```bash
# 明确选择历史/宽松清理敏感性，并保留共同基线。
bash ./le8.sh c1_correlate --Y cvd_cad --biom prot --methods glmnet,lightgbm,abm_case_preserving,abm_legacy,abm_lenient --device cpu --association skip --dry-run

# 同一个深度方法在不同设备上运行；执行前先去掉/保留 dry-run 按实际阶段选择。
bash ./le8.sh c1_correlate --Y cvd_cad --biom prot --methods abm_deep --device cpu --association skip --dry-run
bash ./le8.sh c1_correlate --Y cvd_cad --biom prot --methods abm_deep --device cuda --association skip --dry-run
```

追加单个方法且要复用完全相同的 prepared cohort 时，用 `--prepared-source` 指向已校验的 `c1_correlate/_LOCAL_ONLY/inputs/<指纹>`。一个 prepared source 只属于一个疾病和一个组学层；包含 prevalent 方法时必须有历史来源文件。旧 incident-only NPZ 不能凭空补出历史病例；首次历史方法需要从 host 输入准备。

旧入口仍可读取命令：`c1_abm` 映射为 `abm_legacy,molecular_deviation`，`c1_abm_GPU` 映射为 `abm_deep`。多个旧/新 C1 模块名会合并成一次统一调用，并给出弃用提示。新命令统一使用 `c1_correlate --methods ...`。

<a id="doc-c1-final--4-历史病例的使用边界"></a>

### 4. 历史病例的使用边界

基线 prevalent 者继续不属于新发风险评价队列，但不再一概作为无用信息丢弃。历史分支只使用允许的 build 家系，严格排除 held-out 家系和重复人员。先在 incident build 中拟合年龄/性别相关的分子调整，再构建历史原型和支持特征。年龄重叠、性别匹配、诊断距基线时长及用药暴露分别记录。

当前 duration/treatment 权重是显式的敏感性假设，不是已验证的反向因果校正。缺少年龄/性别或缺乏历史匹配时，不删除 incident 患者，历史支持特征置零并保留风险预测。源域总体可用且选择了非零 alpha 时，带零历史特征的 incident risk head 仍可能与无历史对照产生不同预测，不能把个体历史特征为零解释为其最终概率增量严格为零。只有整体 source 不足或 alpha=0 时，才保证与无历史对照完全一致。

历史增量的混合权重只在 tune_model 上选择，候选为 0—0.25；0 允许模型拒绝历史信息。0.25 限制的是校准前的概率混合，不能声称校准后的概率变化必然不超过 0.25。自动生成 `abm_prevalent_control`：同一 incident 样本、相同基础 PCA/clinical 表示及相同 HGB 架构和超参数，区别是是否额外加入历史相似性特征，用于识别历史信息的真实增量。

<a id="doc-c1-final--5-每个人的输出与公平评价"></a>

### 5. 每个人的输出与公平评价

每个方法输出模型自身的预测概率、预期 Brier 误差、predictability、风险分层后的残差 predictability、支持状态和匹配信息。预期误差在 development 的 tune_gate 上学习；阈值在 development 中冻结。development 资料不足时如实标记 unavailable/support_only，不能把支持度冒充已校准的个体正确率。`calibration_audit` 和 test 不参与这些拟合。既有测试队列已被查看，因此新结果应表述为已查看测试集上的探索性比较，不能重新命名为全新未触碰的验证。

匹配信息至少区分：

| 字段 | 含义 |
| --- | --- |
| `eligible_match_count` | 固定半径内所有合格 incident 参考人数，不被 K 截断 |
| `matched_count` | 实际取用的邻居数，最多 K |
| `eligible_reference_count` | 对该人可用的参考库分母，排除本人/相关家系 |
| `twin_fraction` | 原始匹配数除以可用参考数 |
| `donor_ess` / `family_ess` | 按实际权重计算的有效参考数 / 有效独立家系数 |
| 历史支持字段 | 仅描述 prevalent 源域支持，不能混入 incident twin count |

新方法默认 `radius_k_ref=64`，把半径标定的参考 K 与预测用的 K 分开。改变预测 K 不会仅因容量截断而制造“更多 twins”的表象。跨不同训练库大小、维度或匹配空间比较时，仍需同时查看参考库 N、半径、匹配比例与 ESS。

Matched twin count 是可审计的个体支持度指标，尚不是“预测一定正确”的证明；必须检查它与实际误差的关系，并控制基线风险差异。框架在每个 selector 选出的**同一批人**上评价所有方法，还保留原始队列和未获支持者的覆盖信息。

共同评价使用相同结局、时间窗、build 拟合的删失模型、共同 finite/QC roster 与配对家系 bootstrap，报告 horizon IPCW AUC、完整随访 Harrell C、Brier、log loss、校准、N、病例数、IPCW ESS 和实际 coverage。风险匹配对照的样本量与入选样本量相同，帮助区分挑选低风险人群与模型真正改善。它不把不同人群的 AUC 自动变成同一个估计目标，也不能用“除以 N”调整 AUC。

默认主要推断包括全共同队列及预先指定的 50% 目标覆盖；其余覆盖点主要作描述。有限 bootstrap 有效重复不足时，不输出貌似可信的置信区间。删失权重采用既定固定时间窗风险定义，未新增 competing-risk 模型；死亡按输入中的删失编码处理。

## Frozen evaluation and reference-support audit — 2026-10-21

This supplement describes the new evaluation entry points. The original fit
configuration `config/abm.json` is unchanged. A report correction is not a new fit.
All reviewed CAD results remain exploratory because they have already been inspected.

<a id="doc-fair-evaluation--1-re-evaluate-frozen-predictions-first"></a>

### 1. Re-evaluate frozen predictions first

From the `le8` directory, using its Python environment:

```bash
python f/c1_fair_evaluation.py \
  --analysis-root /mnt/d/analysis/le8 --trait cvd_cad --layer prot \
  --output /mnt/d/analysis/le8/cvd_cad/prot/c1_fair_evaluation/review_20261021 \
  --bootstrap 1000 --count-bootstrap 1000 --include-gpu
```

Repeat with `--layer met` and a separate output directory. For RA use `--trait ra
--layer prot`. The latter can only report `not_available` until private frozen
prediction/model/truth files actually exist. An intermediate training-screening
workbook is not a substitute for a completed holdout evaluation.

The script reads the trusted local artifacts under `c1_abm/abm_twin`:

- `fit/model_LOCAL_ONLY.joblib` and `fit/MODEL_FROZEN.json`;
- `test_predictions_LOCAL_ONLY.joblib`, `test_truth_LOCAL_ONLY.npz`;
- `host_contract.json`;
- optionally `development_LOCAL_ONLY.npz` for frozen calibration-audit projection.

The model, saved test predictions, original result tree and receipts are never
overwritten. The output directory must be new. No risk model, selector or calibration
model is refitted, and test predictions are not recomputed. The reference projection
uses only the predeclared `calibration_audit` features/IDs/groups, not its outcomes.
It respects the existing development-overlap check. `--skip-reference` omits that
projection; fixed count/support bins remain available, while other score-ordering
bins are explicitly unavailable. `--count-bootstrap 0` skips the extra count-only
inference without suppressing descriptive support tables.

New count cutpoints derived from calibration-audit features are exploratory
auxiliary analyses; they are not the original calibration-fit deployment gate.

The report contains aggregate TSVs and `fair_evaluation.xlsx`, with source hashes,
component availability and a final receipt. It does not export participant IDs.

<a id="doc-fair-evaluation--2-evaluation-contract"></a>

### 2. Evaluation contract

Primary discrimination measures are reported together:

- `Harrell_C`: full observed follow-up, strictly ordered event times, risk ties at
  half credit. Tied survival times are excluded from comparable pairs.
- `AUC_IPCW`: cumulative case/control discrimination at the frozen horizon
  (10 years in the reviewed configuration), using one shared frozen build-derived
  censoring distribution for the compared arms.

Secondary measures are horizon-truncated Uno C and IPCW Brier/log-loss. Brier and
log-loss use the existing Hájek normalization, `sum(w*loss)/sum(w)`. The frozen
reverse-KM tie convention is retained in a re-evaluation; silently changing it
would also change the original fitting/calibration weights. Conventional C1 Cox
rank/link scores are not absolute risks and therefore do not receive probability
losses without a separately development-calibrated absolute-risk export.

Within each subset all arms use a common finite-prediction roster. The GPU comparison
also applies frozen CPU reference QC and intersects an explicit saved GPU QC mask
when available. Legacy GPU files lack this column; the report identifies that fact
and does not infer QC from zero IPCW weight, which also occurs after early censoring.
Future GPU exports include `technical_qc`.

Report requested/evaluated/excluded N, events, horizon cases/controls, comparable
pairs, roster hashes and grouping provenance. IPCW effective N and class-specific
effective N describe weight concentration; they do not replace actual sample counts.
Paired family resampling uses the same draw for every arm. At least
`max(20, ceil(0.8 * requested_B))` valid replicates are required for an interval;
otherwise point estimates remain visible and inference is marked unavailable.
Intervals condition on the frozen models, selectors and censoring estimator.

An all-versus-selected comparison changes the population. It is a selection
composition comparison, not proof of algorithm superiority. Algorithm contrasts
must use the same selected people. Risk-matched random controls match counts in
risk bins; they do not guarantee exact balance of continuous predicted risk.

<a id="doc-fair-evaluation--3-individual-support-and-predictability"></a>

### 3. Individual support and predictability

The diagnostics are distinct:

| Field | Meaning |
|---|---|
| `eligible_match_count` | All eligible, nonself, nonfamily donors inside the frozen radius; not capped at K. |
| `matched_count` | Donors actually used after the K cap; legacy name retained for compatibility. |
| `eligible_reference_count` | Positive-weight donors after excluding the query and its family. |
| `twin_fraction` | Raw eligible match count divided by eligible reference count; undefined if denominator is zero. |
| `family_ess` | Effective independent family support among weighted donors actually used. |
| `matching_radius` | Frozen radius in the stated model geometry. |
| `pre_prediction_confidence` | A reference-support score, not a probability of being correct. |
| `risk_resid_error` | Frozen error-related selection score for `elasticnet_full`. |

Old `estimated_error['absolute_error']` targets `config.primary`, often
`elasticnet_clean`; it must not be assessed as if it predicted full-model error.
The new support module preserves each score's actual target.

Non-QC rows were never matched and their zero placeholders are unavailable support
measurements, not observed zero twins. Old frozen banks can supply missing reference
denominators and radius without changing the model. Fixed count bins, K saturation,
ESS/radius distributions, support versus error and count-only risk-matched controls
are aggregate outputs. A larger count is not itself evidence of smaller error.
Normalizing reference N does not make different geometries or adaptive radii equivalent.

<a id="doc-fair-evaluation--4-optional-reference-experiment-requires-a-fresh-fit"></a>

### 4. Optional reference experiment: requires a fresh fit

`config/abm_balanced_reference.json` is an explicit exploratory alternative:

```json
{
  "pruning": "class_risk_stratified",
  "reference_radius_policy": "full_fixed",
  "twin_random_control": true,
  "min_retained_cases": 20,
  "min_case_retention": 0.8,
  "reference_experiment": "balanced_reference_20261021"
}
```

The full file contains the other original settings. Class/risk-stratified pruning
protects the planned case retention. The random library has the same retained
case-by-OOF-risk-bin composition and total N as the clean library. Molecular and
integrated clean/random banks use their respective full-bank geometry and radius.
Per-query match counts, ESS and separately learned calibration functions can still
differ. This is a reference-composition experiment, not a guarantee of better AUC.

New host preparation treats numeric labels of age as continuous unless the variable
is explicitly declared categorical. Encoding is inferred from build rows only.
`clinical_encoding_version` enters cache compatibility checks. A legacy prepared NPZ
already containing age dummy columns remains legacy: regenerate inputs for the
continuous-age experiment. Use a separate analysis root/configuration and preserve
the existing outer roster and family mapping. Do not overwrite or recertify old fits.

<a id="doc-fair-evaluation--5-optional-training-budget-learning-curve"></a>

### 5. Optional training-budget learning curve

Plan only; no fit and no test-outcome read:

```bash
python f/c1_training_budget.py \
  --source /mnt/d/analysis/le8/cvd_cad/prot/c1_abm/abm_twin \
  --fractions .5,.75,1
```

Actual execution is explicit:

```bash
python f/c1_training_budget.py \
  --source /path/to/prepared/abm_twin \
  --fractions .5,.75,1 --out /path/to/new_budget_experiment --run
```

Build families are hash-sampled in nested budgets; other roles remain unchanged.
Every budget refits its own preprocessing and feature selection. All test
predictions are frozen before any test truth is read. All budgets/arms share one
QC/finite evaluation roster and the largest-budget frozen censoring distribution.
Offered build N, actual eligible/pruned N and extra development-role N are separate.
The learning curve is descriptive and does not automatically select a winning budget.

When a source plus an algorithm-template override is used, the resolved source
clinical schema and trait/layer/horizon/grouping contract must be retained. The
script audits those inherited fields and rejects conflicting nonempty clinical
indices. A flat template's empty clinical list cannot turn age/sex into molecules.

This is a same-input, same-offered-build-budget comparison within the ABM pipeline.
It does not establish a matched clinical feature set, objective or training budget
with the broad external C1 Cox benchmark. Do not divide AUC/C by N or discard test
participants solely to equalize protein and metabolite cohort sizes.

## f — usage notes

Run the public script with `-h` for minimal usage and an example with options. These examples are alternatives; complete workflows, prerequisites and detailed options follow.

<a id="doc-f-0-readme--0enginesh--detailed-reference"></a>

### 0.engine.sh — detailed reference

```text
Usage: ./le8.sh [module[,module...]] --Y disease[,disease...] --biom prot,met [options]

Modules (executed in pipeline order):
  c1_correlate   Associations, temporal sensitivity, enrichment + basic prediction
  c2_cause       cis/trans MR, MR-link-2 and DANDELION
  c3_coloc       Coloc and optional fine-mapping/GPU-coloc
  c4_connect    LE8 connections, interactions, nonlinearity, panel validation and reconstruction bootstrap
  pgs_focus     Matched measured/PGS, cross-fitted G/R, source and locus analyses
  final_prediction Joint prot/met/biomarker PGS + automatic all.rds [Y].pgs; outputs in final/<trait>/
  final         Assemble publication figures, tables and result summary

Examples:
  # Public default: C1-C5 with reference ABM; final/shiny are separate.
  ./le8.sh --Y cvd_cad,ra --biom prot,met
  # Selected modules for multiple diseases and both omic layers.
  ./le8.sh c2_cause,c3_coloc --Y cvd_cad,ra --biom prot,met
  ./le8.sh c1_correlate --Y cvd_cad --biom prot
  ./le8.sh c4_connect --Y cvd_cad --biom prot
  # Disease PRS is read automatically from all.rds cvd_cad.pgs (or [Y].pgs).
  ./le8.sh final_prediction --Y cvd_cad --biom prot,met --replace TRUE
  # Default budgets c(5,10,50) are editable in f/0.common.R.
  C4_FOCUS_BUDGETS=5,10,50 ./le8.sh c4_connect --Y cvd_cad --biom prot
  # Reassemble existing results without fitting models.
  ./le8.sh final --Y cvd_cad --biom prot,met
  # Recover Final after every joint fold is saved; also retry per-layer reference.
  FINAL_JOINT_SUMMARY_ONLY=TRUE ./le8.sh final_prediction --Y cvd_cad --biom prot,met --cores 1
  # Inspect planned commands or check available inputs/dependencies.
  ./le8.sh c2_cause,c3_coloc --Y cvd_cad,ra --biom prot,met --dry-run
  ./le8.sh c2_cause,c3_coloc --Y cvd_cad --biom prot --preflight
  # Explicitly recompute selected modules (existing outputs are otherwise reused).
  ./le8.sh c4_connect --Y cvd_cad --biom prot --replace TRUE
  # Optional methods: Top / All / None. MAGMA is a labelled sensitivity only.
  ./le8.sh c2_cause --Y cvd_cad --biom prot --run-mrlink2 Top --run-dandelion Top
  ./le8.sh c2_cause --Y cvd_cad --biom prot --run-dandelion None
  # Cellular analyses are available through the public c5_cellulation module.

Common options:
  --Y CSV              Disease(s); -Y and --trait are accepted aliases
  --dir-analysis-root DIR  Output root (default /mnt/d/analysis/le8)
  --dir-ukb-phe DIR        Phenotype/omics input root
  --Y-date COLUMN     Disease date column in all.rds
  --vars.adj CSV      Explicit covariates; changes require a new output root or replacement
  --white-only BOOL   Restrict ancestry (default TRUE)
  --cores N            Worker count (default 1)
  --memory-limit-gb N  Process-tree RAM cap in GiB (default 32)
  --seed N
  --run-gpu-coloc BOOL --nested-cv BOOL
  --help

Use one positional comma-separated module list; --steps/--from-step/--from/--to
are not supported. Missing prerequisite results are scheduled automatically.
```

### c3.coloc_GPU.sh — detailed reference

```text
Usage:
  ./f/c3.coloc_GPU.sh \
    --qtl-manifest c3_coloc/qtl_cad_manifest.tsv \
    --cad-gwas /mnt/d/data/gwas/main/common/cvd_cad/gwas/cvd_cad.gz \
    --dir-out c3_coloc \
    --outcome-type cc

The qtl manifest is generated by c3.coloc.R with columns:
  omics  trait  file  type  region
```
