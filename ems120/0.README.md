# EMS120：默认启明 HPC，兼容 local

新代码位置是 **`scripts/ems120`**，入口是 `scripts/ems120/ems120.sh`。本版本基于提交 `bf7368b5fd72c9b85b55ea8e942062531e165d59` 的 `0LOCAL/ems120` 迁移；完整 R 分析与 Python 模型代码均随包提供。

默认提交启明 LSF GPU 作业。只有显式 `--submit local` 才在当前机器执行；找不到 `bsub` 或提交失败会报错。请在完整 `scripts` 仓库内使用，共享目录表及 R 绘图 helper 来自同级 `0f`。

## 1. 从仓库根目录运行

```bash
cd /work/sph-huangj/scripts

# 只生成配置和 .cmd，不激活 Conda、不导入 Torch、不读取患者数据、不提交。
bash ems120/ems120.sh --plan-only

# 提交 GPU 环境检查；检查在计算节点执行。
bash ems120/ems120.sh --check-gpu --wait

# 提交完整分析；提交后打印 job ID、plan 和日志目录，然后返回。
bash ems120/ems120.sh
```

`--check-gpu` 在选定 Conda 环境的 **R/reticulate 进程内**运行 CUDA 张量运算，并检查 XGBoost CUDA 构建和一次极小的合成数据拟合。它不读取患者数据、不训练正式模型。默认检查任务限时 1 小时，正式分析限时 120 小时。

Conda 位置或环境不同，可以覆盖；以下示例路径需要替换为实际已安装位置：

```bash
bash ems120/ems120.sh \
  --conda-exe /work/sph-huangj/software/miniconda3/bin/conda \
  --conda-env /work/sph-huangj/.conda/envs/ai \
  --check-gpu --wait
```

程序不会在登录节点或作业内自动安装 R/Python 包。完整依赖和数据准备见 `requirements-notes.md`。

## 2. 默认资源及调整

| 项目 | HPC 默认值 | 说明 |
|---|---|---|
| 队列 | `4a100-40` | 按用户提供的启明队列表选择 A100 40 GB 队列 |
| 节点 | 1 | `span[hosts=1]`；当前流程不是多节点分布式训练 |
| GPU | 1 | `num=1/host:mode=exclusive_process:j_exclusive=yes` |
| CPU | 8 核 | R/data.table、Torch、模型 `n_jobs` 受作业核数约束 |
| 主机内存 | 96 GiB | `-M 96GB`、`rusage[mem=96GB/host]`，与 GPU 显存不同 |
| 正式分析限时 | 120 小时 | `--hours` 可调；已知 GPU 队列按截图上限 336 小时 |
| Conda 环境 | `ai` | `--conda-env` 接受环境名或绝对前缀 |
| 提交后等待 | 否 | `--wait` / `--wait TRUE` 等待；`--wait FALSE` 只提交 |

这些是起始申请值，并非根据真实 EMS 全量数据测得的峰值。首次运行后根据 LSF 内存统计和耗时调整：

```bash
bash ems120/ems120.sh --cores 16 --memory-gb 160 --hours 168

# 更大单卡显存队列示例；可用性取决于账号权限和排队情况。
bash ems120/ems120.sh --queue 2a100-80 --cores 8 --memory-gb 96
```

入口拒绝已知 CPU 队列、超过所选队列保守节点容量的申请及 `--gpus 2` 等未经实现的多卡请求。phone、geo、疾病交叉验证/推理仍按原数据依赖顺序执行；多申请 GPU 不会自动并行化它们。

HPC 保留 LSF 的 `CUDA_VISIBLE_DEVICES`，使用分配后可见的逻辑设备。要求 GPU 时若可见设备不是恰好一张，会明确失败，避免 Trainer 意外使用未分配的卡。

## 3. 统一路径

共享根目录由 `../0f/0os.sh` 解析，使用 2026-11-04 的两个根目录布局；无需定义 `--dir-tmp`。

| 用途 | 默认 HPC 路径 | 默认 local 路径 | 精确覆盖参数 |
|---|---|---|---|
| EMS 输入 | `$DIR_DAT/ems120`，通常 `/work/sph-huangj/ems120` | `/mnt/d/ems120` | `--dir-data` |
| 预训练模型 | `$DIR_BIG/AI_model/hfl` | `/mnt/f/AI_model/hfl` | `--dir-base-model` |
| 分析、缓存、成图 | `$PERSISTENT_ANALYSIS_ROOT/ems120`，通常 `/work/sph-huangj/analysis/ems120` | `$ANALYSIS_ROOT/ems120`，通常 `/mnt/d/analysis/ems120` | `--dir-analysis` |
| 训练模型 | `<analysis>/ml` | `<analysis>/ml` | `--dir-model` |
| YinYang 等素材 | `$DIR_FILES` | `/mnt/d/files` | `--dir-files` |
| 计划、日志、状态 | `<analysis>/.jobs` | `<analysis>/.jobs` | `--dir-jobs` |
| 作业临时文件 | `<analysis>/tmp/<run-id>/<job>` | `<analysis>/tmp/<run-id>/<job>` | 跟随 `--dir-analysis` |

`--dir-dat` 是包含多类数据的共享根目录，`--dir-data` 是直接包含 `clean/`、`szu_xia/` 的 EMS 输入目录，二者层级不同。模型根目录下保留 `hfl/`、`hfl_geo/`、`phone_sco3/` 原有结构。

```bash
bash ems120/ems120.sh \
  --dir-dat /work/sph-huangj \
  --dir-big /work/sph-huangj/data \
  --dir-analysis /work/sph-huangj/analysis/ems120 \
  --dir-base-model /work/sph-huangj/data/AI_model/hfl \
  --plan-only
```

模型、长期缓存和临时文件均默认位于持久分析目录。命令行参数优先于对应 `EMS120_*` 环境变量，环境变量优先于派生默认值。`--analysis-dir` 保留为 `--dir-analysis` 的别名。

预训练模型须提前下载完整。任务默认启用 Hugging Face 离线模式；模型目录缺失时会失败，不会等待节点联网下载。

## 4. local 运行

Shell 入口支持 Linux / WSL，保留原 D/F 盘映射默认值：

```bash
# 默认仍要求 GPU；前台等待整个流程，详细输出写入打印的日志目录。
bash ems120/ems120.sh --submit local

# 显式选择本地 GPU；既有设备选择会被保留。
CUDA_VISIBLE_DEVICES=1 bash ems120/ems120.sh --submit local --check-gpu

# 自定义本地路径。
bash ems120/ems120.sh --submit local \
  --dir-dat /mnt/d --dir-big /mnt/f \
  --dir-analysis /mnt/d/analysis/ems120

# 没有 GPU 时的显式 CPU 调试。
bash ems120/ems120.sh --submit local --gpu FALSE --cores 4
```

local 未设置 `CUDA_VISIBLE_DEVICES` 时选择设备 0；已有显式选择保持不变。local 默认核数不超过 8 及可见 CPU 核数；`--memory-gb` 在 local 中仅记录预算，不会像 LSF 一样建立内存硬限制。原生 Windows 的路径辅助逻辑保留，但 `bash` + `flock` 入口需要 Linux/WSL，未作为 PowerShell 原生程序验证。

## 5. 三个 ML 模块的实际 GPU 行为

| 模块 | 新版执行方式 | 方法保留情况 |
|---|---|---|
| `ml_dx` | PyTorch CUDA 训练、五折 CV 和推理 | 标签、字段、折数、种子及训练参数保留 |
| `ml_geo` | PyTorch CUDA 训练、推理；疾病阶段前释放模型 | 地址分类及 Xia 数据关联方法保留 |
| `ml_phone` | XGBoost 候选启用 `tree_method=hist, device=cuda`；规则和 CPU 候选保留 | 评分规则、特征和按 CV RMSE 选择模型的方法保留 |

旧 phone 代码并未启用 CUDA。ElasticNet、RandomForest 和可选 LightGBM 比较器仍使用 CPU，线程数受申请资源限制。已有有效的 CPU 获胜模型继续复用，不会因为迁移到 GPU 就强制替换赢家。日志会记录所选模型，不能把整个 phone 流程解释为纯 GPU 运算。

默认 `--phone-gpu required`：需要新训练或使用 XGBoost 时，要求 XGBoost ≥2.0 的 CUDA 构建，并检查试训练后实际 booster 设备。训练错误会传递给 R，不再吞掉错误后生成全 NaN 电话分数。

`--phone-gpu auto` 允许明确记录后的 CPU 回退；`--phone-gpu off` 关闭 phone CUDA 分支。二者不关闭 `ml_dx`/`ml_geo` 的 GPU 要求。只有 `--submit local --gpu FALSE` 才显式切换整个本地流程为 CPU，同时将 phone 策略设为 `off`。

GPU histogram 和浮点计算可能造成细小数值差异。本迁移保留方法定义，不承诺 CPU/GPU 重训结果逐位相同；迁移既有模型时应保留库版本并核对代表性输出。

## 6. 重跑、缓存和并发

- 每次调用建立独立 plan、命令、日志和状态文件，记录绝对路径、阶段、资源及主要环境参数。
- 分析目录和模型目录各有一把非阻塞写入锁，同一输出正在使用时，新作业明确退出。不同输入和输出目录可分别提交多个任务。
- RDS 先写同目录临时文件，成功后替换；DX/GEO 模型先保存完整临时模型目录，再发布；电话模型用 `.incomplete` 标记防止复用半份文件。
- 可捕获的模型发布错误会恢复旧模型；若节点直接被杀死，可能保留 `.staging-*` / `.previous-*` 目录，应排查后处理，不要将其视为完成标记。
- 重新执行原命令会创建新计划并按原逻辑复用完成的缓存。失败/未知 `bsub` 回执不自动重试，先检查 `submission.json` 和 `bjobs`。
- 缓存仍按原 RDS/版本逻辑复用，并无完整的输入内容指纹。输入数据、标签、基础模型或定义改变时，使用新的分析目录，避免误用旧结果。

绘图范围参数仍可使用：

```bash
bash ems120/ems120.sh --start-step fig2 --end-step fig2 --run-cv FALSE
```

start/end 限制绘图阶段，前面的数据和 ML 缓存检查仍会执行；没有缓存时仍可能训练。`figS` 依赖主图创建的对象，按原逻辑会从 fig1 开始准备。因此 `--end-step fig1` 不是“小样本训练”开关。

显存不足时可降低推理批量，默认仍使用原代码的批量值：

```bash
EMS120_DX_BATCH_SIZE=256 EMS120_GEO_BATCH_SIZE=256 \
  bash ems120/ems120.sh --queue 4v100-16-sc --memory-gb 96
```

`EMS120_PHONE_BATCH_SIZE`、`EMS120_SENS_N_PERM` 以及显式 Chrome/Edge/Fig2 Python 路径也会存入计划。置换次数是研究参数，应保持正式分析所需的设置。
