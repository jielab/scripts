# 按 McManus et al. (2023) 方法计算 LD blocks

当前目标是将 **A unifying statistical framework to discover disease genes from GWASs** 的 LD 分块方法应用到 **GRCh38、3,202 人的 1000 Genomes PGEN 数据**。默认 `--grch 38`，不再默认使用 GRCh37 VCF。

这是论文公开方法的独立实现与新数据分析，不是对原文块数、坐标或整篇分析的完全复现。原文使用 Phase 3 的 2,504 人，并展示 GRCh37 坐标；当前数据集、坐标与样本数不同。
[论文全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC10025450/)

## Usage example：HPC

代码目录：`/work/sph-huangj/scripts/ld`。输出根路径已按用户确认使用带末尾 `j` 的 `/data/sph-huangj`。

数据复制完成后，在 HPC 登录终端执行。默认 GRCh38：

```bash
cd /work/sph-huangj/scripts/ld
./ld.sh
```

显式指定版本：

```bash
# GRCh38，与默认相同
cd /work/sph-huangj/scripts/ld
./ld.sh --grch 38

# 可选 GRCh37：需要另行复制 37 的输入；不要同时执行两个示例
# ./ld.sh --grch 37
```

命令执行时才提交；明天运行即明天提交，没有创建定时任务。可以在登录节点运行 `./ld.sh`：它只生成 .cmd、检查输入并调用 bsub，计算在分配的节点执行。生成的 .cmd 包含直接运行保护。

```bash
bjobs -w
# 123456 替换为 bsub 返回的实际作业 ID
# tail -f /data/sph-huangj/analysis/ld/38/chr10.123456.LOG
# tail -n 100 /data/sph-huangj/analysis/ld/38/chr10.123456.ERR
```

输出随版本切换：

```text
/data/sph-huangj/analysis/ld/38/rebuild_v2/ALL.38.bed
/data/sph-huangj/analysis/ld/38/rebuild_v2/{AFR,EAS,EUR,SAS}.38.bed
/data/sph-huangj/analysis/ld/38/rebuild_v2/COMPLETE.json
/data/sph-huangj/analysis/ld/38/chr10/rebuild_v2/logs/

# --grch 37 对应：
/data/sph-huangj/analysis/ld/37/rebuild_v2/ALL.37.bed
```

默认 `OUT=/data/sph-huangj/analysis/ld/[grch]`，不是之前临时设计的 `analysis/ld38`。缓存和临时表也在对应版本目录内。`DATASET.json` 防止不同版本、输入格式或样本表误用同一输出目录。

每条染色体一个 LSF 作业：ser 队列、5 核（PLINK 4 线程加压缩器）、16,384 MB 内存、最长 168 小时。没有固定 pilot，各条染色体独立选择和验证 D，由调度器并行安排；每条内部四个祖源依次计算。最后一个 merge 作业（1 核、4,096 MB）等待染色体作业成功后，确认 chr1–22 全部结果完整才汇总。无需 GNU parallel，也不需要 GPU。

这些资源数是初始配置，不能保证任意染色体在 168 小时内完成；实际内存、耗时和个人存储配额需观察首轮生产作业。`df` 显示文件系统空闲空间，不代表个人可用配额。

ld.sh 自动加载 f/env.sh，固定使用 /work/sph-huangj/.conda/envs/py311/bin/python3（Python 3.11.13），并加载 GCC 11.2、PLINK2 和 Zstandard 静态库。入口自动 source conda.sh、conda activate py311，再 module load gcc/11.2.0；用户无需手动激活。兼容非交互批处理环境。任务结束或失败后，再提交同一命令会复核并复用有效缓存。不要向同一输出目录同时提交多个副本。THREADS 默认 4，单染色体申请的核数自动为 THREADS+1。作业内部不再同时处理多条染色体。


### 只处理 chr10–22

```bash
cd /work/sph-huangj/scripts/ld
# 可在登录节点执行：只检查 Python、版本、路径和参数，不计算 LD
./ld.sh --check-env --chr 10-22

# 正式计算通过 LSF 提交，只运行指定范围
```

## 需要 COPY 的数据

GRCh38 默认输入共 **67 个文件，约 14.10 GB**：

| 本机 | HPC 目标 |
|---|---|
| `F:\gen\1kg\38\pfile\chr1.pgen` 至 `chr22.pgen` | `/data/sph-huangj/gen/1kg/38/pfile/` |
| 对应的 22 个 `chrN.pvar.zst` | 同上 |
| 对应的 22 个 `chrN.psam` | 同上 |
| `F:\gen\1kg\38\samples.txt` | `/data/sph-huangj/gen/1kg/38/samples.txt` |

不需要为此次任务复制 VCF、VCF 索引、未压缩 PVAR 的重复副本、EUR 子目录、旧 LD 巨型临时表或 GRCh37 缓存。PGEN 如有外部 `.pgen.pgi` 索引必须一起复制；本次本地清单中没有该文件。

程序支持 `.pvar.zst` 和 `.pvar`，两者同时存在时优先读取 `.pvar.zst`。本站复制清单按现有本地文件选择压缩版本。`f/input_sizes.38.tsv` 记录大小；`f/check.sh` 检查缺失、大小及 PSAM 样本集合。大小一致不是内容哈希校验，必须等复制操作完整结束再提交。

`--grch 37` 使用 `gen/1kg/37/pfile` 和 `37/samples.txt`，不再附带 GRCh37 大小清单，可用 `LD_INPUT_MANIFEST` 指定外部清单。不要混用版本；`--grch` 指定输入的坐标版本，不执行 liftover。

## 每条染色体一个 .cmd

`./ld.sh --chr 10-22` 生成如下结构：

```text
/data/sph-huangj/analysis/ld/38/
  chr10.cmd
  chr11.cmd
  ...
  chr22.cmd
  merge.cmd
  chr10/             # chr10 独立的 PGEN 缓存、中间结果和日志
  chr11/
  ...
  chr22/             # chr22 自己的结果，与其他染色体地位相同
  rebuild_v2/        # merge 作业发布的最终汇总结果
```

仅生成、不提交：

```bash
./ld.sh --chr 10-22 --write-cmd
```

默认 `./ld.sh` 生成 chr1.cmd 至 chr22.cmd。作业名为 `ld38.step1.chrN`，汇总名为 `ld38.step2.merge`，依赖条件为 `-w 'done("ld38.step1.chr*")'`。请勿重复提交同名作业。提交记录仍以时间和进程号区分保存。

`--chr 10-12` 只检查和提交 chr10、chr11、chr12，不要求 chr22 输入。merge 始终检查 chr1–22 的完成标记、样本/工具/方法设置、BED 和选参文件哈希；缺少任一条则退出并列出缺失项，不发布部分汇总。补齐其他染色体后，可单独提交：

```bash
bsub -q ser -n 1 -R 'rusage[mem=4096]' -W 168:00 -J ld38.step2.merge -w 'done("ld38.step1.chr*")' -o /data/sph-huangj/analysis/ld/38/merge.%J.LOG -e /data/sph-huangj/analysis/ld/38/merge.%J.ERR < /data/sph-huangj/analysis/ld/38/merge.cmd
```

每个 chrN.cmd 的 OUT 为 `ld/[grch]/chrN/`。单染色体结果标记为 SUBSET；最终汇总只生成完整的 `rebuild_v2/ALL.38.bed` 及四个祖源组文件。

旧的范围命名 `.cmd` 不再使用。没有 `.lsf` 文件，也没有 `hpc/` 子目录。

## 样本与算法

使用完整 3,202 人 panel 中以下四个祖源组，共 **2,712 人**：

| 祖源 | 人数 | 参与目标函数的单倍型数 N |
|---|---:|---:|
| AFR | 893 | 1,786 |
| EAS | 585 | 1,170 |
| EUR | 633 | 1,266 |
| SAS | 601 | 1,202 |

AMR 490 人不参与当前四祖源 universal 分块。按用户选择保留亲属样本，不进行相关性剪枝。当前 PGEN 的 PSAM 没有父母列，因此全部选中样本参与 PLINK LD；样本表的父母信息不会被用于排除个体。若未来 PSAM 带非零父母 ID，程序会停止，避免 PLINK 静默按 founder 子集计算。

亲属样本下，样本相关性修正项的独立样本解释不一定成立；本次保留论文目标函数的形式，并按所选样本数计算 N。这应作为“方法应用到新数据”的分析限制记录，不能声称复现原文统计校准。

流程直接从源 PGEN 按祖源筛选：MAF >= 0.05、双等位记录，保留相位，不额外限定 SNP。工作区生成过滤后的 PGEN，源文件只读；不会先导出 VCF。重复 ID 的后续记录添加 `:recordN` 唯一后缀；保留全部变异和基因型，不改源文件。随后检查样本身份、变异排序、缺失基因型和相位，任一不通过即停止。

对每个群体的目标函数保持：

```text
score(i,j) = phased_r²(i,j) - [1/(N-1) + 0.0025]
N = 2 × 当前群体样本数
```

每个候选块的最大跨度受 D 限制；自动比较完整分块边界，通常要求候选 D 后有两个更大 D 的一致确认，或通过覆盖全部变异跨度的对照。有限网格稳定性不等于无距离限制问题的全局最优证明。HPC 默认网格上限 40,000 kb；若仍未稳定则停止，不通过修改计数去强制接受。

GRCh38 下 `REFERENCE_COUNT_POLICY=off`：原论文 GRCh37/Phase3 的计数不适用于当前数据，输出记录为 `not_applicable`，不伪装成通过比较。原有相位、缺失、完整 LD 配对、区间有效性及 D 稳定性检查仍启用。

Universal blocks 保留现有独立实现：2 kb 分辨率、右端点候选、空 spanning set 跳过、零宽 cut 基点归左。端点/退化情况的解释尚未与作者源码核对，先前 GRCh37 chr2 也有计数差异。因此只能报告本实现下的结果，不声称与 KHGP 完全等价。作者源码和预计算 blocks 的公开记录目前为受限文件：
[源码](https://zenodo.org/records/7504848)、[预计算 blocks](https://zenodo.org/records/7838959)。

## HPC 参数

```bash
cd /work/sph-huangj/scripts/ld
./ld.sh                    # 默认 GRCh38 PGEN
./ld.sh --grch 38
./ld.sh grch=38             # 等价写法，不在等号两边加空格
./ld.sh --grch 38 --chr 22  # 仅 chr22
./ld.sh --grch 38 --chr 2-21 # 仅 chr2–21，不依赖 chr22
```

所有入口统一使用 HPC 环境，默认每条染色体一个独立作业，输出 `/data/sph-huangj/analysis/ld/[grch]/`。版本参数优先级：命令行 > `GRCH` > `GENOME_BUILD` > 38。显式 `OUT`、`PFILE_DIR`、`PANEL` 可覆盖自动路径；更换版本时不要继续沿用旧版本的这些环境变量。

主要参数：`THREADS`、`MEMORY_MB`、`D_GRID_KB`、`MAX_D_KB`、`LD_TMP_DIR`、`MIN_FREE_GB`。`OUT/ld.runtime.env` 可提供默认值。`LD_STORAGE=blocked-zstd` 为无损压缩模式。缓存凭据绑定输入、样本、工具和算法哈希，不能靠复制/修改 receipt 绕过检查。

运行版本仅面向 HPC，不再维护 WSL 路径或单独的 hpc 子目录；辅助文件统一放在 f/。VCF 入口仅保留用于方法回归验证，生产默认使用 PGEN。
