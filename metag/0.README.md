## Unified local / HPC entry (2026-11-01)

The maintained source is the same in `D:/scripts` and `/work/sph-huangj/scripts`.
Shared platform settings: `../0f/0os.sh`; shared command runner: `../0f/submit_jobs.py`.
Use `submit=local jobs_N=4 ./ENTRY` or `submit=hpc jobs_N=8 ./ENTRY`.
`--submit local|hpc`, `--jobs-N 1..8`, and `--wait TRUE|FALSE` are also accepted.
For metag, `--submit TRUE` submits, `--submit FALSE` only generates; a value is required.
`split` is the public name (classification plus species splitting); the old `classify` command is removed.
`split --queue NAME` sets both pilot and batch queues; it preserves CPU/memory requests.
The full Kraken profile retains 4 TiB on the smp queue. The spec queue currently has a 168 GB limit.
Selecting a queue never reduces the memory request automatically.
Local .cmd files run in a bounded process pool and wait; failed commands stop new local work.
HPC records real JOBIDs and uses explicit dependencies. Missing bjobs entries never imply success.
GU/LD support `--wait TRUE`; metag retains its stage dependency graph (local stages wait automatically).
`jobs_N` controls local .cmd concurrency and GU/LD HPC concurrency; metag HPC array resources remain in hpc.yml.

|---|---|---|

| DIR_DATA | /mnt/f | /data/sph-huangj |
| DIR_SCRATCH | /mnt/d (= DIR_WORK) | /scratch/2026-10-31/sph-huangj |

Only analysis and metag outputs use DIR_SCRATCH (`analysis/PROJECT` and `metag/`).
Reference data use DIR_DATA; software uses DIR_WORK/software. No scratch path aliases are created.
GU AXT on HPC explicitly uses `/work/sph-huangj/data/annot/axt/37`.
Default scratch date stays 2026-10-31 for this existing run. Use `--date-scratch` explicitly for new runs.
Historical `/work/sph-huangj/scripts.HPC` is a compatibility symlink, not a second maintained code tree.

Continue with `submit=hpc ./metag.sh library --prepared --submit TRUE`.
After the database is complete, use `submit=hpc ./metag.sh split --engine kraken --ready-only --submit TRUE --queue smp`.
Reads are discovered under DIR_SCRATCH/metag/raw. `--ready-only` skips missing mates, empty files,
and aria2-marked downloads; explicit `--sample DATASET/SAMPLE` remains strict.
Use temporary filenames while uploading, then rename to final FASTQ names after completion.
Re-run discovery after more inputs arrive; active plans remain frozen to their selected input states.

Completed preparation can be reused with `./1.library.sh --prepared --submit TRUE`.
This validates every preparation receipt before scheduling only build and conversion.
Local native execution is supported, but the full database's 4 TiB request will be rejected
on a smaller local machine; use HPC for that workload. The existing HPC resource budget is retained.

## 数据上传完成后：先准备元数据和参考清单

必须确认 raw 全部文件上传完成，不能在上传过程中固定参考清单。

```bash
./install.sh setup --metadata-source /data/sph-huangj/annot/metag/0.meta --submit TRUE
```

无扩展名的 UniVec / UniVec_Core 按随包 Kraken 官方下载脚本处理，使用 taxid 28384（other sequences），保留为污染序列参考；不按文件中的宿主名称猜测物种。

在线 setup（省略 --offline）在提交节点从 NCBI 预取当前 taxonomy，计算节点从缓存导入，以解决旧快照缺失/删除 taxid 的问题；原始 0.meta 不改动。--offline 严格使用导入的快照。下载包临时保存在 scratch 的 metadata_hpc 目录，setup 成功后可删除。已有成功元数据和建库计划直接复用。

setup 导入 taxonomy/assembly 元数据、检查每个参考的 taxid，并生成建库计划。缺失映射必须解决，不会静默丢掉参考。软件安装成功不代表 setup 已完成。


Taxonomy 补充：2026-10-31 的完整 dump 缺少本次 15 个 assembly taxid，而 NCBI efetch 实时接口仍返回有效节点。工作副本仅补入缺失节点，逐项验证其祖先与现有分类树一致，并移除这些节点的旧 delnodes 标记；原始 0.meta 不修改。官方 XML 保存为工作元数据 taxonomy/ncbi_supplement.xml，与 dmp 一同保存并记录文件大小。来源：https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=taxonomy&retmode=xml&id=3069032,3454623,3454624,3705353,3705352,3705351,3470104,3480004,2963687,3454144,3681872,3681871,3681870,3465770,3465769

文件检查按路径/文件名和大小进行，不使用时间戳、设备号或 inode；原始 FASTA、准备后的序列与导入元数据不做全量 SHA256。仅保留软件来源、小型任务配置及索引转换一致性所需校验。运行时间只用于日志，不参与文件身份判断。

## setup 作业 DONE 后建库

```bash
cd /work/sph-huangj/scripts/metag
./1.library.sh --submit TRUE
```

准备阶段默认 short，40 核/作业，16 个数组工作进程分批完成全部任务（每次最多 32 个工作进程）。避免 100 个子任务超过账号 50 个 pending 作业限制。需要 spec 时使用 ./1.library.sh --queue spec --submit；仅切换准备阶段，4 TiB 建库继续使用 smp。已提交后不要重复提交另一队列。

依次执行参考准备、无容量 cap 的完整 Kraken 建库、Kun-Peng hashshard 转换。完整结果按凭据复用，保留 prepared、两份索引和运行凭据，不使用 --clean。
