# metag

CPU 宏基因组并行建库与 FASTQ 分类。顺序为 `install.sh`（初始化工具与参考计划）→ `1.library.sh`（准备、五类建库及发布）→ `2.kraken.sh`（联合分类和物种拆分）。`3.compare.sh` 用于另行完成的单库 Kraken/Kun-Peng 比较，不用于当前五类联合库。

在本目录查看参数和示例：

```bash
bash 1.library.sh -h
bash 2.kraken.sh -h
bash 3.compare.sh -h
bash install.sh -h
bash metag.sh -h
```

## local 与 HPC

本项目独立运行，不读取 `../0f/0os.sh`。配置优先级为命令行 `--root`、显式 `--config FILE`（或 `METAG_HPC_CONFIG`）、`hpc.yml`。`--root` 只改变相对路径的根；配置中的绝对路径保持原值。

HPC 默认根目录已统一为 `/data/sph-huangj`，代码可位于 `/work/sph-huangj/scripts.H/metag`。`hpc.yml` 使用启明的队列与持久输出目录，`profiles/taiyi.yml` 提供太乙资源覆盖。所有计算均在生成的 `.cmd` 作业内；未指定 `--submit TRUE` 只生成计划。操作前应在所用集群核实队列与项目配额。

```bash
# 初始化：默认 hpc.yml 期望 legacy 两个目录已经存在。
submit=hpc bash install.sh --config hpc.yml --submit TRUE
# 初始化完成后，五类独立建库并行；publish 等待所有类别 done(jobid)。
submit=hpc bash 1.library.sh --config hpc.yml --submit TRUE
# 库发布完成后，生成 pilot 与 split 的依赖作业。
submit=hpc bash 2.kraken.sh --config hpc.yml --dat-list changj --submit TRUE
```

`profiles/local.yml` 是 96 GiB 工作站的显式本地配置。参考默认位于 `/mnt/f/annot/metag/raw`，FASTQ 默认位于 `/mnt/f/metag/raw`；先按实际目录修改该文件。执行时不需要 `bsub`，数组遵守 `jobs_N` 与 `.cmd` 的 `%并发上限` 两者中的较小值。普通 local 类别构建依次执行，避免五个内存密集构建同时挤占本机内存。

```bash
# fresh local 需要提供已有 taxonomy/assembly metadata；也可以显式使用
# --download-metadata 在提交主机下载官方 metadata。
submit=local jobs_N=2 bash install.sh --config profiles/local.yml \
    --metadata-source /actual/metadata_source --submit TRUE
submit=local jobs_N=2 bash 1.library.sh --config profiles/local.yml --submit TRUE
submit=local jobs_N=2 bash 2.kraken.sh --config profiles/local.yml \
    --dat-list changj --submit TRUE
```

local 支持不等于整套超大参考库能放入 96 GiB 内存。代码保留全量容量估计，若单类别或五库查询所需内存超预算，会在运行前拒绝，不会缩减参考内容以强行运行。大库仍应使用 HPC。

## 保留已有 prepared、metadata 和原生 checkpoint

`hpc.yml` 中的 `legacy_library_dir` 与 `legacy_metadata_dir` 是明确的旧缓存位置，默认分别为 `/data/sph-huangj/cache/metag_legacy/lib_hpc` 与 `/data/sph-huangj/cache/metag_legacy/metadata_hpc`。如果旧缓存仍在其他持久位置，把这两个键改成它们的真实绝对路径；不要删除已有 `prepared/` 或 `metadata/`。没有旧缓存才使用 `profiles/qiming.fresh.yml`，并提供 metadata 来源或显式下载。

已有新流程的 `library_dir`、`parallel_reference_dir`、`tools_dir` 必须继续指向原目录。此次默认路径纠正不会移动文件；覆盖配置前先保留自己的路径值。原生 checkpoint 绑定输入、taxonomy、映射、线程及构建参数和 native binary；本次没有修改 native builder/classifier，已保存的原生哈希可复用。

更换 Python/shell 代码后需要重新生成 `.cmd` 计划，因为计划校验源代码身份；重新生成不会删除 prepared 文件、完整类别或哈希 checkpoint。已在运行的作业应在旧代码副本上运行完毕，或受控停止后再更新代码，避免作业混用版本。

每类作业申请 120 小时，默认约 110 小时软停止、约 4 小时尝试保存实际哈希表。保存发生在完整输入文件边界，写出大表也需要时间，不能保证严格每 4 小时或总共 5 天完成。退出码 `75` 表示已有有效 checkpoint 的暂停，不会被当成完成，也不会放行依赖任务。

```bash
# 确认旧计划中所有运行作业已停止后，恢复同一计划并重建依赖。
submit=hpc bash metag.sh submit --manifest /actual/plan/jobs.json \
    --retry --cancel-pending
```

若更新了本次代码，应先重新生成计划，再提交新计划；旧计划会因代码身份不符拒绝执行。缓存身份不变时会自动复用。

## 验证

`f/2test/` 包含回归测试与入口自检依赖，请保留。端到端原生小样本测试不访问生产数据和网络：

```bash
python3 -m unittest discover -s f/2test -p 'test_*.py'
python3 f/2test/parallel_smoke.py --destination /tmp/metag_smoke_NEW --allow-local
```

`parallel_smoke.py` 的目标目录必须为空或不存在；它会真实编译工具、执行暂停恢复、发布五类库、分类拆分并检查原始 paired FASTQ 字节及成功复用。
