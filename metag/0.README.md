## 1. 安装替换包

先在旧任务终端正常停止旧版 `2.split.sh`，确认其 Python/MetaCache 子进程退出。

把 ZIP 解压到一个独立的临时目录。在有 `replace_metag.sh` 的目录执行：

```bash
bash replace_metag.sh
```

默认替换 `/mnt/d/scripts/metag`，自动备份旧代码目录；保留旧 `f/metag.conf` 的路径及已有设置，补入新设置。参考 FASTA、永久数据库、原始 FASTQ、分析结果和已安装的 MetaCache 不在替换范围内。自定义代码位置可用 `--target` 指定。

如果直接手动复制，应先备份旧代码，再用本包的整个 `metag/` 目录替换代码目录，保留实际配置。不要把代码包覆盖到数据目录。

**已经完成的 1.library.sh 不需要重跑。也不需要重新运行 install.sh。**
首次正式查询会自动用本机 g++ 编译一个小型 C++17 合并器，不会重新编译 MetaCache，也不会访问网络。原安装过程已经要求 g++。

## 2. 可以直接使用的命令

检查这个已知样本的真实输入和数据库：

```bash
cd /mnt/d/scripts/metag
bash 2.split.sh --plan --sample Ndesert/SRR23862437
```

自动定位该样本并进行小规模测试：

```bash
bash 2.split.sh --benchmark --sample Ndesert/SRR23862437
```

测试默认使用前 100,000 个配对 fragments，数据库清单中的首/中/末三个分片，以及 batch 512、4096、8192。自动创建测试目录；不用手填 FASTQ 路径或数据库文件名。它是吞吐诊断，不能代表整个样本的物种检出敏感性，不会生成正式 species 输出。

正式处理这个样本：

```bash
bash 2.split.sh --sample Ndesert/SRR23862437
```

处理已下载完成的数据集，或所有输入布局完整的数据集：

```bash
./2.split.sh --dat-list changj,Ndesert,Wxiamen
./2.split.sh
```

默认使用 GPU，batch size 为 `f/metag.conf` 中的 `QUERY_BATCH_SIZE=4096`，无需每次指定。
不带参数时扫描 `DIR_RAW=/mnt/f/metag/raw` 下所有数据集，逐样本检查正式输出：
完成记录与当前输入、数据库和代码一致且输出文件完整时自动跳过；未完成任务复用同一版本的已提交检查点。
删除正式输出后，该样本会重新生成结果；若工作缓存也已清理，则重新查询。
仅有输出文件夹不代表已完成，冲突或不完整的正式输出会报错，避免静默跳过或覆盖。
输入缺少 mate、存在重复 FASTQ 或 `.aria2` 下载标记时会报错，应先处理输入状态。
需要 CPU 时显式使用 `--backend cpu`；需要其他 batch 时使用 `--batch-size`。

只用 run ID 也可以；如果它出现在多个数据集中，会要求使用 dataset/run 来消除歧义：

```bash
bash 2.split.sh --sample SRR23862437
```

更多选项：

```bash
bash 2.split.sh --help
```

默认路径来自 `f/metag.conf`。支持通过环境变量 `METAG_CONFIG` 指定另一份配置；日常使用无需设置。

## 3. 保留和改变的内容

### 参考库

本版直接读取原 `lib/metacache/db/build.json` 中的实际数据库列表，并验证各分片完成记录和文件状态。不假设分片必须叫 `part0001s00001`，也不根据数字猜测数据库路径。

`1.library.sh`、参考准备、sourmash 建库、MetaCache 建库及输入分片核心保持原版。原始 FASTA 保留策略、16 GiB 全建库 cgroup 限制和完成库复用机制保持有效。

调整 `PART_COMPRESSED_GIB` 不会把已完成的 1054 个小库自动合并。本次不对已有索引进行重新分片或重建。

### 查询与合并

旧版每片输出所有参考命中 JSON，再由 Python 提取、排序、压缩并建立 SQLite。新版生产路径：

1. 验证整个 FASTQ，记录 fragments、配对顺序 SHA256 和逐 query header 指纹。
2. 在空间允许时生成仅含序列的查询 FASTA 缓存。
3. 每次加载一个已有数据库，连续查询样本。
4. 映射结果经独立管道 FD 直接送入 C++ 合并器，日志写另一个文件。
5. 按 numeric query ID 更新全局两个候选，只暂存发生改变的记录。
6. 成功验证生产者、消费者、ID 和完成计数后，提交该分片检查点。
7. 全部分片完成后统一执行 ranked LCA 分类。
8. 再顺序读取原始 FASTQ，将原始 header、sequence、quality 和 mate 配对写入物种文件。

生产路径不使用 `-refhits`、逐片 sort 或 reference-evidence SQLite，不累积 1054 份 mapping 文本。

候选规则保持固定上游语义：同一 taxon 跨分片取最大分数；保留两个不同 taxon；保留弱竞争候选；按原分片顺序处理平分；hitmin=5、hitdiff=100、最低species、最高domain。不能把这一过程改成投票、求和或 first-hit。

### 搜索范围

默认始终查询**全部**完成分片。没有默默根据 sourmash gather 排除低丰度物种或小病毒。当前发布版不提供启发式 screened 模式；它需要另行验证召回率。

可选 `--screen` 只增加现有 sourmash 样本组成报告，不改变 MetaCache 搜索范围：

```bash
bash 2.split.sh --sample Ndesert/SRR23862437 --screen
```

## 4. 文件与空间

默认配置：

```text
DIR_REF=/mnt/f/annot/metag/raw
DIR_LIB=/mnt/f/annot/metag/lib
DIR_RAW=/mnt/f/metag/raw
DIR_SPLIT=/mnt/f/metag/split
DIR_OUT=/mnt/d/analysis/metag

QUERY_BATCH_SIZE=4096
QUERY_CACHE=auto
QUERY_CACHE_GIB=100
MIN_FREE_GIB=20
```

新工作目录为：

```text
/mnt/d/analysis/metag/runs_v2/<dataset__run>/<identity>/
```

旧 `runs/` 不会自动删除、覆盖或直接作为新版检查点。旧版完成的两个查询分片默认重新查询；其保留的数据不会误当成新格式。本版复用的是全部永久参考库。

对于 N 个 fragments，核心格式为：

| 文件 | 大小 |
|---|---:|
| 全局候选状态 | 64 + 24N bytes |
| 原始 query header 指纹 | 8N bytes |
| 当前分片变化记录 | 96 + 32×发生变化的fragments bytes |
| 最终 taxid | 8N bytes |
| 查询完整性 bitmap（内存） | 约 N/8 bytes |

43,416,284 个 fragments 的候选状态约 0.97 GiB。计入 header 指纹和最坏情况下的当前 delta，查询阶段这些二进制文件约 2.59 GiB；这不包括可选序列缓存、数据库、taxonomy、日志或最终 FASTQ。

序列缓存默认上限100GiB。在同一遍读取过程中发现超限或可用空间不足时，auto模式删除本次的部分序列缓存，继续校验，回退到直接读取原始FASTQ。显式 `--query-cache fasta` 超限会报错，不静默降级。

```bash
bash 2.split.sh --sample Ndesert/SRR23862437 --query-cache none
bash 2.split.sh --sample Ndesert/SRR23862437 --cache-gib 50
```

工作盘和最终输出盘都检查最低20GiB余量。可用 `--min-free-gib` 调整，但不能把零余量视为大任务可运行的保证。查询缓存大小或策略变更会使用独立工作身份；batch size可以调整后继续已有检查点。

**样本成功完成并验证输出后，默认清理本次二进制工作文件和查询缓存，保留日志、参数、分片时间记录及最终输出。** 未完成样本的检查点保留。需要保留所有中间状态用于检查时加 `--keep-work`。

## 5. 中断与恢复

Ctrl-C 会停止本次子进程。重新执行相同命令即可恢复已提交的分片：

```bash
bash 2.split.sh --sample Ndesert/SRR23862437
```

当前分片只有在 MetaCache 与合并器都成功退出、完整行数/ID/header/physical-read summary 都正确时才成为有效结果。

更新使用只读旧状态计算 delta，再以绝对值写入。若在应用 delta 中途被杀死，恢复时可重复重放相同 delta，不会把分数加两次，也不会遗漏半个分片。

若中断发生在最终 FASTQ 写出阶段，已完成的分类检查点仍然保留，重启会重新写这个样本的暂存 FASTQ 输出；不会重新执行已提交的全部 MetaCache 查询。

匹配的完成样本自动跳过。已存在但版本不同或不完整的正式输出不会覆盖，可指定新后缀：

```bash
bash 2.split.sh --sample Ndesert/SRR23862437 --output-suffix v2
```

GPU查询失败不会自动用CPU重跑整个巨大样本。需要CPU时明确指定 `--backend cpu`。CPU与GPU后端的结果身份分开。

## 6. 正式输出

```text
/mnt/f/metag/split/Ndesert/SRR23862437/
    bacteria/<taxid>_<name>/PE.R1.fastq.gz
    bacteria/<taxid>_<name>/PE.R2.fastq.gz
    virus/...
    human/...
    animal/...
    plant/...
    fungi/...
    archaea/...
    other_eukaryote/...
    split.bad/...
    counts.tsv
    read-assignments.tsv.gz
    read-reference-hits.tsv.gz
    run-provenance.json
    split.done
```

单端输出使用 SE.fastq.gz。较高分类层级和未分类 reads 进入 split.bad，不能强行分到某个species。

read-assignments.tsv.gz 保留每个physical read的fragment编号、mate、物种/分类层级与配对分类说明。reference_status明确为not_recorded；read-reference-hits.tsv.gz只有列名，是兼容文件，不代表“没有参考命中”。

run-provenance.json 保存输入身份、实际数据库清单、分类参数、代码版本和每片耗时，随最终FASTQ保留。

启用 --screen 时另外保存 reference-matches.tsv（样本级sourmash候选）。样本级匹配不能解释为每条read的唯一来源。

组成报告：

```bash
bash metag.sh composition --sample /mnt/f/metag/split/Ndesert/SRR23862437
```

所有read fractions以全部输入reads为分母，包括未分类部分。配对fragment按2reads计数。

## 7. 验证和实际性能边界

测试脚本已从代码目录移除；本节保留历史验证范围与性能边界，不再提供依赖 `f/tests/` 的运行命令。

可选native兼容性测试需要固定上游CPU程序，通过 METAG_NATIVE_CPU 和 METAG_COMPACT_HELPER 两个环境变量启用。此次复核已经实际执行：从固定上游源码编译CPU程序，建立3个小索引，查询24个paired fragments，逐fragment与官方merge比较taxid/rank；原FASTQ与FASTA缓存候选一致；真实native程序经管道运行完整新流程，也与官方结果一致。这次oracle是官方未加refhits补丁的CPU版本；同时检查原安装补丁，普通查询的新增refhits分支默认关闭。GPU吞吐仍须本机benchmark。

另包含模拟MetaCache异常的完整CLI测试和真实C++检查点测试，覆盖非零退出、缺失/重复ID、配对错位、缓存上限、磁盘不足、首状态初始化中断、分片应用前后中断及完成输出发布后的恢复。

这不是在用户RTX5090或100GB输入上完成的吞吐测试。去掉全部参考命中和反复排序能消除大量工程开销，但完整搜索仍需读取全部数据库分片。benchmark.tsv包含加载数据库的耗时，不应直接把小样本结果线性外推为精确完成日期。
