# metag：本地 FASTQ 物种拆分

项目说明统一保存在本文件，包含主流程、安装方法及高级子模块参数；`f/` 存放实现代码。
以下命令示例均从项目根目录运行。

<a id="overview--快速开始"></a>

## 快速开始

默认流程为：**输入清单 → 参考子库/索引/审计/清理 → split 与汇总**。没有独立 FASTQ QC 步骤。
原始下载由用户先用 `download_check.py --check-only` 完成外部 MD5 校验；
`metag.sh` 假定输入可用，不重复计算 MD5，不预读 FASTQ，也不自动跑 pilot。

```bash
./metag.sh                        # 全部数据集，直接执行
./metag.sh --dry-run              # 只读展示计划
./metag.sh split                  # 同样准备必要参考，再拆分并汇总
./metag.sh prep_ref               # 只恢复/完成参考子库、索引、病毒映射和审计
./metag.sh --dat-list emp,neon --threads 16
./metag.sh --dir-fastq /mnt/f/metag/raw --dir-out /mnt/d/analysis/metag \
  --dir-annot /mnt/f/annot/kraken2_ictv
```

默认 `--dir-fastq /mnt/f/metag/raw`，`--dir-out /mnt/d/analysis/metag`，
`--dir-annot /mnt/f/annot/kraken2_ictv`。拆分 FASTQ 默认写入 raw 同级的 `split`，
即 `F:\metag\split`；可用 `--dir-split` 指定其他磁盘。`--dir-out` 保存输入清单、
完成凭据和合并汇总。默认日志在 `/mnt/d/analysis/metag/logs/`，由 `SCRIPT_LOG_DIR`
控制，启动时显示实际路径。
不传 `--dat-list` 时选择 raw 下所有非链接一级目录，以及 split 中已有有效数据集
完成标记的目录；后者允许 raw 已移走。输入目录内递归发现文件，不遍历目录链接。
原有 `prepare/pilot/full/run/align` 等高级命令仍保留，下文“高级 ENA 清单流程”只适用于它们。
旧 `qc` 子命令不再提供；旧命令行中的 `--qc-jobs`、`--qc-reads` 仅兼容接收，不执行 QC。

<a id="overview--输入清单与失败处理"></a>

## 输入清单与失败处理

只读取目录和文件元数据，核对普通文件/文件链接、非零大小、文件名角色与 mate 是否齐全。
支持 `.fastq` / `.fq` 及 gzip 版本；识别 `_1/_2`、`_R1/_R2`、`_R1_001/_R2_001`。
不带这些后缀的文件作为单端流；不能自动判断交错双端。相同相对目录和 stem 形成一个 run。
缺失 mate、重复角色、空文件、FASTQ 失效链接或对应 `.aria2`/`.tmp` 标记会立即报错。
上次清单中的未完成数据集若整对文件消失，也会报错；已完成数据集允许移走原始数据。
元数据、非 FASTQ 名称及目录链接忽略，保留原位，其变化不会导致流程退出。

**不创建 `raw.bad`，不创建 `.raw.metag.qc.lock`。拆分期间不修改原始 FASTQ；默认保留原始 FASTQ，便于数据集完成后手动移到归档盘。**
只保留输出目录的工作流锁及 split 输出锁，避免并行写入同一结果。
输入清单写入 `inputs/files.tsv`，不填写未经实际读取的 reads 数，不声称已完成 FASTQ 内容验证。
参考完成并通过审计后写入 `inputs/ready.done`，记录 `external_md5_assumed`、输入元数据和参考身份。
历史 `qc/` 文件不删除、不作为本次内容校验结果；首次迁移只利用其中的文件路径发现缺失输入。

split 在实际读取时核对 gzip/CRC、四行记录、非空序列、序列与质量字符、mate ID、
Kraken2 输出的 ID/长度/条数。发现损坏、缺失或不一致就停止，错误包含输入文件路径，
不跳过坏记录、不隔离原文件、不发布失败样本的 `split.done`。失败现场保留在该样本的
`.partial/`，包含 `FAILED.json` 和分类器日志；修复输入后重提原命令。
参考库由独立的 NCBI FASTA 构建，不使用 raw FASTQ；替换 raw 文件不会改变参考 library。

屏幕只显示模块/数据集开始、结束、复用和诊断；逐 run、下载和 split.bad 详情保存在完整日志。
同一警告去重；参考 taxonomy、各 library、build、audit 分别显示 START/DONE/SKIP/FAIL。

<a id="overview--默认完整双端分类"></a>

## 默认完整双端分类

输入清单准备后恢复/审计参考库，再按数据集顺序拆分。每个数据集默认并行处理 4 个样本，
总共分配 16 个 Kraken2 分类线程，每个样本 4 个；另有 Python 分流和解压开销。
并行拆分自动启用 `--memory-mapping` 共享数据库文件页。FASTQ 用 gzip level 1 压缩，
读写采用 MiB 级缓冲；工作流整体内存上限仍为 36 GiB。
默认不写逐 read assignments 表，保留全部分流 FASTQ、Kraken report、计数表和汇总。

```bash
./metag.sh
./metag.sh --split-jobs 4 --threads 16
./metag.sh --classification-mode full          # 默认：完整检查双端序列
./metag.sh --classification-mode quick         # 可选：提前结束的快速筛查
./metag.sh --keep-assignments                   # 需要逐 read 分配表时启用
./metag.sh --split-jobs 1 --threads 16           # 磁盘争用严重时减少并发
```

默认 `--classification-mode full` 不启用 Kraken2 `--quick`，完整搜索 R1 和 R2，
汇总双端证据后给整个片段一个分类结果；仍保持配对，split 不抽样丢弃 reads。
分类支持度阈值为 `--confidence 0.1`，最少命中组数为 3。完整搜索仍可能错分或漏分，
只定位到属/科等而没有物种祖先的结果保留到 `split.bad`，不强行指定物种。
显式选择 `--classification-mode quick` 才提前结束检索，可能只检查第一端的部分序列；
该模式的支持度和 minimizer 统计仅基于已搜索部分，适合快速候选筛查。
参见 [Kraken2 分类说明](https://github.com/DerrickWood/kraken2/wiki/Manual#classification)。
目前使用 CPU 多进程/OpenMP，没有 GPU 依赖或 GPU 开关。

<a id="overview--split-与后续汇总"></a>

## split 与后续汇总

默认保留所有输入 reads，不做 fastp 剪切。Kraken2 参数默认
`--confidence 0.1 --minimum-hit-groups 3`，默认 full 完整搜索双端；
显式选择 `--classification-mode quick` 才添加 `--quick`；支持 `--memory-mapping`。
沿用原有分类器输出与每条 FASTQ 的 ID、长度及记录数量核对；双端作为 fragment
共同分流。多线程要求已验证输出顺序的 Kraken2 2.17.1；其他版本使用 `--threads 1`。

默认目录布局：

```text
D:/analysis/metag/
  inputs/                             # 待处理输入清单与参考准备完成凭据
  logs/                               # 完整运行日志
  summary/                            # 当前选择集合的合并汇总
F:/metag/split/<dataset>/<short-run>/
  species/<group>/<taxid>/       # 达到 species 级别的 FASTQ
  split.bad/<group>/<taxid>/...               # 未分类或没有 species 级归属的 FASTQ
  *.kreport, *.log                     # assignments.tsv.gz 需 --keep-assignments
  input.json, counts.tsv, split.done
F:/metag/split/<dataset>/split.done   # 整个数据集已完成，允许清理已处理 raw
F:/metag/split/<dataset>/raw.cleanup.json  # 最近一次 raw 自动清理摘要
F:/metag/split/<dataset>/raw_cleanup/      # 逐次清理计划、事件和状态
F:/metag/split/<dataset>/summary/
  species_by_run.tsv                  # 含 split.bad 行及 destination 字段
  virus_by_run.tsv                    # 病毒 DNA/RNA/unknown 分类
  summary.tsv, summary.svg            # 分类 reads 数图表
F:/metag/split/split.done             # 当前所选集合全部完成
```

每个数据集的所有 run 完成后，校验输入和输出，写好汇总及**数据集级** `split.done`，
默认保留原始 FASTQ，然后开始下一个数据集；此时可手动把对应 raw 移到归档盘。
只有显式启用自动清理时，才删除该数据集清单中的原始 FASTQ。运行级 `split.done` 或
`.partial` 不能触发整个数据集的 raw 删除。默认按数据集名称排序；`--dat-list neon,emp,...` 可指定顺序。

项目根目录 `metag.conf` 提供开关：

```ini
[split]
delete_raw_after_split = FALSE
```

默认 `FALSE` 保留原始 FASTQ；如需自动删除，再改为 `TRUE`，**下次启动流程时生效**。修改此配置不会使已有 split 签名失效。
也可单次启用：`./metag.sh --delete-raw-after-split TRUE`。该选项不改变分类或输出内容。
`--dry-run` 只显示清理策略，不删除文件。

清理前重新验证数据集及每个 run 的完成标记、输出文件身份和输入清单，并把输出、完成标记、清理
计划同步落盘；不额外全量读取 FASTQ 做 MD5。只删除完成清单中的 `.fastq` / `.fq` 及其 `.gz`
文件，保留目录、下载 URL/MD5 清单、说明文件和其他数据。文件链接只删除链接本身，保留目标；
目录链接、变化的输入、未完成下载标记、损坏输出均拒绝清理。记录在数据集的 `raw_cleanup/`
以及 `raw.cleanup.json`，记录字节数是删除条目的逻辑大小，不保证硬链接情形下的物理释放量。

启用自动清理时，屏幕显示 `DONE raw cleanup dataset=...` 后继续下一数据集。若删除过程失败或中断，已经完成的
split 仍保留，下次校验输出后继续清理剩余 raw，不重新拆分；设为 FALSE 则保留剩余 raw。
此前关闭开关时完成的数据集，下次开启后也会在复用校验通过后清理原始文件。

成功拆分满足记录守恒：参与该数据集拆分的原始 FASTQ 记录 = 所有 `species/` 记录 + 所有
`split.bad/` 记录；每条记录恰好写入一处，双端共同分流，read 名称、序列、质量及四行内容原样保留。
当前默认流程不剪切、不做质量过滤、不抽样丢 reads。按物种分组会改变跨分组的原始顺序，并重新 gzip
压缩，因此压缩文件的字节、大小及 MD5 不等于原始下载。后续基于 reads 的分析可以使用这些输出；
请保留整个 split 数据集目录（含 `input.json`、计数、汇总、配对文件及各级 `split.done`），
不是只保留某些物种 FASTQ。原始压缩文件逐字节/原始顺序的恢复仍需要原文件或重新下载。

下一数据集开始前比较可用空间与未完成输入的压缩体积；空间明显不足时停止并说明，
默认保留 raw，可及时把已完成数据集的 raw 移到归档盘；空间不足停止后重跑会复用已完成结果。
该检查只是粗略下限，gzip level 1 拆分输出可能更大。仍需容纳当前一个数据集的 raw 和拆分输出；
自动清理不会在一个数据集尚未全部成功时删除其原始文件。

直接以 SRR/ERR/DRR 命名的平铺样本保持 accession 目录名；其他样本只取末级名称
（最多 40 个字符）及 12 位来源哈希，不把输入目录层级拼进输出路径。物种目录只用 taxid，
完整学名、原始 bucket 和来源路径在 TSV/input.json 中保留；计数表的 `relative_dir`
给出该 run 下实际的短路径。

`split.bad` 是可继续研究的未解析 reads，不代表坏 FASTQ；执行失败不会把原始
数据放进去。每个数据集和 run 独立存储，不合并生物样本；物种标签是分类候选，
统计 reads 数不能直接解释为生物量。后续默认只做汇总，保留原有 `align` 作人工
选择候选物种后的可选验证步骤。

<a id="overview--续跑与变更"></a>

## 续跑与变更

每次运行重新核对文件清单和配对，仅访问文件元数据。参考准备及 split 前后只比较本次
清单中的 FASTQ 大小、纳秒修改时间及链接目标；忽略文件的变化不参与比较。
参与分析的 FASTQ 若在运行中修改或缺失，会停止并报错；本次清单形成后新增的 FASTQ
留待下次运行发现。重提时不依赖旧 QC 完成标记，也不会重新预读 FASTQ。
没有逐次重算大 FASTQ 的内容哈希，因此请勿人为保留修改时间来替换数据。
每个 run 的 `split.done` 还记录参考、参数、工具版本和输出状态；重跑时检查后跳过。
未完成数据集中的新增 run 可以继续处理；已经完成的数据集不再追加新输入。
已经完成的 run 若输入/参数/参考发生变化，要求新的
`--dir-split`，不覆盖已有结果。修改分析代码也会使旧 split 结果签名失效；只改变线程数、并发数或
内存映射或 `metag.conf` 中的 raw 清理开关不会使已完成的 split 失效。`--keep-assignments` 会改变输出，因此参与签名。
完成标记和数据在同一个暂存目录中写好后一起原子发布。每个样本只使用一个固定的
`<short-run>.partial` 暂存目录；中断后保留错误现场，重跑时校验本程序的来源标记后
清理该未完成目录并重建，不累积随机名字的临时目录。正式结果和原始 FASTQ 不受此清理影响。

中断的拆分留在带 `.partial` 的目录，含失败日志；下次从未完成 run 重新处理，
不会续接半截 gzip。已完成 run 会复用。顶层 split.done 只声明当前选择集合完成，
仍逐 run 检查，不凭空标记跳过。数据集完成标记保存原始清单、分类配置、
run 完成标记及汇总的文件状态；raw 移走后仍会校验输出并复用，保留它的汇总。
若剩余 raw 新增或改变 FASTQ、已完成输出缺失或被修改，则停止并报告；忽略文件不参与比较。
汇总仅包含当前选择的数据集。
systemd 用户 scope 的 30/36 GiB 内存阈值与 4 GiB swap 限制继续生效。


<a id="overview--默认入口参数与资源"></a>

## 默认入口参数与资源

| 参数 | 默认值 / 含义 |
| --- | --- |
| `--dir-fastq` | `/mnt/f/metag/raw`；数据集目录的父目录 |
| `--dir-out` | `/mnt/d/analysis/metag`；输入清单、完成凭据和合并汇总 |
| `--dir-split` | raw 同级的 `split`，默认 `/mnt/f/metag/split`；拆分 FASTQ、逐数据集汇总和完成标记 |
| `--dir-annot` | `/mnt/f/annot/kraken2_ictv`；共享参考根目录 |
| `--dat-list` | 不指定时按名称处理所有非链接一级目录并复用已完成数据集；显式指定时按逗号列表顺序处理 |
| `--threads` | 16；建库线程 / 所有 split 样本合计的 Kraken2 分类线程预算 |
| `--split-jobs` | 4；同时拆分的样本数，不超过分类线程预算 |
| `--keep-assignments` | 默认关闭；开启逐 read 分配表 |
| `--delete-raw-after-split TRUE/FALSE` | 覆盖 `metag.conf`；默认 FALSE，保留 raw；显式 TRUE 时在数据集成功并校验后删除已处理 raw FASTQ |
| `--download-threads` | 8；参考准备下载线程 |
| `--mask-jobs` | 2；同时进行 taxid/masking 的基因组数，与下载并发分开 |
| `--masker-threads` | 1；每个 k2mask 的线程数；总 masking 线程不超过 `--threads` |
| `--prepare-memory-gb` | 12；下载/masking scope 的 RAM 硬上限 GiB，另有 1 GiB swap 上限 |
| `--max-db-gb` | 24；hash 表上限 GiB，恢复时须与冻结配置一致 |
| `--classification-mode` | full；完整搜索双端序列，quick 为可选的提前结束筛查 |
| `--confidence` | 0.1；Kraken2 分类置信阈值 |
| `--hit-groups` | 3；Kraken2 最少命中组数；quick 模式至少为 2 |
| `--memory-mapping` | 单任务时可选；多个 split 任务时自动开启 |
| `--dry-run` | 只读展示计划 |

直接执行无需 `--execute`。需要可用的 `systemctl --user`，否则资源 scope 创建失败后停止。
hash 表上限不同于实际内存限制，也不限制参考下载和临时文件的磁盘占用。
预处理使用独立 scope，默认 MemoryHigh 为 10.8 GiB、MemoryMax 为 12 GiB；
正式索引构建和 split 保持原有 30/36 GiB 阈值与 4 GiB swap 限制。
预处理 scope 绑定外层工作流的生命周期；取消工作流时也结束其预处理子任务。
单独 `build-db` 同样限制预处理内存，但正式建索引仍应通过统一入口或由调用方配置资源限制。

```bash
./metag.sh --dry-run
./metag.sh                              # 分批预处理、24 GiB 索引、full split
./metag.sh prep_ref --mask-jobs 1 --prepare-memory-gb 8
```

减小并发主要降低内存峰值；在 CPU 未饱和时也可能延长 masking 时间。
不合并参考 FASTA 可省去全部新处理参考的一次读取、一次写入和一份磁盘副本，
但容量估算和正式建索引仍各需扫描全部参考，不能承诺所有阶段均加速。
保留全部物种、当前冻结参考选择、低复杂度屏蔽、k/minimizer 参数和 24 GiB hash 上限；
不按物种分别分类后拼接结果，共有序列仍由统一索引计算跨物种 LCA。
24 GiB hash 的正式构建无法仅靠预处理分批压到 16 GiB RAM。

<a id="overview--环境与入口说明"></a>

## 环境与入口说明

入口通过 `f/conda_env.sh` 自动查找 Anaconda、Miniforge 或 Miniconda，并激活其 `metag` 环境，
Python 和 fastp、Kraken2 等工具均从该环境加载；激活仅影响脚本及其子进程。
可用 `METAG_PYTHON` 或 `PYTHON_BIN` 显式指定解释器。帮助页无需激活环境即可显示。
`f/conda_env.sh` 是供入口脚本加载的共享函数库；可用 `bash f/conda_env.sh --help` 查看说明。
入口可从其他目录用绝对路径调用；输入、输出相对路径以调用目录为准。
不带参数时执行默认全流程；`--help` 显示帮助。入口关闭 Python 字节码缓存，代码目录不会因此生成 `__pycache__/`。

依赖 `openpyxl` 解析 ICTV XLSX。分类、分流和汇总不联网。
Kraken2 2.17.1 的源码使用有序输出队列；多线程模式限定该已核对版本。
其他版本须先使用 `--threads 1`，完成顺序兼容验证后再扩展版本支持。
保留每条 read 的 ID、长度、C/U、taxid 和配对检查；不以删除检查解决软件不兼容。
<a id="overview--安装与迁移"></a>

## 安装与迁移

```text
用法：./install.sh [options]
  默认                 安装/检查固定版本的 metag 环境，不下载参考或运行全量分析
  --prepare            另行下载/建立共享参考、ICTV 映射并审计
  --datasets CSV       与 --prepare 配合，整理指定已下载数据集的 metadata/raw
```

<a id="overview--冻结病毒基因组映射"></a>

## 冻结病毒基因组映射

先确定实际 Kraken2 库，保留它建库时的 `taxonomy/nodes.dmp`、`names.dmp`，以及已有的
`merged.dmp`、`delnodes.dmp`。不能拿新版 taxonomy 覆盖旧库。

支持离线本地 XLSX、包含 `Species / Genome composition / GenBank accession` 的 TSV；
实际 ICTV 文件中的 `Genome` 列也支持，按工作表与表头定位，不写死列号。
只解析正式 accession，多个片段归并到同库物种；不同片段指向不同物种时记录一对多异常。

交叉表支持 `accession + taxid`、NCBI `accession.version + taxid`，或以 seqid/taxid 开头的 seqid2taxid.map（可含附加来源列）。
构建器优先检查实际存在的库内 `seqid2taxid.map`、`taxonomy/seqid2taxid.map`、`accession_taxid.tsv`；
多个候选时要求显式指定。按 VMR 需要的 accession 流式过滤本地大表。
显式版本号不自动替换为其他版本。
无交叉表时仅允许**唯一且严格匹配**同库科学名/官方同义名，方法记入审计，不做模糊匹配。
可用 `virus cache-accessions` 单独批量获取 VMR 所需 accession 的 NCBI 交叉引用。

每批最多 100 个，限速、重试、保存带哈希的原始响应，支持中断续跑。
接口出错、访问限制或返回非预期 schema 时停止；不把错误页面当映射。
`mol-type` 只描述序列记录，绝不作为病毒基因组类型。

每个新的映射目录包含：

```text
virus_genome_types.sqlite / virus_genome_types.tsv
virus_metadata.source.json / virus_metadata.build.json
virus_metadata.evidence.tsv / virus_metadata.conflicts.tsv
virus_metadata.unmatched.tsv / virus_metadata.unknown_labels.tsv
```

记录源版本、URL/本地来源、原文件 SHA256、交叉表/规则/override 哈希、代码规则版本和 taxonomy 身份。
读入时校验内容与来源；同一运行中的映射不可变，内容变化即停止。构建拒绝覆盖已有目录。
同库 taxonomy 缓存位于 `.metag_taxonomy/<内容身份>.sqlite`，加锁构建、原子发布，不热更新旧缓存。

可选 `--rules rules.tsv` 和 `--overrides overrides.tsv`：

```text
taxid  evidence_scope  genome_composition_raw  source_ref  source_version  reason  review_date
```

文件为制表符分隔；scope 为 taxon/species/subtree，review_date 为 YYYY-MM-DD。
subtree 必须有权威的全分支适用依据，不能用数据库碰巧包含的几个后代推断。
override 是明确审核结论，保留被覆盖证据；祖先 override 不自动抹掉更具体的冲突。
这些表必须填写适用于实际数据库的已审核证据，不将合成示例用于正式分析。

<a id="overview--数据库覆盖与执行"></a>

## 数据库覆盖与执行

`db-audit` 使用实际 `kraken2-inspect` 的 direct minimizers，每个节点只计一次；不能按 VMR/taxonomy 中存在物种就声称库覆盖它。
`metag.coverage.tsv` 保留七大基础类；`metag.virus_coverage.tsv` 给出 DNA/RNA/unknown、节点、物种、比例与分母。
必须满足基础 virus direct minimizers = 三类之和。未知节点不是必须存在的覆盖条件。
默认要求 DNA 和 RNA 都有实际支持；`--allow-incomplete-virus` 为显式探索选项，run 时也须提供并记录不足。
元数据未注释与无相应参考支持分别记录。七大类不足另由 `--allow-incomplete-db` 控制，不能替代病毒类型检查。
`db-audit --base-only` 仅用于新建库的基础检查，**不能据此启动 v2 run**。

已有索引优先复用。`./metag.sh build-db --dir-db "$DB"` 默认仅打印计划；已有完整索引时仅准备审计，不重建 hash。
新建库需要显式 `--execute`，并使用新目录；含 archaeal/bacterial/viral/human/fungal/plant/protozoal/vertebrate/invertebrate/UniVec 参考。

```bash
./metag.sh build-db --dir-db /path/to/NEW/database --threads 16 --max-db-gb 24
# 确认计划后加 --execute；已有兼容的冻结病毒映射时可加 --virus-map FILE。
```

`--max-db-gb 0` 关闭 hash 表容量上限，内存需求可能很大。`--virus-map` 指向与数据库
taxonomy 兼容的冻结 `virus_genome_types.sqlite`。脊椎动物和无脊椎动物参考下载使用
k2 2.17.1；不能替换为旧版 `kraken2-build --download-library` 接口。

参考下载通过 `f/k2_compat.py` 调用固定版本的 `k2 download-*`，修正 NCBI 路径尾部斜杠、404 空文件和并行错误传播；断线重试有次数限制，新下载文件核对 NCBI MD5。
建库的 `--resume` 复用已在外部完成校验的非空参考文件，不再逐文件读取并计算 MD5；缺失、空文件或带 `.tmp` / `.aria2` 标记的文件仍交给下载器检查和补下载。
类别完成断点为 `metag_build_state/<类别>.complete`。新处理的基因组还各自保存
`*_genomic.fna.metag.json`，只有 k2mask 成功退出、FASTA 与映射均有效后才发布。
收据记录来源文件身份、taxid、masker 指纹和产物身份；中断后重跑只处理未完成或产物失效的基因组。
来源/屏蔽参数改变会拒绝混用，需另建数据库；更改并发数不使完成收据失效。
首次处理时冻结 assembly summary，恢复时不从 NCBI 的更新清单引入不同参考。
默认 2 个基因组并发、每个 masker 1 线程，沿用完整序列屏蔽，不切断染色体以改变边界结果。
各基因组独立生成小型 prelim 映射；类别结束后只合并映射，发布 `library.inputs.json`，
不创建新的 `library.fna`。每个基因组完成及至少每分钟的等待进度写入建库日志。

索引读取冻结类别配置和 `library.inputs.json` 中校验通过的基因组文件；顺序保持旧版
合并时的基因组排序。旧版已经完成的类别直接复用其 `library.fna`，同一类别绝不同时
读合并文件及其基因组副本。UniVec_Core 保留原有小文件处理方式。
容量估算和索引构建各读取一次这些输入，仍只构建一个全局 Kraken2 数据库。
容量扫描现在经 `f/index_capacity.py` 执行，缓存仅在估算程序指纹、全部参数、
输入顺序及每个文件的大小/修改时间完全匹配时复用。`--precompute` 可提前顺序读取
已完成的类别，并等待后续类别完成；不会用部分数据外推容量，也不会相加不同类别的估算。
正式构建仍使用原始估算值、24 GiB 上限和确定性算法。缓存缺失或失效时执行原样扫描。

`f/reference_accelerate.py` 是针对现有分批进程的辅助加速入口：先验证原 PID、
scope、冻结选择和已完成记录，再冻结原 scope，保留正在运行的 Python/masker 内存状态。
辅助进程只处理原调度器有界窗口之外、尚无产物的基因组，使用相同的单线程 masker
和逐基因组完成记录；原进程恢复后按原顺序复用这些记录并生成最终类别清单。
辅助进程应在独立的受限用户服务中运行，并设置 `ExecStopPost=systemctl --user thaw <原scope>`，
以便异常终止后恢复原进程；代码也在正常完成和可捕获异常时自动恢复。
它会暂时停止原终端的 BATCH 更新，辅助日志记录实际进度。停止辅助服务即可恢复原流程。
并行数为上限，调度器还根据源文件大小控制估计内存用量；仍须为服务设置硬内存上限。
`f/index_inputs.py` 校验 Kraken2 2.17.1 脚本指纹后，在临时目录生成私有构建入口；
共享 Conda 脚本、正在运行任务的入口及参考内容均不因此修改，普通 Kraken2 库保留原行为。

切换版本前先结束同一参考目录的旧工作流和接续任务，确认没有建库进程仍持锁；不要删除锁文件。
新版可以复用旧版完整类别。旧版未完成类别的单个 FASTA 没有完成收据，不能仅凭文件存在
认定成功，需要重新 masking；若旧版已进入大型索引阶段，保留现有计算通常更划算。
使用分批布局后应继续使用新版入口，不应再用旧入口恢复同一未完成数据库。
内存不足失败时已经完成的收据仍保留，可降低 `--mask-jobs` 后续跑；单个超大基因组
仍无法完成时，显式提高 `--prepare-memory-gb`，程序不会偷偷跳过物种或取消 masking。
若索引构建阶段已留下不完整的 `.k2d`，
重跑会拒绝自动覆盖，需先检查这些产物。
已有文件的批量 MD5 校验独立执行，不加入 `metag.sh`。当前参考目录已提供独立脚本（清单路径相对于参考根目录）：

```bash
/mnt/f/annot/kraken2_ictv/check_md5.sh
# 可选：只检查某一类
/mnt/f/annot/kraken2_ictv/check_md5.sh plants
```

默认检查五份清单；屏幕显示类别开始、结束、错误和每分钟最多一次的文件计数进度。
完整逐文件结果保存到 `0.metadata/md5-check.<时间>.<PID>.log`；全部通过返回 0，缺失、校验不符或清单格式错误返回非零。

需要检查并尝试修复时，可独立使用 `/mnt/d/scripts/download_check.py`；它支持这些 aria2 清单的 `dir=` 子目录布局：

```bash
(
  for group in microbes viruses plants vertebrates invertebrates; do
    python3 /mnt/d/scripts/download_check.py \
      --dir /mnt/f/annot/kraken2_ictv --folder "$group" --url "0.url/$group.url" || exit "$?"
  done
)
```

默认下载缺失文件，并尝试修补可定位的 `ConnectionClosedException` 错误文本；修补后必须完整 MD5 通过。
屏幕只显示目录进度和问题文件，不逐文件打印 OK；完整逐文件结果仍保存在 `.download_check.jsonl`。
普通损坏、截断或版本不同不会自动重下覆盖已有文件，而是实时写入对应的 `.download_check.fail.txt`
（路径、原因、下载 URL），并保留兼容的 `.download_check.fail.tsv`。已通过复核的失败项会从问题报告移除。
完整检查也会报告已列文件旁的清单外疑似重复下载副本（如 `.fastq.1.gz`），标为未校验，留待人工确认；
不因名字相似就删除或判定损坏。有失败或此类副本时返回非零。
加 `--check-only` 只检查；加 `--failed-log 0.metadata/md5-check.<时间>.<PID>.log` 只复核该日志中已发现的失败项，不代表整批数据已检查完成。
NCBI 更新源文件后，旧 MD5 清单可能过时；应先核对官方 `md5checksums.txt` 并保存旧清单及依据，不能用本地计算值直接覆盖预期值。

校验清单支持含空格的文件名，并检查 MD5 格式；异常响应按次数重试，不能作为有效校验结果使用。
每个参考类别必须产生非空 FASTA 和映射文件，才标记完成。
索引构建使用 `kraken2-build --build`，规避 k2 2.17.1 的容量上限及失败返回码问题。
构建后检查三个索引文件再标记完成。
单独 build-db 和统一入口的默认 hash 上限均为 24 GiB，与当前冻结建库配置一致。
该上限不限制参考下载、全部磁盘或实际内存，且下采样会降低敏感性。
保留 taxonomy、建库来源与审计；不要运行会删 taxonomy 的 clean。

<a id="overview--建库后的自动清理"></a>

### 建库后的自动清理

统一入口、`prep_ref` 和 `install.sh --prepare` 在建库完成、七大基础类及病毒 DNA/RNA
覆盖审计全部通过后，自动执行 `reference-clean --execute`。单独 `build-db --execute`
提供 `--virus-map` 时也会在完整审计后清理；只有基础审计时保留文件，等完整参考准备完成。
导入的非 metag 管理数据库自动跳过清理。

清理范围仅限已配置子库的 `library/<类别>/library.fna`、`library/<类别>/genomes/` 下的
`*_genomic.fna` / `*_genomic.fna.gz`，以及共享参考根目录对应类别中的 `*_genomic.fna.gz`。
原始参考压缩文件也会删除；将来重建按保留的来源清单重新下载。不会匹配 `.fastq.gz` / `.fq.gz`，
参考清理模块不会访问 `F:\metag\raw` 或 split 输出。原始样本 FASTQ 由独立的 split 完成后清理模块
按 `delete_raw_after_split` 配置处理，默认 FALSE，保留 raw 供手动归档；参考建库完成不能触发样本 FASTQ 删除。

保留三个 `.k2d` 索引、原版 `taxonomy/`、`.metag_taxonomy/`、冻结病毒映射、ICTV/accession
来源、`0.url/` 下载及 MD5 清单、assembly/manifest/prelim/seqid 映射、冻结选择、建库完成标记、

删除前核对建库完成标记、索引/taxonomy 审计身份、病毒映射及 inspect 校验值；取得建库与审计锁，
拒绝未完成下载、符号链接及规划后发生变化的文件。每次清理先落盘逐文件计划，再记录删除结果。
记录位于库内 `metag_cleanup/*.plan.jsonl`、`*.events.jsonl`、`*.summary.json`；最近一次
成功摘要为 `metag.cleanup.json`，包含文件数、字节数和审计身份。中断保留现场，重跑仅清理剩余文件。

<a id="overview--高级-ena-清单流程prepare--pilot--full--run"></a>

## 高级 ENA 清单流程（prepare / pilot / full / run）

本节描述保留的高级模块，不是默认本地拆分流程。只有显式使用这些命令时，
才涉及 ENA 元数据、raw 软链接、fastp、`results_v2`、`done.json` 及旧版汇总表。
默认本地流程的输出路径和标记以前文为准，不要求 ENA 项目登记。

`prepare/pilot/full` 的数据集名须在 `f/datasets.example.tsv` 登记；默认父目录
仍为 `/mnt/f/metag`。若用于现在的 raw 布局，须显式指定 `--dir-data-root /mnt/f/metag/raw`，
并先确认清单与链接路径。`--check-md5` 仅为旧 pilot/full 模块的可选参数，默认入口不接受它。
清单同步在临时目录检查后发布，变更前备份到 `metadata.before-sync.*`；保留人工字段和 include。
旧 run 消失或布局变化会停止，`prepare --refresh` 会重建清单，不能用于常规同步。

<a id="overview--full-参数与先决条件"></a>

### full 参数与先决条件

```bash
# 批量形式
./metag.sh full emp,Weurope --dir-db DIR --virus-map FILE
# 单目录形式
./metag.sh full --dir-db DIR --virus-map FILE --dir-root DIR --dir-out DIR --threads 16
```

单目录形式默认输入为 `/mnt/f/metag/ocean`，输出为输入目录下的 `results_v2`。
不带 `--execute` 只打印计划；加上后依次审计、检查清单、分类、汇总。
执行前需准备好环境、数据库、病毒映射，并完成 `manifest` 和 `organize`。
清单中有 `valid=no`（文件缺失、存在 `.aria2` 等）时，先完成下载并更新清单。
默认依赖流程外已完成的 FASTQ MD5 校验；需要重新完整校验时加 `--check-md5`。

<a id="overview--清单raw-与校验"></a>

### 清单、raw 与校验

`manifest` 只扫描根目录和 `raw/`，检查 ENA 文件数组、大小、缺 mate 和 `.aria2`。
ENA 返回 HTTP 200 也可能包含服务端错误。程序会检查整张表的必要列、run 编号和行完整性，
拒绝错误或截断响应并重试，校验通过后才写入 ENA 缓存；`--ena-tsv` 同样检查表格。
网络错误反复出现时可改用完整的本地 ENA 报告。清单中的 `valid=no` 表示文件缺失、
大小不符或仍有 `.aria2` 等待处理项，详见 `metadata/inventory.audit.json`。
其 `samples.tsv` 保留 sample → run 两层，`files.tsv` 记录原路径、raw 路径和 ENA MD5。
同一样本的多个 runs 不自动合并。缺 `_2` 不能把 `_1` 当单端；额外无后缀文件保留为 `ARCHIVE_SINGLE`。
单文件但元数据为 PAIRED 时需审核 merged/interleaved，不能直接当原始单端。

`organize` 默认软链接，不修改原 FASTQ；软链接依赖原文件，不能随后删除原件。
首次也可选择 `--mode hardlink` 或同文件系统的 `--mode move`，搬移后保留操作收据。
MD5 必须完整读取压缩文件；`--gzip` 另做全解压与四行 FASTQ 检查。存在/大小匹配不能代替 MD5。
不要对人工整理后的清单使用 `manifest --refresh` 来做元数据升级。

<a id="overview--非破坏性元数据升级"></a>

### 非破坏性元数据升级

升级先创建 `samples.before_v2.<时间>.<唯一值>.tsv`，追加缺失列，初始值 `unknown`。
逐字段变更和冲突分别记录于 `metadata_upgrade.*.changes.tsv`、`*.conflicts.tsv`。
保留人工值、额外自定义列、include/valid、sample_key 和路径。更新表不允许修改这些控制字段。
非空旧值与新值不同会进入待审表，不覆盖。更新表必须有 `metadata_evidence` 和
`metadata_review_status=reviewed/provisional`。既有值要更正时，先人工审阅冲突再明确编辑原清单。

新增列：

```text
input_nucleic_acid   DNA / RNA / total_nucleic_acid / unknown
library_method      shotgun / capture / amplicon / unknown
reverse_transcription, dna_retained, virus_enriched, is_control   yes / no / unknown
processing_protocol, metadata_evidence
metadata_review_status   reviewed / provisional / unknown
```

保留 assay_class、ENA 原字段、human_read_masking、pooling、source_matrix 等。
新建 ocean WGS 清单仅根据原 README 初填 DNA/shotgun，标记 provisional 并记录依据。
CASPER 不统一推定纯 RNA、去 DNA 或总核酸；RNA-Seq 标签不能代替 run 级实验协议。
这些字段只用于解释和分层，**不参与病毒路由**。

<a id="overview--类型分类层级与输出"></a>

### 类型、分类层级与输出

- dsDNA/ssDNA/dsDNA-RT → DNA；dsRNA/ssRNA/ssRNA-RT → RNA。
- Hepadnaviridae 是 DNA；Retroviridae 是 RNA。复制中间体/前病毒的分子类型不改变该规则。
- Riboviria/Viruses 等混合高层节点默认 unknown；缺失、新标签、未解决冲突均保留 unknown。
- 菌株允许继承物种；属/科仅可继承有来源的全分支规则，目录仍 `_unresolved/实际节点`。
- 病毒宿主为人/动物/植物时，病毒仍在病毒分支。viroid/satellite 等实体仅沿实际 taxonomy，entity_type 无依据则 unknown。

```text
ROOT/raw/<sample_key>/<run>/<原始文件名>
OUT/human|animal|plant|fungi|bacteria|archaea/<sample_key>/<run>/<species>/
OUT/virus_DNA|virus_RNA|virus_unknown/<sample_key>/<run>/<species 或 _unresolved/taxid_name>/
OUT/other_eukaryote|ambiguous|technical|other|unclassified/...
OUT/reports/<run>/
OUT/summary/
```

默认 OUT=`ROOT/results_v2`。不再生成聚合 `virus/` 或重复数据软链接。
非病毒语义沿用原版：human 优先于非人动物；plant 是 Viridiplantae；无法排除人的 Metazoa 等高层结果为 ambiguous。
物种目录始终依据同库 NCBI species，不把属/科结果提升为物种。
保留 PE.R1/PE.R2、QC_U1、QC_U2、ARCHIVE_SINGLE 流；PE 以 fragment 联合分配，两端同路由。

<a id="overview--汇总断点与解释"></a>

### 汇总、断点与解释

只看粗略大类时，使用 `groups_by_run.tsv`；病毒 DNA/RNA 类型另见 `virus_genome_by_run.tsv`。

`assignments.tsv.gz` 保留原列并追加 canonical_taxid、base_group、病毒类型、状态和 evidence_taxid。
详细证据在 taxid 级表，读数量不会导致全量 ID 缓存或反复扫描 FASTQ。
GzipBins 保留有限缓冲/句柄以及合法的拼接 gzip members。

- `species_by_run.tsv` 兼容原视图，历史语义包括 `_unresolved` 行。
- `groups_by_run.tsv`：互斥组计数；`qc_by_run.tsv`：QC 与守恒。
- `virus_taxa_by_run.tsv`：所有病毒 assigned taxid，包括属/科/unknown。
- `virus_species_by_run.tsv`：仅 species_taxid>0，按 run/species/group/stream 聚合。
- `virus_genome_by_run.tsv`：每个 run 的 DNA/RNA/unknown，含零计数和未知比例。
- `virus_annotation_audit.tsv`：使用的节点、来源、继承、冲突、缺失。

这些是不同视图，不能再次相加。分节段或不同 assigned 节点不能重复计为新物种。
所有视图包含 schema 和映射身份。汇总只使用有 done.json 的完整结果与每个 run 的 input.json 元数据快照，
检查签名、报告校验和、计数，并拒绝 v1/v2 或不同映射混合。

```text
raw_reads_processed = clean_reads + qc_failed_reads
clean_reads = 所有互斥输出组 reads 之和
virus_all_reads/fragments = virus_DNA + virus_RNA + virus_unknown
PE: reads=2*fragments；单端/孤立 mate: reads=fragments
```

空分母写 NA。未知 read 比例与节点比例分开。每百万 clean reads 不是颗粒、细胞、活性或绝对浓度。
普通 DNA、RNA、总核酸、病毒富集、捕获、扩增子、对照不可无分层比较。
DNA 文库未检出 RNA 病毒不能直接称为阴性；mask 人源后的零计数也不能证明原样本无人源。
候选分类不等于 confirmed species、感染或完整活病毒；必要时用 `./metag.sh align` 做独立竞争比对与覆盖核查。

旧 virus/、旧 schema、输入/参数/脚本/映射变化均要求新的 OUT；同路径换映射内容也会失效。
缺少 done.json 的部分结果不汇总、不覆盖。完成前检查全部输出，done 最后写入。
跨类别提交不是单一文件系统事务；中断产生的文件须按 input/FAILED 收据人工核查，不盲目清理。
原 raw 不删除、不重新编码、不先去人源。
