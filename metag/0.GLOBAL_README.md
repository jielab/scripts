# 全局 Kraken 2 路线：解决每个样本反复扫描 1,054 个分区的结构性开销

## 默认一条命令运行全部模块

```bash
cd /mnt/d/scripts/metag
sleep 2h && ./3.global.sh --dat-list changj,Ndesert,Wxiamen
```

不写模块名等价于 `all`，顺序为 `install → plan → build → benchmark → split`。
`benchmark` 自动使用所选样本中的第一个，默认测试前 100 万个片段；随后 `split`
按所选数据集顺序逐样本处理全部样本（包含第一个完整样本）。任一步失败立即停止，
不会继续后面的模块。全流程不暂停等待人工确认；基准通过仅表示程序运行成功，
不代表生物学准确率已验证。仍可单独指定模块，例如 `plan`、`build` 或 `split`。

完全不带参数的 `./3.global.sh` 会发现 `DIR_RAW` 下的全部数据集并执行相同全流程。
`./3.global.sh --help` 只显示帮助；`./3.global.sh all --help` 显示全流程参数。
`--threads`、`--db`、`--db-gib`、`--benchmark-fragments` 和分类参数可在全流程中统一指定。
显式 `--kraken-dir` / `METAG_KRAKEN2_DIR` 会验证该安装，不覆盖或回退到另一套程序。
重复执行会校验并复用已完成的同身份数据库/样本；基准测试会重新运行。

根据本机 WSL 约 70 GiB 总内存和优先节省时间的要求，默认改为 **24 GiB 哈希预算、
40 GiB 整个任务内存硬上限、8 GiB 内部余量**。使用独立 systemd 用户 scope / cgroup v2，
所有子进程都受限制；禁用本任务 swap，超限只终止本 scope 内进程。启动前要求
至少 48 GiB 可用内存，运行期间若系统可用内存低于 8 GiB，只停止本任务。
无法建立或验证内存隔离时直接失败，绝不退回无限制运行。`plan` 为只读检查，不创建 scope。
`--memory-limit-gib` 可显式调整硬上限；默认不会修改 WSL 配置或关闭 masking。

默认开启 `--quick`、`--confidence 0`，保留 `--minimum-hit-groups 2`，以较少的
命中证据提前结束分类。可用 `--no-quick --confidence 0.1` 改回更充分的搜索。
默认不生成逐 read 明细表；保留 species FASTQ、`counts.tsv`、`split.done` 和
`run-provenance.json`。需要明细时加 `--read-reports`。这些选项均纳入输出身份，
参数变化不能冒充之前的完成结果。未分类与高层分类读段仍保留，不随意分配物种。

适用基线：`jielab/scripts` 的 `metag/`，提交 `423a0e5bc02a86be719b3470cef550e8a0fade45`。

本入口是一条新的分类路线，使用一个全局 Kraken 2 索引。每个样本读取一次原始 FASTQ 完成主要分类，之后再次读取原始 FASTQ，按结果写出物种分组。原始读段、质量值、配对及每个分组内部的输入顺序均保留。

这会更换分类算法。它不承诺与 MetaCache 的物种结果一致；设置哈希表上限后还可能对 minimizer 抽样，尤其需要检查稀有物种、短 reads 和小型病毒的敏感度。全部有效参考 FASTA 都参与建库，不等于完整保留全部参考特征。

## 为什么已有版本仍然很慢

日志中的当前样本约 4,273 万对 reads，每对仍需接受 1,054 个分区的查询，总计约 450 亿次“片段 × 分区”。`169.3 秒 × 1,054 / 3,600` 约为 49.6 小时，因此日志的 47.2 小时剩余估计与实际机制相符。约 3.4 分钟/分区则约为 59.7 小时/样本。

上一版 compact merge 减少了中间表、排序及磁盘占用，未减少分区查询次数。22 MiB compact delta 是有变化的紧凑状态，不代表仅查询了少量 reads。466 个样本逐个查询 1,054 个分区，意味着约 491,164 次查询调用。650 天只是按压缩数据量外推的粗估，不能当成精确工期；现有结构不适合直接启动整批长跑的结论则充分成立。

## 安装附加入口

下载包解压后，在解压目录运行：

```bash
python3 install_overlay.py /mnt/d/scripts/metag --check
python3 install_overlay.py /mnt/d/scripts/metag
cd /mnt/d/scripts/metag
./3.global.sh install --threads 16
```

安装器只写新路线的文件，并检查依赖代码与审阅基线一致。`f/metag.conf`、`2.split.sh`、已有 MetaCache 数据库及其运行目录保持原样；已存在且需要更新的新路线文件会先备份。源代码有不兼容的修改时，安装器在复制之前报错。

Kraken 2 独立安装于 `${METAG_TOOLS:-$HOME/.cache/metag/tools}/kraken2/2.17.2/bin`，不要求改动现有 conda 环境。下载仅涉及官方程序源码；本工作流不会重新下载 NCBI 参考库或 taxonomy。

构建需要 Linux/WSL 上的 `git`、`make`、`g++`/`gcc`、OpenMP、zlib 开发头文件、Perl、Python 3 和常见 shell 工具。若缺少系统编译依赖，应先由本机管理员补齐。2.17.2 的核酸低复杂度屏蔽程序是随源码编译的 `k2mask`，无需为此另装 BLAST。

**版本校验注意：**官方标签 `2.17.2` 对应源码提交 `8c190b1b668825935dbf6dee5f969227dc8269bb`，但该源码中的 `VERSION` 仍为 `2.17.1`。安装器保留上游原样，以固定提交号及全部安装文件 SHA-256 记录来源；不能仅凭 `kraken2 --version` 的文字判断是否包含抽样数据库崩溃修复。

## 先做只读计划

```bash
./3.global.sh plan --dat-list changj,Ndesert,Wxiamen
```

计划读取现有配置与有效参考清单，检查与 `check-ref.receipt.json` 的状态一致，显示样本数、输入文件字节数、Linux/WSL 可用内存、cgroup 限制、磁盘剩余量和目标路径。不会查询 reads 或写入数据库。样本总片段数并未从压缩文件大小猜测。

默认读取：

| 用途 | 路径（可由现有 `f/metag.conf` 改变） |
| --- | --- |
| 原始参考 FASTA | `/mnt/f/annot/metag/raw` |
| 有效参考清单 | `/mnt/f/annot/metag/lib/reference/inventory.tsv` |
| 现有 taxonomy | `/mnt/f/annot/metag/lib/metacache/taxonomy` |
| 新全局数据库 | `/mnt/f/annot/metag/lib/kraken2_global/db` |
| 原始样本 FASTQ | `/mnt/f/metag/raw` |
| 新运行目录 | `/mnt/d/analysis/metag/runs_global` |
| 示例新输出 | `/mnt/f/metag/split/changj/SRR21290127__kraken2` |

有效参考清单已按原流程排除的 deleted taxid 记录不会重新加入。所有加入的序列使用明确的 `kraken:taxid` 标签，不依赖重新下载 accession 映射。现有 taxonomy 会复制并冻结在新数据库内。

## 建库一次

```bash
./3.global.sh build --db-gib 24 --threads 16
```

24 GiB 是 **哈希表上限**，不是数据库总大小。另用 `--memory-limit-gib 40` 硬限制整个任务内存，默认内部余量为 8 GiB。硬上限必须至少比哈希预算加内部余量再大 1 GiB。若更改数据库预算，请使用单独的 `--db` 路径，并在后续命令持续指定；抽样比例和分类敏感度可能变化。程序不会自动改变预算或 WSL 设置。

**磁盘成本必须考虑：**本构建方法保留一份用于 Kraken 2 建库的解压、整理后的参考 library，外加哈希、taxonomy、映射及少量临时块。它不生成两份完整的解压库，但仍可能比压缩参考文件大很多。最终解压量在流式读取完成之前未知，`plan` 的初始磁盘通过不保证全部参考一定容得下。建库期间持续检查保留空间，空间不足会停止且保留原始参考和已完成块。建库耗时也需要本机实测，可能很长；它是全体样本共用的一次性成本。

准备阶段以默认 512 MiB 碱基数为单位提交块，优先按完整序列边界分块，只有超过块大小的单条序列会切分，邻块重叠 34 bp 以覆盖固定 `k=35` 的跨边界 k-mer。低复杂度屏蔽对切分后的序列运行；超长序列切分点附近的屏蔽上下文可能不同。receipt 记录原始碱基数、序列条数、格式化碱基数和重叠碱基数。

默认使用 `k=35`、minimizer 长度 31、7 个 spaced-seed 位置，并开启低复杂度屏蔽。`--no-masking` 会明确改变分析方法，不应为绕过环境检查而默认使用。哈希预算、屏蔽选项、参考状态、taxonomy、程序来源与程序校验值都纳入数据库身份。

中断后重复同一建库命令：已经完整提交的参考块可重用，未完成块不会重复追加。准备尚未全部完成时，恢复可能需要再次读取前面的原始参考以重建确定的块边界；不承诺从任意压缩文件字节位置继续。原生索引构建中断可能需要重新做容量估计和索引构建。完成 receipt 只有在原生建库成功、文件完整且 `kraken2-inspect` 通过后发布。

## 用当前样本做吞吐基准

```bash
./3.global.sh benchmark \
  --sample changj/SRR21290127 \
  --benchmark-fragments 1000000 \
  --threads 16
```

该命令读取前 100 万对 reads（单端时为 100 万条），记录数据库加载在内的时间、吞吐量、输入量和参数，输出 `runs_global/benchmarks/.../benchmark.json`。它只验证这个前缀，不能证明 FASTQ 尾部完整，也不生成正式物种分组。它主要用于测吞吐，不代替生物学准确率验证。

数据库加载在小基准中占比可能很高；可再选 500 万对进行较大前缀测试。不要从本包的小型测试库速度外推真实全参考库性能。整批估算应包括一次性建库、每样本加载、实际片段数、分类、解压、最终 gzip 分组和存储 I/O；单一压缩字节比例不足以得到精确工期。

## 先完整跑一个样本，再跑整批

```bash
./3.global.sh split --sample changj/SRR21290127 --threads 16

# 审查单样本计数、未分类比例与代表性物种结果后：
./3.global.sh split --dat-list changj,Ndesert,Wxiamen --threads 16
```

新路线使用 CPU 多线程 Kraken 2，上游此版本没有 CUDA 分类后端；原 MetaCache GPU 路线需要反复扫描分区。这里的提速来自单全局查询、quick 模式和减少明细输出。默认 `--quick --confidence 0 --minimum-hit-groups 2 --minimum-base-quality 0` 优先节省时间，不承诺与完整搜索或 MetaCache 相同的准确率。

菌株/亚种分类会归并到其 species 祖先；高于 species 的分类保留在相应层级，未分类读段保留，不强行填入某个物种。核查 `split.done`、计数表和 provenance；本路线不提供逐 read 的参考序列命中证据。

## 恢复和旧任务

正在运行的 `2.split.sh` 不会被此安装器停止，也不会自动改用新算法。若决定切换，应在原任务的前台终端用一次 `Ctrl+C` 正常停止，让原流程处理子进程和状态。不要删除 `runs_v2`、旧数据库或其 checkpoint。当前的 15/16 个 MetaCache 分区状态只能用于继续 MetaCache 流程，不能折算为新分类器的进度。

新路线在单个样本的查询完全成功后提交紧凑 taxid 数组；若最终分组中断，再次运行可复用完整查询结果。若查询本身中断，需要重新查询该样本。最终分组结束后默认清理紧凑工作数组，保留日志和 receipt；`--keep-work` 可保留该数组。完整输出会按相同身份跳过；参数、输入、数据库或代码改变时，应使用新的 `--output-suffix`。

为防止原生多线程输出乱序、重复 read 名称或配对混淆，查询流使用临时数字序号，通过磁盘 mmap 保存 taxid、长度和完成位图。最终输出重新读取原始 FASTQ，不把临时数字序号写回原始 reads。缺失/重复/越界序号、长度不符、坏 gzip、配对不匹配、非零退出、输入或数据库改变均禁止发布完整成功结果。

## 测试和边界

压缩包包含原始测试代码、校验清单及日志；本机修改后的测试与资源计划保存在 `global_validation/`。原生测试使用固定源码提交编译的真实 Kraken 2，包括强制抽样数据库。额外端到端测试覆盖默认全流程、quick 分类、无明细 species 输出、重复运行复用，以及真实 cgroup 超限时组外进程存活。测试是小型数据上的软件正确性验证，不代表完整参考库吞吐、生物学准确率或整批完工时间。

在安装目录运行普通测试：

```bash
PYTHONPATH=f python3 -m unittest discover -s f/global_tests -v
```

可用真实安装重复原生测试（会创建临时小数据库）：

```bash
METAG_KRAKEN2="$HOME/.cache/metag/tools/kraken2/2.17.2/bin/kraken2" \
  METAG_TEST_CGROUP=1 PYTHONPATH=f python3 -m unittest discover -s f/global_tests -v
```
