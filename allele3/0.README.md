# allele3

等位基因、PCA、HERV 与变异扫描。支持 local/HPC；先生成计划并核对输入与资源，再提交。AlphaGenome 注释不是因果证据。

启明已上传 AlphaGenome 文件的解压结果、索引兼容性修复、验收记录和运行命令见 [HPC_ALPHAGENOME_20261104.md](HPC_ALPHAGENOME_20261104.md)。

在本目录查看参数和示例：

```bash
bash 1.pca3D.sh -h
bash 2.herv.sh -h
bash 3.scan.sh -h
bash allele3.sh -h
bash install.sh -h
```

路径优先使用命令行覆盖；共享默认配置位于 `../0f/0os.sh`。

可复用的计算结果保存在持久的 `ANALYSIS_ROOT/allele3/stores/`：`gnomad_scan/` 保存完成的 gnomAD 扫描、分片和汇总；`archaic_overlap/` 保存分队列的古人类片段交叠结果及历史版本。它们供后续分析反复读取，应长期保留。原始 VCF 留在 `DIR_ANNOT/allele3/gnomad/sites/`，不再向注释目录写这两类结果。

对应覆盖参数是 `ALLELE_SCAN_STORE` / `--scan-dir`（扫描管理入口用 `--store`）和 `ALLELE_ARCHAIC_CACHE` / `--archaic-cache`。已有扫描的原始 `run.json`、`COMPLETE.json` 和来源记录保持原样，通过随目录保存的 relocation 记录定位分片。

运行顺序为 `1.pca3D.sh` → `2.herv.sh` → `3.scan.sh` → `allele3.sh`。前三步完成后，直接运行 `bash allele3.sh --submit hpc ...`，不用填写模块名称，也不用逐个提交。默认 `--ibdmix FALSE`，依次运行 11 个主分析模块：`primary → summary → spatial → windows → alleles → time → selection → candidates → genotypes → ld → report`。前一步成功后才继续，失败会阻止后续步骤；已有结果通过身份和完整性检查后可复用。资源参数和可复制命令见 `bash allele3.sh -h` 的第一个示例。

主分析只生成一个 `cmd/all.cmd`、提交一个 HPC 作业，在同一份资源中依次执行选定模块；`--stages` 选择多个模块时也只提交一个作业。每个模块仍保留独立完成记录，整体状态实时写入 `pipeline_status.json`。内存按各模块的峰值需求申请，`--job-hours` 是全部模块合计的运行时限；失败后修复并重新提交，会先核验并复用已有有效结果。`batch allofus` 等可选分支仍按其任务特点调度。

IBDmix 默认不参与主分析：不提交 `archaic`，主结果与敏感性汇总在推断和 FDR 计算之前排除缓存中的古人类片段标签，报告不展示保存的 IBDmix 证据。探索性测试须显式使用 `--ibdmix TRUE --archaic-root DIR --archaic-datasets NAME`，并使用独立输出目录。本地 `ukb001`–`ukb013` 与 `1kg` 同在 `/mnt/d/analysis/gu/ibdmix/` 下，可用 `--archaic-datasets ukb009` 指定某个队列。

显式指定模块用于单独重跑；`batch atlas` 等可选研究分支有各自的数据要求。完成扫描的原始记录保持不变，外部输入当前路径由扫描目录内唯一的 `input_locations.json` 记录，登记时核对原始大小和指纹，使用时核对目标文件身份。liftOver chain 的统一默认目录是 `${DIR_FILES}/liftOver/`，命令行覆盖仍优先。
