<a id="overview--基础流程与-v31-兼容说明"></a>

### 基础流程与 v3.1 兼容说明

**现代 gnomAD 多 ALT 分布 → 古代选择背景与频率轨迹 → PC1–PC2–时间柱 → 稀疏 Atlas 功能向量。**

这是一套可运行的新代码。保留本地扫描、古代 DNA 和交互式可视化。v3.1 根据用户提供的旧 `check` 计数表，增加多 ALT 位点的 singleton 联合统计，并优化千万级现代位点的古今连接和候选存储。默认主分析没有远程查询；`--with-atlas` 或独立 `atlas-query` 才联网。

<a id="overview--v31-根据真实-countstsv-做了什么"></a>

### v3.1 根据真实 counts.tsv 做了什么

用户表包含常染色体 503,792,916 个旧规则 SNP 位置组，其中 37,985,189 个有至少两个保留 ALT（7.5398%）。这是 `PASS`/`AC>0` 条件下的统计，不是全部基因组碱基的密度，也不自动证明 REF 在相同样本中被观察到。算术审计和定义见 [相关说明](#doc-docs-counts-audit-zh)；设计与迁移见 [相关说明](#doc-docs-counts-audit-zh)。

- 新增 `audit-counts`：核对四类求和、重复总数、百分比舍入，生成离线 HTML、PNG、TSV 和 JSON。不存在的 Y 组记为缺失。
- 同一次 VCF 扫描记录 `n_alt × n_singleton_alts × min_alt_ac_bin`。汇总输出 `singleton_sensitivity.tsv`，回答去掉 AC=1 的 ALT 后，同一批多 ALT 位点有多少仍保留至少两个 ALT。
- 古今连接默认 `--join-strategy selection-first`：先索引论文的全部可用 SNV 坐标，再顺序读现代缓存，只在坐标命中时做两套 FASTA 和等位基因检查。没有按 S、posterior、频率或 FILTER 预筛论文记录。
- 新扫描默认 `--candidate-storage deferred`：保留全部现代位点和原 ALT 表，省去可重建的每位点三个理论替换表。只有显式全量离线 `annotate` 才生成它；数千位点的稀疏 Atlas 流程直接使用有界计划。

旧 v2/v3.0 现代缓存仍可通过 `--modern-out` 使用，无需重扫；缺少新的联合统计时标为未测定，不补零。要取得新联合统计，才需要以新输出目录重新扫描原 VCF。旧连接目录的策略签名不同，请为 v3.1 的 `evolve` 使用新的输出目录。

<a id="overview--必须保持的定义"></a>

### 必须保持的定义

- REF 不是祖先碱基；ALT1/ALT2 不是产生顺序。`extra_alt` 指现代直接观测到、但不属于某一古代 REF/ALT 对比的碱基。
- 古代 PGEN 来自双等位参考面板插补。PVAR 未收录第三碱基时标为 `not_represented_in_panel`，不填频率零、不推断首次出现年代。
- 论文 S 属于一个具体 REF→ALT 对比。先做 GRCh37↔GRCh38 双向映射、两套 FASTA 检查和方向转换。翻链不翻 S，第三碱基不继承旁边 ALT 的 S；原始 X/P/POSTERIOR/FDR 不再 inflation 校正。
- 3D 图是 PC1–PC2–年代，不是 PC1–PC2–PC3。年代不进入 PCA 矩阵，所有时期共用一个基底；gnomAD sites 汇总频率不转换成虚构个人散点。

<a id="overview--本机-bash-入口与资源限制"></a>

### 本机 Bash 入口与资源限制

`./allele3.sh -h` 由 Bash 直接输出，不依赖 Python 是否已安装。入口集中列出了默认路径、参数、目录别名和执行限制，可直接阅读修改。本机 `allele.env` 指向独立的 `allele3-evolution` 环境；外部环境变量与命令行都可覆盖对应默认值。

```bash
./allele3.sh -h
./allele3.sh --dry-run
./allele3.sh --preflight
./allele3.sh                         # 自动接续：现代扫描/汇总 → 古代分析 → 共享 PCA → 报告
./allele3.sh --with-atlas             # 在上述流程后增加 AlphaGenome 功能查询及比较
./allele3.sh --no-pca                 # 仅执行现代及古代分析，保留 PCA 计划
./allele3.sh run                     # 只做现代扫描及汇总
./allele3.sh evolve --with-pca        # 只接续古代流程及共享 PCA
```

无子命令时默认执行 `pipeline`。已完成的现代扫描会核对原输入、参数、完成标记和缓存文件；已完成的汇总直接复用，不改写现代 `run.json`，因此不会使下游古今连接缓存失效。扫描未完成时复用已完成染色体，继续剩余部分。古代连接、候选、面板和轨迹复用各自完成记录，PCA 完成后通过校验结果复用；未完成的 PCA 会重新执行其计算阶段。输入或科学参数变动不会静默混入旧结果。单独的调度代码位于 `runtime/pipeline.py`，不改变扫描模块的代码签名。

`pipeline`、`run`、`scan`、`evolve` 默认使用精简屏幕日志：同类重复进度每 300 秒最多显示一次，并发染色体共享扫描进度间隔；阶段开始、完成、缓存复用和警告/错误即时显示。完整 stdout/stderr（包括 PLINK 进度和 JSON）实时保存到输出目录的 `logs/命令_时间_PID.log`，启动时显示实际路径；失败时额外显示最后 30 行，并保留非零退出码。`--screen-log-interval 600` 或环境变量 `ALLELE_SCREEN_LOG_INTERVAL=600` 可调整间隔，`--verbose-screen` 恢复完整屏幕输出。帮助、版本、预检查及其他单独命令保持原输出方式。日志启动层位于 `runtime/console_log.py`，不会改变分析缓存签名；修改只对下次启动生效。

默认执行 PCA，PLINK 使用 4 线程、8192 MiB 工作内存，整个流程共享 16 GiB 内存上限；FINAL 保留完整 U0，使用 U1=20,000 unique sites 与全部 eligible U2 strong rows 及匹配对照。**AlphaGenome 默认关闭，不需要 API 密钥，不影响现代统计、古代频率轨迹和 PCA。** 它只为候选提供额外的预测分子效应比较。需要时运行 `./allele3.sh --with-atlas`，使用独立 U3=3,000 sites、最多 9,000 个唯一替换；本机从 `ALLELE_API_KEY_FILE=/mnt/d/files/alphaG.api` 读取密钥，也可用 `--api-key-file` 覆盖，或用 `--api-key-env ALPHAGENOME_API_KEY` 改为环境变量。

`--dir-modern` 指定自动流程的现代输出/缓存目录，`--dir-out` 指定古代及 PCA 输出目录；`--dir-analysis-root` 同时更换两者的默认根目录。`--preflight` 仍只检查现代输入，不启动古代分析。

本机 FINAL 默认结果写到 `/mnt/d/analysis/allele3/final`：现代结果为 `gnomad_local/`，古代结果为 `evolution/`，现代缓存为结果目录下的 `shards/`。输入数据仍在 F 盘。`--dir-analysis-root` 更换统一根目录；`--dir-out`、`--dir-vcf`、`--dir-cache`、`--dir-ancient`、`--dir-modern`、`--dir-atlas-cache` 分别控制具体目录，旧参数名也保留。`--help-full` 显示相应 Python 模块的完整参数。

默认现代扫描并发为 2；整个进程树共用 **16 GiB 的 cgroup 内存硬上限**，swap 上限为 0，OOM 时终止同组任务。限制包括 Python、bcftools、PLINK 和其子进程。PLINK 默认工作内存 8192 MiB、4 线程，若总上限调低，工作内存自动限制为总额的一半。设置 `--memory-limit-gb N` 可调整总额，本共享主机最多 32 GiB。没有可用的 user systemd/cgroup v2，或内核限制核验失败时，程序直接拒绝启动分析。这里不修改 WSL 全局配置，也不终止其他任务。

```bash
./allele3.sh --jobs 2 --memory-limit-gb 16 \
  --dir-analysis-root /mnt/d/analysis/allele3
./allele3.sh evolve --dir-modern /mnt/d/analysis/allele3/gnomad_local \
  --dir-out /mnt/d/analysis/allele3/evolution --max-sites 200 --max-variants 600
```

本机 PCA 默认把只读 PGEN/PVAR/PSAM 输入的校验副本缓存到 `$HOME/.cache/allele3-evolution/pgen`，避免 WSL 挂载盘逐小块读取的开销；结果仍在 D 盘。首次约需 27 GiB 本地空间，复制时比对源流与副本的 SHA-256，复用时核验缓存 SHA-256 和源文件指纹，原始 F 盘文件保留。`--dir-pgen-cache DIR` 更换缓存目录，`--no-pgen-cache` 直接读取原文件。缓存记录保存在结果目录的 `pca_input_cache.json`。

默认 `pipeline` 和单独的 `run` 都不访问 Atlas；`--with-atlas`、`evolve --with-atlas` 或 `atlas-query` 显式启用有界网络查询。API key 仅从外部文件或环境变量读取。

<a id="overview--1-复用或生成现代-gnomad-扫描"></a>

### 1. 复用或生成现代 gnomAD 扫描

已经完成 v2/v3.0 本地扫描时，直接把 `run.json` 所在目录传给 `--modern-out`。无需重扫 VCF，也不要求 `--write-all-sites`。旧版逐 SNP 请求 Atlas 的输出不能冒充新本地缓存。

尚无现代结果时：

```bash
bash allele3.sh run \
  --dir-vcf /mnt/f/annot/gnomad/sites --chr autosomes \
  --fasta /mnt/f/gen/1hgp/38/GRCH38.fasta.gz \
  --backend bcftools --jobs 4 --vep \
  --min-an 100000 --thresholds 1,2,5,10 \
  --source-label gnomAD-v4.1-genomes \
  --candidate-storage deferred \
  --out /mnt/d/analysis/allele3/gnomad_local_v31_an100000
```

`min-an=100000` 是高覆盖敏感性分析的示例，按真实 release 选择。`--vep` 只读取已有注释；若没读取或没有注释，匹配状态为 `codingunknown`，不伪称已控制编码状态。现代扫描的完整说明保留在 [相关说明](#doc-docs-local-scan-zh)。

单独审计旧 `check` 表不需要 VCF、FASTA、古代面板或网络：

```bash
bash allele3.sh audit-counts \
  --counts-tsv /path/to/old_check/counts.tsv \
  --out /mnt/d/analysis/allele3/counts_v31
```

报告位于 `counts_v31/counts_audit/counts_review.html`。`/path/to/old_check/counts.tsv` 是占位路径，请替换为真实路径。也可在 `evolve` 中传入 `--counts-tsv`，将报告并入总入口。`--no-plots` 跳过 PNG，保留表格与 HTML。

<a id="overview--2-一条命令完成古今连接和轨迹"></a>

### 2. 一条命令完成古今连接和轨迹

```bash
bash allele3.sh evolve \
  --modern-out /mnt/d/analysis/allele3/gnomad_local_v31_an100000 \
  --ancient-dir /mnt/f/gen/ancient \
  --fasta38 /mnt/f/gen/1hgp/38/GRCH38.fasta.gz \
  --fasta37 /mnt/f/gen/1hgp/37/GRCH37.fasta.gz \
  --chain38to37 /mnt/f/gen/chains/hg38ToHg19.over.chain.gz \
  --chain37to38 /mnt/f/gen/chains/hg19ToHg38.over.chain.gz \
  --qpadm /mnt/f/gen/ancient/Ancestry_Composition_3way_qpAdm_Patterson2022.tsv \
  --ancestry-model 3way \
  --max-sites 2000 --max-variants 6000 \
  --out /mnt/d/analysis/allele3/evolution_v31
```

请按真实位置修改参考与链路径。该命令依次：

1. 将 PSAM 与公开 Excel 精确连接，保留全部行，用 `include=0` 标记排除样本。
2. 索引完整已发表 SNV 选择统计的坐标，流式读取现代多 ALT 缓存，精确连接命中位置的等位基因。
3. 预先按 posterior、AC、物理区块选择候选，并匹配弱选择证据的多 ALT 对照。
4. 顺序读一次完整 PVAR，保留原始行索引，核对 HQ 表。
5. 仅随机读取目标 PGEN 行，输出时间与地区分层的 AC/AN/AF。
6. 生成有硬上限的 Atlas 计划、可执行 PCA 脚本和 `report.html`。

默认不执行远程 Atlas 或较重的背景 PCA。加 `--with-pca` 执行本地 PCA 并渲染图；加 `--with-atlas` 执行稀疏远程查询。首次建议 `--max-sites 200 --max-variants 600`，核对真实数据行为后再用新的输出目录扩展预算。

`selection-first` 与 `modern-first` 参考实现的有效交集相同，但输出行顺序及映射 QC 的检查范围不同。新策略的 `mapping_rejections.tsv.gz` 仅记录现代坐标命中后的参考检查失败；论文坐标预筛失败在 `selection_coordinate_rejections.tsv.gz`。未命中现代位置没有检查参考，不能计为映射失败。manifest 记录实际扫描数、命中数、完整参考验证调用数、索引大小和内存观测。它没有预设全量耗时。

<a id="overview--3-pc1pc2时间柱"></a>

### 3. PC1–PC2–时间柱

在完整 `evolve` 命令加 `--with-pca` 最方便。也可分开：

```bash
bash allele3.sh pca-plan \
  --ancient-dir /mnt/f/gen/ancient \
  --out /mnt/d/analysis/allele3/evolution_v31

bash /mnt/d/analysis/allele3/evolution_v31/pca/commands.sh

bash allele3.sh pca-time \
  --ancient-dir /mnt/f/gen/ancient \
  --eigenvec /mnt/d/analysis/allele3/evolution_v31/pca/all.sscore \
  --pca-basis-label joint_balanced \
  --out /mnt/d/analysis/allele3/evolution_v31
```

`pca/pca_time.html` 包含绘图依赖，可以离线打开；支持三维/二维切换、旋转、时间窗口、地区/来源筛选和 ALT 剂量着色。更高 Z 表示更大的 BP（更古老）。当前筛选样本的 AF/AC/AN 只是样本统计，不是整个人群的无偏频率。

默认基底 `joint_balanced` 对年代箱×地区×队列各组的无亲缘样本数封顶，减少大组主导；这不保证各组权重相等。以 HQ 常染色体背景 SNV 做 MAF/缺失率过滤和 LD pruning，并排除长程 LD 预设及 U2 strong loci ±1 Mb（旧流程使用 candidates）；不以全部 U1 背景位点掩蔽基因组。basis N≤5000 使用标准 PCA，>5000 使用 approx。所有样本，包括基底样本本身，都通过同一次投影得到 `all.sscore`，不混用 eigenvec 与 projection 的缩放单位。

`--pca-basis modern_projection` 只用 EUR1KG 建基底，再投影古代样本，是敏感性方案；现代 EUR 基底可能无法完整表达古代结构，可能出现投影收缩。

蓝→橙 0/1/2 指同一个 ALT 的拷贝数，不是三个碱基。第三碱基是否可测定，查看它自己的 target 状态；不能从 anchor 的 0/1/2 推断。HTML 初始面板最多 12 个目标（通常约 6 个位点的 anchor＋extra），顺序来自功能查询之前的候选清单。完整候选仍全部进入轨迹与功能分析；可用 `--selected-variants` 指定另一份小目标表出图。

<a id="overview--4-稀疏-atlas"></a>

### 4. 稀疏 Atlas

先查看 `atlas_plan/plan.json`。每个位点查询 GRCh38 REF 以外的三个可能 ALT，因此 2,000 位点最多 6,000 个唯一 variant。有限重试会增加实际 RPC 尝试次数，预算字段不会把重试隐藏成“零成本”。

```bash
bash allele3.sh atlas-query \
  --out /mnt/d/analysis/allele3/evolution_v31 \
  --api-key-file /path/to/private/api_key.txt \
  --max-variants 6000 --workers 2 --requests-per-second 2

bash allele3.sh atlas-summarize \
  --out /mnt/d/analysis/allele3/evolution_v31

bash allele3.sh compare-functions \
  --out /mnt/d/analysis/allele3/evolution_v31 \
  --geometry /mnt/d/analysis/allele3/evolution_v31/geometry/geometry.tsv

bash allele3.sh report-evolution --out /mnt/d/analysis/allele3/evolution_v31
```

这是预计算 Atlas 查询，不是为 9 billion 变异本地推理。缓存保存 raw signed effect、quantiles、完整特征轴和原始 protobuf。不同 scorer 分开；轴/区间不一致、unsigned、缺失和退化向量都显式标记。

主要问题：第三碱基的分子向量更接近历史估计上升还是下降的碱基？`breadth` 是预测响应维度超过阈值的比例，不是独立功能数、真实适合度或已验证 pleiotropy。REF 零向量是相对基线，不表示 REF 没有功能。

<a id="overview--抽样总体与推断限制"></a>

### 抽样总体与推断限制

本版复用现代多 ALT 缓存，研究总体是已观察到现代多 ALT 的位点。它不会把未保存的全体双等位位置伪造为对照。若要问“方向选择是否提高多 ALT 出现概率”，另需同一 callable universe 的双等位对照，控制突变机会、检测力和祖源；当前不声称完成该全位点富集检验。

强证据默认 `POSTERIOR>=0.99`，弱证据 `<=0.5`，后者不等于中性。FINAL U2 保留全部 eligible strong contrasts，按真实 EUR.37 LD blocks 聚类并另外输出每 block 的保守代表；只有未启用 `--with-universes` 的旧兼容入口使用每 1 Mb 的近似区块。默认排除 MHC；`--include-mhc` 是敏感性分析。功能对照匹配三碱基 context、论文 pooled AF、extra AF、AN 和可用编码注释；既然已匹配 extra AF，就不能再用这些配对检验 extra AF 差异。

轨迹默认 0–10,000 BP、2,000 年一箱，现代是独立 endpoint，更老样本计数但不进此窗口。PCA 可显示全部纳入年代。可设 `--bins 0,2000,4000,6000,8000,10000,14000,20000` 延长轨迹。

固定构成敏感性分析使用 `--weights weights.tsv`（两列 `stratum`、`weight`，权重和为 1）。某箱有正权重地区支持不足时结果为 NA，不重新归一化。无效 qpAdm 比例保留并标记，不截断；3way 和 4way 不混成同一基底。

## 独立 PCA 与三维年代图：0.pca3D.sh

`0.pca3D.sh` 不调用 `allele3.sh`、`evolve_cli.py`、现代扫描或选择分析。
它复用 `f/pca_time.py` 中的固定基底 PCA 和绘图函数，计算逻辑与原流程一致。
原来的 allele3 集成流程继续使用这些函数，避免维护两份科学计算代码。

三维轴为 **PC1、PC2、年代 BP**。年代不参与 PCA 计算。
目前 PCA 计划适用于人类常染色体 **GRCh37**；内置长程 LD/MHC 排除区间也是 GRCh37，
不能直接用于 GRCh38 或其他物种。已有共享坐标的绘图模式不读取基因组坐标或 PGEN。

<a id="doc-docs-pca3d--使用"></a>

### 使用

```bash
./0.pca3D.sh --help
./0.pca3D.sh --dry-run

# 原始 ancient 数据布局；自动从其原始补充表生成规范元数据。
# 默认输入 /mnt/f/gen/ancient，输出 /mnt/d/analysis/pca3d。
./0.pca3D.sh plan --out /mnt/d/analysis/pca3d/ancient
./0.pca3D.sh run  --out /mnt/d/analysis/pca3d/ancient

# 其他 GRCh37 数据：明确指定该数据自己的背景位点和样本信息。
./0.pca3D.sh run \
  --pgen-prefix /data/my_cohort \
  --hq-variants /data/background_variants.tsv \
  --metadata /data/sample_metadata.tsv \
  --out /analysis/my_cohort_pca

# 已有共享 PCA 坐标：不需要原始古代数据、PGEN 或候选位点。
./0.pca3D.sh render \
  --eigenvec /data/all.sscore \
  --metadata /data/sample_metadata.tsv \
  --pca-basis-label '共同背景标记和固定基底；所有样本统一投影' \
  --out /analysis/my_pca_plot
```

`--dry-run` 只打印命令，不读输入、不建目录，也不执行 PLINK。
`plan` 会读取输入、生成 keep/背景位点/排除区间/PLINK 脚本与计划记录，
但不会执行 PLINK；指定 `--dir-pgen-cache` 时仍会准备经验证的输入副本。
`run` 生成或复用计划，执行 PCA、统一投影，再导出 HTML、PNG、PDF。
`render` 仅绘图，需要 `--eigenvec` 和 `--metadata`。

配置文件为 `PCA3D_CONFIG` 或入口旁的 `pca3d.env`，配置示例见本文件的“环境与配置”。
命令行覆盖配置值。独立入口不加载 `allele.env`，不继承 `ALLELE_*` 分析配置。
`--python` / `PCA3D_PYTHON` 可指定解释器；否则依次使用当前 Conda 环境、
已安装的 `pca3d`、本机已有的 `allele3-evolution`、PATH 中的 `python3`。
历史环境仅作为可复用的依赖环境，不要求 allele3 主流程存在。

<a id="doc-docs-pca3d--输入约定"></a>

### 输入约定

PGEN 前缀对应 `.pgen`、未压缩 `.pvar`、`.psam` 三个文件。
背景 TSV 的列名必须包含 `#CHROM、POS、ID、REF、ALT`，位置为 GRCh37 的 1-based 坐标，
ID 必须对应输入面板；由调用方负责背景位点质量筛选。
对自定义 `--pgen-prefix`，必须显式提供 `--metadata` 和 `--hq-variants`。

元数据采用制表符分隔，最少五列：

```text
sample_id	cohort	age_bp	include	stratum
sample_A	modern	0	1	East
sample_B	ancient	4200	1	West
sample_C	ancient	3500	0	West
```

`cohort` 为 `ancient` 或 `modern`；`age_bp` 为距 1950 年的非负年数；
`include` 为 0/1，表示调用方完成样本 QC 后是否纳入；`stratum` 为分层名称。
可增加 `region、data_source、data_types、target_coverage、iqs` 用于悬停和筛选。
现代样本也应提供有含义的分组；不得为缺失年代随意填写 0。
PCA 计划要求元数据覆盖完整 PSAM 且 ID 唯一；绘图要求坐标覆盖所有 `include=1` 个体。
固定训练基底至少为 `max(50, PC数+1)` 人。

原始 ancient 数据的自动元数据适配器仍使用该研究特定的 XLSX 字段和 QC 规则，
不套用于其他研究。自动生成的元数据带有输入和输出校验记录，变更后要求新输出目录。
其他数据通常直接提供规范 TSV。

输入坐标接受 `IID/PC1/PC2`，或统一 `.sscore` 的 `PC1_AVG/PC2_AVG`、
`PC1_SUM/PC2_SUM`。不能混用训练 eigenvector 与投影 score 的尺度。

<a id="doc-docs-pca3d--可选目标与结果"></a>

### 可选目标与结果

不提供目标文件时即可完成完整 PCA 与三维图。
`--target-variants` 只排除背景目标及其侧翼，要求 `chrom,pos`，可加 `build=GRCh37`。
`--selected-variants` 额外显示目标等位基因，必须提供已核验的
`variant_id,pvar_index,chrom,pos,ref,alt,status`；最多按输入顺序显示 12 个，
选择记录写入 `overlay_selection.json`。缺失或未覆盖等位基因显示不可用。
未单独指定 `--target-variants` 时，也从背景中排除 `--selected-variants` 所列目标。
这两项均为显式输入，不自动寻找 allele3 的候选文件。

输出保留原有子目录布局：`OUT/pca/` 包含 `pca_plan.json`、`commands.sh`、
`all.sscore`、`PCA_COMPLETE`、`pca_time.html` 和 PNG/PDF 图。
日志位于 `OUT/logs/pca3d_*.log`。
相同输入和设置可复用已校验的 PCA 结果；改变设置须另用输出目录。
`--html` 只改变图的路径，静态图写入该 HTML 所在目录。
不要让新入口和原 allele3 流程同时写同一个输出目录。

<a id="doc-docs-pca3d--依赖与复制到其他场景"></a>

## 个体基因组 HERV / ERV 占比

输入是人类个体的相位 VCF 或 PLINK 2 PGEN，
输出是 chr1–22 的参考、hap1、hap2、二倍体 ERV 碱基覆盖比例。
`prepare-erv` 整理现有 RepeatMasker 注释表；本模块会重建个体序列并重新运行 RepeatMasker。
metag 的 FASTQ HERV 模块（包括 DNA/RNA、参考准备和 `census` 命令）已移除。
本模块不需要 RNA 数据，也不估计表达；已有共享参考及参考统计仍保留在原位置。

<a id="doc-docs-herv--运行"></a>

```bash

# HG00096 已完成目录迁移；检查并复用既有分块，未完成的分块才会计算。

```

<a id="doc-docs-final-implementation-zh--抽样概率"></a>

### 抽样概率

真实完整 intersection 有 30,997 个非空联合 strata，超过 U1=20,000 的预算，不能给每层强行至少 1 个样本。实现先按 `sqrt(N_h) × oversampling factor` 分配期望数量 μ_h，并以 N_h 封顶；使用一次随机 systematic rounding 得到整数 K_h，使总样本数固定且 E[K_h]=μ_h；每层使用独立 seeded SRS 排序取 K_h。

因此每个位点的边际纳入概率为 `μ_h/N_h`，weight 为倒数。`sampling_design.tsv` 同时记录 N_h、实际 K_h、期望 μ_h；未抽中的层仍有正边际概率。不能把实现出的 K_h/N_h 冒充整体设计概率。U0/U2 不受抽样预算截断。U3 是目标功能 panel，优先病例/对照，不能当成全基因组无偏样本。

## allele3 local：从 gnomAD sites VCF 研究同一位置的多个 ALT

版本：2.0.0-local-20261021。

本版把主分析改为 **本地 VCF → 按位置重组 → 条件分布与祖源描述 → 可选离线分数注释**。主流程不读取 AlphaGenome API key，不发起网络请求，不要求 GPU，也不下载 Atlas 全量输出。

研究对象是同一参考基因组位置上观察到的不同 SNV ALT。它适用于 gnomAD sites-only 汇总 VCF，既可读拆成多行的多等位位点，也可读一行多个 ALT 的记录。它不需要个体基因型。

<a id="doc-docs-local-scan-zh--1-先明确第三个-allele"></a>

### 1. 先明确“第三个 allele”

- `REF` 是参考序列中的碱基，不等于祖先、主要或本批样本中一定存在的 allele。
- VCF 中 `ALT` 的行顺序/数组顺序不代表突变产生时间。
- `n_alt` 是通过本次过滤并有正 AC 的不同非参考 SNV 碱基数，范围 1–3。`n_alt=2` 是常说“三等位位点”的候选；本程序不无条件把它写成 `allele_count=3`。
- `primary_alt`、`secondary_alt` 按各自 `AC/AN` 降序排列，只在 ALT 之间排名。相同 AF 会标记 `primary_tie`。这不是包含 REF 的群体频率前三名。
- 每条 ALT 保留自己的 AC、AN 和 AF。对拆分记录，不计算 `REF_AF=1-sum(ALT_AF)`、REF AC、全位点 Shannon entropy 或杂合度。
- 没有列出的 ALT 标记 `not_listed_in_release`，计数保持缺失；它不自动等于“真实 AC=0”“不可存活”或“已灭绝”。

gnomAD 官方已解释，拆分/downcode 在频率汇总前发生，因此同一位置不同 ALT 的 AN 可不同。即使 AN 数值碰巧相同，也不能单靠该数字证明统计使用的是相同染色体集合。方法依据与研究边界见 [docs/METHODS.zh.md](#doc-docs-methods-zh)。

### 7. 可选注释与离线预测分数

`--vep` 读取原 VCF 中已有的 `INFO/vep` 或 `CSQ`，不运行新的 VEP，不发起联网注释。该选项会增加字段读取与 CPU；主要 ALT 的 consequence 分类不是位点独立功能标签。

本地 AVI 示例：

```bash
bash allele3.sh annotate \
  --dir-out /mnt/d/analysis/allele3/gnomad_local_an100000 \
  --scores /mnt/f/annot/alphagenome/avi.tsv.gz \
  --score-format avi --score-column phred \
  --score-build GRCh38 --score-label AVI \
  --score-version YOUR_DOWNLOADED_RELEASE
```

`avi.tsv.gz` 为您已下载的本地文件示例名。官方六列无 header 格式需显式 `--score-format avi`；普通表则使用 header 和 `--score-format tsv`。它们按 CHROM/POS/REF/ALT 完全匹配，不自动交换 REF/ALT、不做 liftover，缺失保留缺失。有 Tabix 索引时按坐标块查询；否则按排序流式合并。

AVI 的训练使用了 gnomAD 频率 proxy 标签。因此 AVI 与同一来源频率/多 ALT 占用的关联只能作探索性注释，不能作为独立的选择或 pleiotropy 验证。分数差也不等于功能数量或功能相似性。详见 [docs/OFFLINE_SCORES.zh.md](#doc-docs-offline-scores-zh)。

<a id="doc-docs-local-scan-zh--8-运行时间内存与恢复"></a>

### 8. 运行时间、内存与恢复

主要代价是一次本地文件读取、BGZF 解压、逐位置统计以及多 ALT 详细结果写出。内存以当前坐标组、当前窗口分层计数、汇总计数和可选 callable 区间为主；不把全量 VCF 读进 DataFrame。

`--jobs` 是并发染色体数，每条染色体一个扫描进程。机械盘、网络盘或 WSL 的 `/mnt/f` 上，增大并发可能降低速度；建议比较 1、2、4 个任务的真实吞吐，再选择。试跑后可由日志/`scan.json` 得到本机速度，但一个区域的记录密度不代表全基因组，不能简单把 toy benchmark 外推成总耗时。

恢复与缓存规则：

1. 原始 VCF、索引、FASTA 不会被改写。
2. 完成的染色体有 `COMPLETE.json`，相同输入和扫描参数重跑可复用；失败染色体从该染色体开头重扫，当前版本不支持染色体内部断点。
3. 所有扫描参数、版本、核心 Python 代码哈希、输入身份参与签名。输入内容/路径/mtime、阈值、掩码、build、祖源选择或代码改变时，应选择新的输出目录。
4. 输入指纹包括路径、大小、mtime 和文件头尾 SHA256，用于快速防止误复用；不是整文件校验和。下载完整性仍应使用发布者 checksum。
5. 输出目录和共享缓存分片均加锁，避免并发覆盖。使用 `--dir-cache` 时同一输入签名可共享已完成分片；改变染色体输入集合也会改变整体签名。
6. 旧版 prepare/Atlas 输出不被自动当作本版缓存；旧输出目录不会被接管。

只改变绘图与最少训练数时可直接重新汇总：

```bash
bash allele3.sh summarize \
  --dir-out /mnt/d/analysis/allele3/gnomad_local_an100000 \
  --min-training-sites 200
```

`summarize` 读取扫描 manifest 中记录的窗口、阈值和掩码，不能在这个阶段重新指定过滤条件；新过滤需重新扫描。`annotate` 独立于扫描，可在已有结果上补分数。

<a id="doc-docs-local-scan-zh--10-从旧版迁移"></a>

### 10. 从旧版迁移

保留并复用原始 `sites/*.vcf.bgz`、`.tbi/.csi`、FASTA、`.fai/.gzi`。原 `counts.tsv` 可保留作旧 QC 记录，不充当新分析的分母。

旧 `prepare` 需要重新生成，因为旧提取逻辑曾构造 REF 频率/entropy，并可能丢弃 AN 不一致或 REF 推算异常的位点。单纯在旧汇总结果后接一个快速脚本不能恢复已丢弃信息。

旧 Atlas 缓存可继续保存，但本版本不依赖也不自动导入。新结果目录默认使用 `gnomad_local`，避免覆盖 `/mnt/d/analysis/allele3/gnomad`。给本地 Codex 的具体交接文本见 `allele3.codex.txt`。

研究背景、先前 triallelic 文献、假说的可检验形式及来源均见方法文档。不要把这一套软件的成功运行表述为“已证实多功能 SNP 更容易形成平衡”。

## allele3：基于 gnomAD sites VCF 的多 ALT 观察结构研究

版本日期：2026-10-21。本文对应当前代码中的 `scan.py`、`summarize.py`、`intervals.py` 和 `local_scores.py`；文中的后续研究建议另行标明。本文没有报告真实 gnomAD 分析结果，示例数字仅用于说明定义。

<a id="doc-docs-methods-zh--一研究问题与当前交付的边界"></a>

### 一、研究问题与当前交付的边界

本研究首先回答：在同一个核苷酸位置，什么情况下会观察到一种以上的非参考碱基？这些位置在染色体上的分布、序列上下文、替换类别和人群频率结构有什么规律？

当前主流程只需要本地的 gnomAD sites VCF 和匹配版本的参考 FASTA；不需要个体基因型，不调用 AlphaGenome API，也不要求先获得全部候选变异的功能预测。现有 VCF 中的功能注释和本地预计算分数均为可选输入。

必须分开三个层次：

1. **观察结构**：在这个版本、这个样本集合、这套质控和阈值下，哪些 ALT 被列出且满足分析条件。
2. **形成机制**：重复突变、人口历史、遗传漂变、选择、人群混合等因素如何共同塑造观察结构。
3. **多效性假说**：某些多维功能作用模式是否有助于等位基因共存或持续存在。

当前程序完成第一层，并提供第二层的描述性背景。它不会自动把背景之外的差异解释为第三层的证明。人群中的 triallelic 现象及其频谱已有专门研究；项目的创新应聚焦大样本人类数据中的全基因组结构、严格的观察定义和机制比较，不能写成首次研究第三种等位基因。[4–6]

<a id="doc-docs-methods-zh--二分析单位同一核苷酸位置的不同-alt"></a>

### 二、分析单位：同一核苷酸位置的不同 ALT

<a id="doc-docs-methods-zh--21-refalt-和出现先后不同"></a>

#### 2.1 REF、ALT 和出现先后不同

VCF 的 REF 是参考序列碱基，ALT 是相对该参考的替代碱基；ALT 的编号由记录顺序确定。REF 不自动等于祖先碱基、最常见碱基或“第一个出现的碱基”。ALT2 也不代表历史上第二次突变产生的碱基。VCF 另有独立的祖先等位基因字段约定，说明这些概念不能互换。[3]

程序在同一坐标重组所有拆分的记录，确认单碱基 REF 一致后，对不同 `A/C/G/T` ALT 去重。以下两种表示应产生一致的 ALT occupancy：

```text
chr1  100  REF=A  ALT=G,T
```

```text
chr1  100  REF=A  ALT=G
chr1  100  REF=A  ALT=T
```

只计算单碱基替换。插入、缺失、多核苷酸变异、`*` 和其他符号等位基因不进入 SNV occupancy。若同位置还存在这些记录，相关多 ALT 位点会带有 `has_non_snv` 标志；该标志不等于对结构变异做了分析。

<a id="doc-docs-methods-zh--22-n_alt-的准确含义"></a>

#### 2.2 `n_alt` 的准确含义

令 \(O_i(t)\) 为位置 \(i\) 在 AC 阈值 \(t\) 下合格、不同的非参考 SNV 碱基数：

\[
O_i(t)=\sum_{b\ne REF_i}
I\{b\text{ 是合格 ALT，且 }AC_{ib}\ge t\}.
\]

| 程序指标 | 可以确定的含义 | 不能自动推出的结论 |
|---|---|---|
| `n_alt=1` | 观察到一种合格 ALT | REF 一定仍存在；该位点一定恰有两种碱基 |
| `n_alt=2` | 观察到两种合格 ALT | 已证明人群中同时存在 REF 加这两种 ALT，共三种碱基 |
| `n_alt=3` | 三种非参考碱基均被观察到 | REF 一定仍存在；已证明四种碱基共存 |
| `n_alt_ac5=2` | 有两种合格 ALT 的 AC 均至少为 5 | 存活了特定时间，或受到平衡选择 |

本代码的主要术语是 **multi-ALT site：至少两种合格 ALT 的位置**。文件名 `multiallelic_sites.tsv.gz` 延续多等位研究的使用习惯，但文件中的 `n_alt` 始终是 ALT 数，不是已证实的全部人群碱基数。

<a id="doc-docs-methods-zh--23-按频率排序的对象"></a>

#### 2.3 按频率排序的对象

对每一种 ALT，程序以其自身的 \(AC/AN\) 计算 AF，然后按 AF 降序排序；AF 相同时用 AC 和碱基名称确定可重复的顺序，同时记录 `primary_tie`。

- `primary_alt`：满足当前条件的最高频 ALT。
- `secondary_alt`：第二高频 ALT。
- `alt_frequency_rank`：ALT 内部的频率排序。

这些字段**不包含 REF 的频率排序**。`secondary_alt` 因而不自动等于所有碱基中第三常见的一种。不同 AC 阈值可能保留不同 ALT，条件背景中会重新选择该阈值下的最高频 ALT。

<a id="doc-docs-methods-zh--三acan-与-ref为什么不能直接补出-ref-频率"></a>

### 三、AC、AN 与 REF：为什么不能直接补出 REF 频率

<a id="doc-docs-methods-zh--31-gnomad-拆分记录的-an-可以不同"></a>

#### 3.1 gnomAD 拆分记录的 AN 可以不同

gnomAD 团队说明，其流程先拆分多等位变异并对基因型下编码，再计算汇总频率；同一个位置不同 ALT 的 AN 因此可能不同。官方实例 `chr1:1228635` 的两种 ALT 使用了不同 AN。[1]

因此，下面两个公式不能无条件当作精确重构：

\[
AC_{REF}=AN-\sum_b AC_b,
\qquad
AF_{REF}=1-\sum_b AF_b.
\]

即使拆分后两个 AN 的数字相同，也不能仅凭这个数字证明用于每一种 ALT 的基因型集合和质控状态完全相同。当前代码采用更明确的规则：

- 各 ALT 保留自己的 AC、AN 和 `AF=AC/AN`。
- 不把其他 ALT 的 AN 填给缺失 AN 的记录。
- 不使用 INFO/AF 反推缺失 AC。
- 不把所有 ALT 频率重新归一化。
- 不估算 REF_AC、REF_AF、全碱基频率排序、联合熵或杂合度。
- 多 ALT 位点统一标记 `ref_frequency_status=not_inferable_from_sites_summary`。

`an_min`、`an_max` 和 `an_relative_spread` 用于显示同位点分母的不一致程度。它们是解释和敏感性分析的信息，不是“修复后得到了共同计数”的证明。

<a id="doc-docs-methods-zh--32-all-sites-an-的用途"></a>

#### 3.2 all-sites AN 的用途

gnomAD v4.1 另行公开了所有可调用位置的 AN，其中包括没有观察到非参考基因型的位置；官方说明这部分 AN 在拆分多等位变异之前计算。[1,2]

本代码可以把本地 overall all-sites AN 标量表转换为 callable BED。它的用途是定义**某个位置是否具有足够检测规模**，从而补充空间密度的分母。它不会自动把拆分后的 ALT AC 变成严格共同样本的多项计数，也不会补出 REF 频率。

`make-callable` 目前接受带标题的 `locus, AN` 或 `chrom, pos, AN` 表；位置为 1-based，AN 必须为标量整数。Hail 数组或嵌套结构需要先明确提取所研究人群、数据类型对应的 overall AN。不同数据类型、版本和祖源的 AN 不能混用。

<a id="doc-docs-methods-zh--四质控状态与分析阈值"></a>

### 四、质控状态与分析阈值

<a id="doc-docs-methods-zh--41-原始观察状态"></a>

#### 4.1 原始观察状态

程序不会把“不合格”重新编码成“从未出现”。每个实际列出的 ALT 都有以下状态之一：

| 状态 | 含义 |
|---|---|
| `observed_pass` | 通过所选记录/等位基因过滤，有合法 AC/AN，且达到基础阈值 |
| `present_failed_filter` | 记录已存在，但未通过过滤或被用户选择的区域标记过滤 |
| `present_missing_counts` | 记录已存在，但缺少可用计数或分母 |
| `present_below_threshold` | 记录已存在，但 AC、AN 或 AF 未达到基础条件 |
| `not_listed_in_release` | 该理论 ALT 在所读取的发布文件中没有记录 |

最后一种状态只用于生成同位点理论候选；它不等于“从来没有突变过”“已经灭绝”或“人类中不存在”。发布文件中没有记录也可能反映有限样本和变异发现能力。

默认只接受 `FILTER=PASS`；用户可显式选择同时接受 `FILTER=.`。存在 `AS_FilterStatus` 时会检查与 ALT 的对应关系。计数为负、AC 大于 AN、ALT 数组与字段长度不一致、相同 ALT 的冲突重复记录会触发错误；完全一致的重复记录去重，不累加。

<a id="doc-docs-methods-zh--42-当前默认值"></a>

#### 4.2 当前默认值

主命令默认 AC 阈值为 `1,2,5,10`，并始终包含 1；基础 `min_an=100`、`min_af=0`。祖源分析默认 `min_pop_an=100`、`min_pop_af=0`。这里的 100 是运行时的低分母门槛，**不是全基因组充分检测保证，也不是为所有祖源和频率问题验证过的通用质控标准**。

默认保留 singleton 的目的是先描述完整观察结构。是否以 AC≥2、≥5 或更严格条件作为论文主分析，应结合实际计数稳定性、区域质控、重复数据或独立资源结果决定。程序已经同时输出这些阈值，避免重复扫描。

`--exclude-flags lcr,segdup` 是可选敏感性分析；它只使用输入 VCF 已有的相应 INFO 标志，未提供的标志不会被程序凭空补齐。`--vep` 只读取 VCF 中已存在的 `vep/CSQ`，不执行在线注释。

<a id="doc-docs-methods-zh--五空间分布与正确的分母"></a>

### 五、空间分布与正确的分母

<a id="doc-docs-methods-zh--51-条件多-alt-比例"></a>

#### 5.1 条件多 ALT 比例

对窗口 \(w\) 和 AC 阈值 \(t\)，定义：

\[
N_{w,t}=\sum_{i\in w}I\{O_i(t)\ge1\},
\quad
M_{w,t}=\sum_{i\in w}I\{O_i(t)\ge2\},
\quad
T_{w,t}=\sum_{i\in w}I\{O_i(t)=3\}.
\]

程序输出的 `n_sites`、`n_multi`、`n_three` 分别对应这三个量。`multi_fraction=M/N` 是**至少一种 ALT 达标的 SNV 位置中，至少两种 ALT 达标的比例**。

阈值升高时，分子和分母同时改变。例如，一个仅有 AC=1 ALT 的位置在 AC≥2 的分析中不再属于分母。因此不同阈值的 `multi_fraction` 不能直接解释成“同一批初始位点的存活比例”。比较数量变化应同时查看 `n_sites` 与 `n_multi`；频率表中的每一行也必须带上阈值。

默认窗口为 1 Mb，坐标使用 BED 式 0-based、右端不包含。程序同时保留染色体和序列上下文汇总。窗口标签代表完整分箱；在 region 或扫描范围末端，实际 callable 分母可以小于标签的总长度。

<a id="doc-docs-methods-zh--52-缺少-callable-信息时"></a>

#### 5.2 缺少 callable 信息时

sites-only VCF 未列出的位置不能自动当作单态位置。没有 callable BED 时，程序输出上述多态位点条件比例，不输出有效的 `multi_per_callable_mb`。研究者不能用缺失 VCF 记录给全基因组创建单态对照。

<a id="doc-docs-methods-zh--53-有-callable-信息时"></a>

#### 5.3 有 callable 信息时

若提供匹配版本的 callable BED，扫描时先把不在 mask 内的位置排除，然后使用同一个 mask 的区间并集计算分母：

\[
D_{w,t}=\frac{M_{w,t}}{L^{callable}_{w}}\times10^6.
\]

`multi_per_callable_mb` 即该密度。它仍是指定数据与阈值下的观察密度，不是每代突变率。

BED 重叠区间只计一次。分母同时与 `scan_scope.tsv` 和 region 取交集；已扫描且具有 callable bases 的窗口即使没有合格变异也明确输出零。未扫描染色体不会因为存在于全基因组 BED 中而被填成零。程序还检查一个窗口中合格 SNV 位置数不能超过 callable bases。

对全基因组空间图谱，genomes 和 exomes 应分别处理。捕获区间和数据来源不同时，测序可及性差异可能主导表面上的分布差异；gnomAD 也专门说明了两种数据类型的 AN、频率不一致与样本构成问题。[2]

<a id="doc-docs-methods-zh--六条件观察概率背景具体实现与解释"></a>

### 六、条件观察概率背景：具体实现与解释

<a id="doc-docs-methods-zh--61-预测目标"></a>

#### 6.1 预测目标

背景模型的目标是：

\[
P\{O_i(t)\ge2\mid O_i(t)\ge1,\;\text{已实现的分层变量}\}.
\]

它不是从单态位置到多态位置的产生概率，也没有估计每个候选碱基的独立突变率。它是对当前多态 SNV 观察集合的经验描述。

<a id="doc-docs-methods-zh--62-五项精细分层"></a>

#### 6.2 五项精细分层

对每个阈值，程序使用：

1. AC 阈值 `threshold`。
2. 嘧啶方向统一的三核苷酸 `context`：中心为 A/G 时整体反向互补，使中心为 T/C；未知侧翼保留未知碱基标识。
3. 该阈值下最高频 ALT 的方向统一替换类别 `primary_change`，例如 `C>T`。
4. 该 ALT 的 AF 分箱 `primary_af_bin`。
5. 该 ALT 自身的 AN 分箱 `an_bin`。

AF 的切点为 `10^-5,10^-4,10^-3,0.01,0.05,0.5`；AN 的切点为 `100,1000,10000,50000,100000,120000,140000,150000,200000`。实际区间标签由代码输出，边界使用左闭右开，最后一档为不低于最后切点。AN 背景使用 anchor 的 AN，不代表已经获得未观察候选 ALT 的检测分母。

这个背景控制了部分突变相关上下文和观察规模。它未显式加入独立突变率图、甲基化、重组率、局部树龄、人口史或全部技术因素，不能写成已完整剔除这些机制。

<a id="doc-docs-methods-zh--63-留一条常染色体loco"></a>

#### 6.3 留一条常染色体：LOCO

当评价染色体 \(c\) 时，从训练统计中完全减去该染色体。在每个分层中，只用其他已扫描常染色体的 \(N_{-c}\) 与 \(M_{-c}\) 估计：

\[
\widehat p_{-c}=\frac{M_{-c}+0.5}{N_{-c}+1}.
\]

待评价染色体的 observed outcomes 不参与其训练概率。训练必须至少有两条总体上有观察位点的常染色体可供轮流留出；程序只用实际扫描到的常染色体，不自动假定全部 22 条已覆盖。

X、Y、MT 以及其他非常染色体仅作描述；它们不进入常染色体背景，也不产生这类期望值。仅扫描 chr22 时背景不可用。显式指定 `--region` 时同样不计算跨染色体背景。LOCO 的作用是减少同一染色体被自己“解释”的问题，并不构成独立队列验证。

<a id="doc-docs-methods-zh--64-训练支持不足时的回退"></a>

#### 6.4 训练支持不足时的回退

每次回退都重新检查留出染色体之外的训练位置数；默认最低为 100：

| 优先级 | 训练层级 | 所保留条件 |
|---|---|---|
| 1 | `exact` | threshold + context + primary_change + AF bin + AN bin |
| 2 | `context_change` | threshold + context + primary_change |
| 3 | `threshold` | 仅 threshold |
| 4 | `unavailable` | 所有层级均未达到支持要求，或不满足 LOCO 范围条件 |

回退到 context 层时，AF/AN 条件已被放宽；回退到 threshold 层时，context 条件也被放宽。因此不能把所有输出 O/E 都描述为同等程度的“上下文与检测校正”。应同时查看每个层级贡献的 `training_*_sites`、训练样本量和 `expected_context.tsv` 中的训练染色体数。

<a id="doc-docs-methods-zh--65-窗口期望与-oe"></a>

#### 6.5 窗口期望与 O/E

对待评价窗口中各分层 \(s\)，计算：

\[
E_{w,t}=\sum_s N_{w,t,s}\widehat p_{-c,t,s},
\qquad O/E=M_{w,t}/E_{w,t}.
\]

`expected_multi` 只预测“至少两种合格 ALT”的位置数，不预测 `n_three`。如果窗口中只有部分位置有可用背景，程序不输出使用全部观察计数的 `observed_over_expected`；它另行报告 `scored_observed_over_expected`，其分子只包括同一已评分子集，并给出覆盖率。

含非常染色体的总计表可能显示 `partial`，因为总观察计数包括这些描述性部分，但背景仅适用于常染色体。背景不可用时保留原因，不自动以零替代期望值。

**O/E>1 仅表示相对这个经验背景更常观察到 multi-ALT 位点。** 程序不对 O/E 计算选择检验 P 值。原始比例的 95% Wilson 区间为描述性二项区间，不处理相邻位点相关性，也不替代正式的区块重抽样或人口遗传模型推断。

<a id="doc-docs-methods-zh--七祖源结构共存分散和无法判断"></a>

### 七、祖源结构：共存、分散和无法判断

程序自动识别 VCF 中同时存在 AC/AN 字段的祖源组，也可由用户指定。对一个位置、一个阈值，只在该位置**当前所有 retained ALT** 的祖源 AC/AN 都非缺失且 AN 达到 `min_pop_an` 时，才认为该祖源组可评价。

在可评价组内，按相同 AC 阈值和 `min_pop_af` 计算 ALT 数；缺失计数不补零。程序输出 `n_evaluable`、`n_sites`、`n_multi`、`n_three` 等计数，便于显示各组使用了不同的实际观察分母。

| `population_class` | 正确解释 |
|---|---|
| `within_group_observed` | 至少一个可评价祖源组中，观察到至少两种达标 ALT |
| `distributed_across_groups` | 在可评价组中未发现组内 multi-ALT，而不同组的达标 ALT 并集至少包含两种；该结论仅限可评价组 |
| `not_resolved_with_available_groups` | 可评价组尚不能解释全球合并后的多 ALT 结构 |
| `insufficient_group_callability` | 满足条件的祖源组不足，无法完成相应比较 |

`distributed_across_groups` 不表示所有人类祖源组内都不存在共存；被排除的低 AN 或缺失组仍然未知。程序也没有证明各 ALT 在族群之间存在迁移方向。

对最高频和第二高频 ALT，另外提供：

- **presence Jaccard**：两种 ALT 达标的祖源组集合之交集/并集，仅使用共同可评价组。
- **AF profile cosine**：至少有三个共同可评价组、两个 AF 向量范数都非零时计算，各组等权，不填补缺失值。

这些指标描述祖源分布相似性；不等于基因型相关、单倍型相似或历史亲缘关系。余弦相似性还可能受两种 ALT 普遍低频、共同背景人口史等因素影响。不同组的 AN 不同，统一 AC 阈值不会自动统一发现能力；提高共同 AF 门槛和最低 AN 可用于敏感性分析，但当前代码没有实施精确的跨祖源联合下采样。

<a id="doc-docs-methods-zh--八更像哪一种当前实现的三种描述"></a>

### 八、“更像哪一种”：当前实现的三种描述

<a id="doc-docs-methods-zh--81-碱基替换类别"></a>

#### 8.1 碱基替换类别

`secondary_ref_relation` 描述第二高频 ALT 与 REF 之间属于 transition 还是 transversion；`secondary_primary_relation` 描述它与最高频 ALT 的类别关系。

这是碱基化学类别关系，不能推出该 ALT 从哪一种碱基直接演化而来。对任意三个不同 DNA 碱基，嘌呤/嘧啶组合本身已限制了可出现的替换配对，因此若后续检验这些类别的富集，需要使用匹配的碱基组成与突变机会背景。

<a id="doc-docs-methods-zh--82-已有-vep-consequence"></a>

#### 8.2 已有 VEP consequence

启用 `--vep` 后，程序读取各 ALT 的现有 consequence terms 和 gene symbols。`same_consequence_terms` 比较最高频和第二高频 ALT 的 consequence term 集合是否相同；这是所有已读取转录本注释集合的比较，不是特定转录本、同一蛋白效应或真实分子功能完全相同的证明。

`annotation_counts.tsv` 的类别来自该阈值下最高频 ALT 的注释，不能当作独立于 ALT 的位置注释。当前程序没有完成系统的 exon/intron/intergenic/cCRE 区间富集模型。

<a id="doc-docs-methods-zh--83-本地预计算标量分数"></a>

#### 8.3 本地预计算标量分数

`annotate` 按完整的 build、chrom、pos、REF、ALT 对本地分数做匹配；不调用在线预测、不自动下载分数、不进行 liftover。

对于恰有两种 observed-pass ALT、最高频 ALT 没有频率并列、且剩余理论 ALT 为 `not_listed_in_release` 的位置，可以生成配对表：

```text
anchor：最高频 observed-pass ALT
observed：另一种 observed-pass ALT
unobserved：未在该发布文件中列出的理论 ALT
```

配对输出包括 observed 与 unobserved 的分数及其算术差。failed、missing 或 below-threshold 的 ALT 不冒充 unobserved 对照；三种 ALT 均已观察的位置没有这样的未观察候选，保留注释但不构成该配对。

该模块只整理探索性分数差异，不实施条件 logistic 回归，不计算功能维度数量，也不检验平衡选择。AVI 等标量影响分数不是 pleiotropy 的直接测量；如果分数训练标签使用了 gnomAD 频率信息，再把它与同来源 occupancy/AF 联系起来，不是独立的进化验证。Atlas/AVI 的训练细节及离线资源限制见同目录 [相关说明](#doc-docs-offline-scores-zh) 和 Atlas 原文。[8]

<a id="doc-docs-methods-zh--九如何把-pleiotropy-设想转成可检验问题"></a>

### 九、如何把 pleiotropy 设想转成可检验问题

建议预先写下同时允许被数据支持或否定的假说：

> 在控制突变机会、检测规模和基因组背景后，某些多维功能作用模式，是否提高了额外等位基因被观察并达到较高频率的概率？

“影响的功能更多”可能增加某些环境中的适应收益，也可能增加不利作用和净化选择。多效性不自动等于平衡选择，低频不自动等于正在灭绝，高频也不自动等于长期保留。

作为概念模型，两个等位基因的频率变化可以近似表示为：

\[
\Delta p\propto p(1-p)(w_A-w_a).
\]

多种功能共同影响总适合度，但如果适合度差长期保持同一方向，仍可能向固定或丢失发展。要维持稳定共存，需要具体机制，例如某些频率依赖关系、杂合子优势或环境结构。即便考虑简化的杂合优势模型 \(w_{AA}=1-s,w_{Aa}=1,w_{aa}=1-t\)，内部平衡也为 \(p_A=t/(s+t)\)，不必是 50:50。这些方程用于提出问题，当前代码未估计其中的适合度参数。

因此，现阶段最有价值的产物是把候选机制分开：高突变机会是否足以解释多 ALT？多 ALT 是否主要由低频、祖源特异的变异构成？哪些区域在不同阈值、检测要求和独立数据中仍显示稳定结构？这些结果决定后续功能分析应聚焦哪里。

<a id="doc-docs-methods-zh--十建议的后续研究顺序以下尚未由当前代码自动完成"></a>

### 十、建议的后续研究顺序：以下尚未由当前代码自动完成

<a id="doc-docs-methods-zh--第一阶段让观察结构经得起数据处理差异"></a>

#### 第一阶段：让观察结构经得起数据处理差异

先报告输入版本、genomes/exomes 类型、参考版本、过滤选项、AC/AN/AF 阈值、实际染色体与检测范围。比较 AC≥1/2/5/10、较高 AN 子集、CpG/非CpG、区域质控标记排除后的结果。对排名靠前的异常窗口，先检查重复序列、比对困难、AN 差异和候选 ALT 的过滤状态。

在独立人群资源中复现时分别扫描，比较方向和结构；不能将有重叠样本或不同发布版本的 AC 相加。跨祖源结果必须同时展示检测分母，不仅展示 multi-ALT 数量。

<a id="doc-docs-methods-zh--第二阶段为形成机制建立有辨别力的模型"></a>

#### 第二阶段：为形成机制建立有辨别力的模型

若需要把“高突变机会”与“特殊留存”分开，应引入独立突变率、有限位点重复突变、人口规模变化和相应检测过程。triallelic 频谱对人口史和重复突变敏感，已有理论工作可作为方法基础。[4,5,7]

当前 LOCO 经验背景是实用的探索起点；它没有替代中性/选择人口遗传模型。正式推断中可考虑按染色体或足够长区块重抽样，以反映局部相关和模型不确定性，而不是给每个窗口套用独立位点的简单 P 值。

<a id="doc-docs-methods-zh--第三阶段检验多维功能模式"></a>

#### 第三阶段：检验多维功能模式

只有在问题明确、候选规模可控后，再整理可获得的离线分子效应向量或独立实验数据。预先定义功能广度、方向和相似性；对相关组织、轨道和输出维度做适当处理，避免把高度冗余的多个预测轨道计成多种独立生物学功能。

可使用当前导出的同位点候选表进行配对研究，但必须控制替换类型和独立突变机会，并说明未列出候选的观察局限。一个位点内共享的基因或位置变量会被配对消除，不能在 site-fixed-effect 模型里再解释这些不随候选变化的主效应。

涉及 AF 训练标签的分数可用于探索或候选排序；验证多效性与留存的关系，应优先使用不会复用目标 AF/occupancy 标签的证据。2016 年的 triallelic 研究已利用果蝇数据推断同位点非同义突变的适合度相关性，说明这一方向有理论先例，但其对象和模型不等同于本代码的人类描述性分析。[6]

<a id="doc-docs-methods-zh--第四阶段如果未来需要回答从哪一种演化而来"></a>

#### 第四阶段：如果未来需要回答“从哪一种演化而来”

需要另加可靠的祖先状态、局部单倍型/基因树、古代样本或其他时间信息，并处理祖先推断错误与重复突变。当前 gnomAD sites 汇总没有这些信息，程序不输出演化先后或来源等位基因。

同位点不同碱基在一条染色体上互斥，其频率组成和指示变量自然产生约束；不能把这种机械的负相关当作竞争或平衡选择，也不能将其包装为常规两位点 LD。

<a id="doc-docs-methods-zh--十一推荐报告中的表述"></a>

### 十一、推荐报告中的表述

可以写：

> 我们按同一核苷酸位置重组 gnomAD 发布文件中的单碱基替换，研究不同非参考等位基因在给定质量和计数阈值下的 occupancy。我们区分每个 ALT 的观察分母，未从拆分后的汇总计数推断参考等位基因频率。空间差异以合格多态位置为条件，并通过留一条常染色体的分层背景提供描述性 O/E。

不应写：

- 已从 `n_alt=2` 确认三种碱基同时存在。
- 已观察到第三次突变的时间或来源。
- 多 ALT 富集证明了多效性维持平衡选择。
- 未在发布文件出现的候选已经被自然选择消灭。
- AVI 分数或多个相关预测轨道的数量就是功能数量。
- LOCO O/E 已排除所有突变率、人口史或技术因素。

## 离线关联 AVI 与其他本地 SNV 分数

本步骤用于给已经生成的多 ALT 位点候选表补充功能预测分数。核心的等位基因占位、染色体分布、突变背景与祖源分组分析都可在没有 AVI 的情况下完成。`annotate` 只读取本地文件，按染色体、位置、REF、ALT 关联，不调用 AlphaGenome 或 Atlas API。

<a id="doc-docs-offline-scores-zh--1-为什么无需-api也无需下载整个-atlas"></a>

### 1. 为什么无需 API，也无需下载整个 Atlas

AlphaGenome Atlas 的约 90 亿条预测覆盖参考基因组上可能发生的单碱基替换；它们不代表在人群中已经观察到的 90 亿个多态性。官方所述约 1 PB 的资源包含大量分子层面的预测，而 AVI 是把多种预测汇总成的单一分数。对本项目而言，只需选择性关联 AVI 静态分数表，无需取得完整分子预测数据。[官方介绍](https://deepmind.google/blog/alphagenome-atlas-a-predictive-map-of-every-possible-dna-letter-change-in-the-human-genome/)

Ensembl 官方 AVI 插件使用本地、经 BGZF 压缩且具有 Tabix 索引的 TSV，说明离线关联已有明确的数据格式与使用路径。本项目直接读取同类文件，不要求安装或运行 VEP。[Ensembl AVI 插件](https://github.com/Ensembl/VEP_plugins/blob/release/116/AVI.pm)

这并不意味着全基因组 AVI 文件很小，也不保证一次全基因组流式读取很快。节省的是逐变异远程请求，以及与当前问题无关的原始分子预测下载。实际耗时仍取决于分数表体积、索引、候选位点分布和本地磁盘速度。

<a id="doc-docs-offline-scores-zh--2-准备本地输入"></a>

### 2. 准备本地输入

<a id="doc-docs-offline-scores-zh--已完成的扫描"></a>

#### 已完成的扫描

先按主 README 完成 `scan` 或 `run`。`annotate --dir-out` 必须指向该次扫描的输出目录，其中已有 `run.json`、完整 shard 及其完成标记。CLI 从清单获取候选，无需手工拼接文件。v3.1 新扫描默认 `--candidate-storage deferred`：第一次显式全量离线 `annotate` 时，从完整位点表和 ALT 表逐组精确重建候选到 `OUT/candidate_cache/`，不改原 shard。旧 eager 表直接复用；派生缓存按 shard 原子提交，可恢复已完成部分。

CLI 会先检查分数文件、表头、分数列及所需 tabix 索引，避免输入配置错误时先生成大型候选表；实际行内容和排序仍在流式注释时检查。

重建复制原表的 AC/AN/AF 字符串，保留 failed、missing、below-threshold 和未收录状态，不重新舍入或补零。它与 eager 输出逐行等价，但显式全量注释仍可能需要很大的候选表和磁盘。稀疏 `atlas-plan` / `atlas-query` 不经过这一全量候选表。确实需要扫描时就生成该表，可指定 `--candidate-storage eager`。

候选表针对符合主扫描条件的多 ALT 位点，列出 REF 之外的三个可能碱基。这里的 `n_alt` 是主扫描条件下观察到的非参考等位基因数，主阈值含 `AC >= 1`，并受该次扫描的 AN、AF、过滤条件和区域掩码约束。它不是已经确认包含 REF 的人群等位基因总数。扫描时的这些设置保存在运行清单中。

<a id="doc-docs-offline-scores-zh--avi-分数与索引"></a>

#### AVI 分数与索引

官方下载入口：<https://alphagenome.google/downloads>。该地址目前会跳转到 <https://deepmind.google.com/science/alphagenome/downloads>；在本次核对时，未登录访问只显示 Google 登录入口。请在官方页面按其授权与下载说明取得 AVI 文件。这里没有经过验证的匿名批量下载直链，因此不提供推测的 `wget` 地址。

以下文件名是本地路径示例，不是官方固定命名：

```text
/mnt/f/annot/alphagenome/avi_scores.tsv.gz
/mnt/f/annot/alphagenome/avi_scores.tsv.gz.tbi
```

也支持同名 `.csi` 索引。索引必须与分数文件匹配，并紧邻该文件；例如程序寻找 `avi_scores.tsv.gz.tbi`，不会寻找另一个目录里的索引。使用 Tabix 时，压缩文件必须实际采用 BGZF 格式；普通 gzip 文件改名不能替代 BGZF。没有索引的普通 gzip 文件仍可用流式后端读取。

官方六列格式按以下固定顺序解释，位置为 **1-based**：

| 列 | 含义 | 本程序对应名称 |
| --- | --- | --- |
| 1 | 染色体 | `chrom` |
| 2 | 位置 | `pos` |
| 3 | 参考碱基 | `ref` |
| 4 | 替换碱基 | `alt` |
| 5 | AVI 原始分数 | `raw_score` |
| 6 | AVI PHRED 分位数分数 | `phred` |

必须显式选择 `--score-format avi`，程序才按六列位置读取无表头文件。默认 `--score-format tsv` 要求有表头，不会自动猜测无表头文件属于 AVI。格式依据见 [Ensembl 插件的 `parse_data`](https://github.com/Ensembl/VEP_plugins/blob/release/116/AVI.pm)。

AVI 模式要求 GRCh38。其他有表头的本地分数可以声明 GRCh37 或 GRCh38，但必须与扫描清单中的基因组版本相同。`--score-build` 是用户对数据版本的明确声明；若文件没有版本元数据，软件无法仅凭坐标自动鉴别版本。程序检查可识别的版本注释，并在通用 TSV 中检查版本列；没有自动 liftOver。

<a id="doc-docs-offline-scores-zh--3-可直接使用的命令"></a>

### 3. 可直接使用的命令

以下命令在解压后的 `allele3_local` 项目根目录运行。将示例路径替换为实际文件，`--dir-out` 保持为已有扫描结果目录。

<a id="doc-docs-offline-scores-zh--有索引且已安装-pysam按区域关联"></a>

#### 有索引且已安装 pysam：按区域关联

```bash
python3 f/cli.py annotate \
  --dir-out /mnt/d/analysis/allele3/gnomad_local \
  --scores /mnt/f/annot/alphagenome/avi_scores.tsv.gz \
  --score-format avi \
  --score-column phred \
  --score-build GRCh38 \
  --score-label AVI \
  --score-version unspecified \
  --score-backend tabix
```

`--score-version unspecified` 是诚实的缺省记录。若官方文件注明版本，应把它替换为实际版本；不要把分析日期冒充模型版本。`tabix` 后端需要当前 Python 环境能 `import pysam`，并存在 `.tbi` 或 `.csi` 索引。显式要求该后端但缺少依赖或索引时，命令会报错。

<a id="doc-docs-offline-scores-zh--无索引或无-pysam自然顺序的流式关联"></a>

#### 无索引或无 pysam：自然顺序的流式关联

```bash
python3 f/cli.py annotate \
  --dir-out /mnt/d/analysis/allele3/gnomad_local \
  --scores /mnt/f/annot/alphagenome/avi_scores.tsv.gz \
  --score-format avi \
  --score-column phred \
  --score-build GRCh38 \
  --score-label AVI \
  --score-version unspecified \
  --score-backend stream
```

也可使用 `--score-backend auto`，这是默认值：当本地索引与 `pysam` 都可用时选择 Tabix，否则选择流式读取。实际选择记录在 `scores/score_annotation.json` 的 `backend` 字段中。缺少索引时，`auto` 不会自动创建索引。

要关联原始 AVI 分数，把 `--score-column phred` 改成 `--score-column raw_score`；`AVI_RAW` 和 `AVI_PHRED` 也可作为 AVI 模式下的列名别名。一次运行只选择一个分数列。同一输出目录下再次成功运行 `annotate` 会替换 `scores/` 中的三个结果文件；如需同时保留 PHRED 与原始分数结果，应先另存上一组结果。

<a id="doc-docs-offline-scores-zh--其他有表头的本地分数"></a>

#### 其他有表头的本地分数

通用 TSV 必须含染色体、位置、REF、ALT，以及所选的数值列。坐标列允许 `#Chrom` / `Chrom` / `chrom`、`Pos` / `pos` / `position`、`Ref` / `ref`、`Alt` / `alt` 等别名；所选分数列按不区分大小写匹配。文件可为普通 TSV、`.gz` 或 `.bgz`，表头之前可有以 `#` 开头的元数据注释。

例如，对列名为 `PHRED` 的已有本地 TSV：

```bash
python3 f/cli.py annotate \
  --dir-out /mnt/d/analysis/allele3/gnomad_local \
  --scores /mnt/f/annot/local_scores/snv_scores.tsv.gz \
  --score-format tsv \
  --score-column PHRED \
  --score-build GRCh38 \
  --score-label local \
  --score-version unspecified \
  --score-backend auto
```

若已有扫描使用 GRCh37，只有相同 GRCh37 版本的通用 TSV 才能用 `--score-build GRCh37` 关联。`annotate` 以既有 `run.json` 为准；给它另加 `--build GRCh37` 不会转换既有扫描坐标。

<a id="doc-docs-offline-scores-zh--4-两种后端的顺序与内存约束"></a>

### 4. 两种后端的顺序与内存约束

<a id="doc-docs-offline-scores-zh--流式后端"></a>

#### 流式后端

候选 shard 按清单顺序连接后，必须按自然染色体顺序及位置递增排列；分数表也必须遵循同一顺序。常规染色体的顺序是 `1, 2, …, 10, …, 22, X, Y, MT`，而不是字符串字典序 `1, 10, 11, …, 2`。常见 `chr` 前缀及线粒体别名会统一。同一个位置内，不要求 ALT 按字母排序。

目录扫描时，程序会自然排序各染色体输入文件。单个多染色体 VCF 若按不同的 `##contig` 顺序排列，扫描仍可成功，但其候选输出未必满足流式关联的顺序要求；这时应使用有索引的 Tabix 后端，或预先准备正确排序的输入。程序不会把全基因组分数表读进内存排序，也不会静默忽略顺序错误。

实现是有界内存的排序合并：顺序读取本地分数，保留当前位点的分数记录。即使只需少量较靠后染色体的候选，也可能需要读取大量前缀数据。验证范围是实际读取的前缀，而不是未读取的整个文件；元数据将其记录为 `streamed_prefix_through_last_candidate`。

<a id="doc-docs-offline-scores-zh--tabix-后端"></a>

#### Tabix 后端

CLI 固定采用 **1,000,000 bp** 区块，对含候选的区块调用本地 Tabix 查询，再在区块内流式匹配。它不会为每一个变异单独发起查询，也不会把整个区块的所有分数一次性装入字典。

候选中的每条染色体必须形成一个连续区段，且该染色体内的位置递增。染色体之间可以采用自然顺序或其他顺序，但不允许读完 `chr1`、再读 `chr2`、随后重返 `chr1`。每个查询区块内的分数也需按位置排序；有效 Tabix 索引的输入应满足这一条件。索引若同时包含会归一化成同一名字的 contig，例如 `1` 和 `chr1`，程序会拒绝模糊匹配。

耗时由候选覆盖的区块数和这些区块内的分数记录量决定，不能简单按候选条数估算。查询区块会完整读完以检查其中的重复与顺序问题；没有查询的区块不作完整校验。元数据将验证范围记录为 `queried_coordinate_blocks`，并记录查询次数与读到的记录数。

<a id="doc-docs-offline-scores-zh--精确关联与失败处理"></a>

#### 精确关联与失败处理

关联键为归一化后的 `CHROM, POS, REF, ALT`。仅接受 A/C/G/T 单碱基替换。程序不会交换 REF/ALT、自动反向互补、重建祖先碱基或转换组装版本。相同键的重复分数若数值相同，可合并并计数；若冲突则报错。冲突检查只覆盖该次实际读取或查询的范围。

输出先写入 `.partial` 文件，正常完成后替换正式结果。解析错误会清除本次临时文件，并保留尚未替换的既有正式结果。残留的 `.partial` 文件会阻止直接覆盖，需先确认没有另一个任务正在使用该输出目录。

<a id="doc-docs-offline-scores-zh--5-输出及缺失值的含义"></a>

### 5. 输出及缺失值的含义

三个文件写入既有输出目录的 `scores/`：

| 文件 | 内容 |
| --- | --- |
| `candidate_scores.tsv.gz` | 原候选列，加上 `local_score`、`score_status`、`score_reason` |
| `pairs.tsv.gz` | 满足严格条件的同位点“已观察到 ALT 对未列出候选”的分数差 |
| `score_annotation.json` | 输入路径、版本声明、后端、验证范围、匹配数、排除计数与解释限制 |

`score_status=available` 表示精确匹配且所选分数是有限数值；`absent` 表示没有可用分数。`score_reason` 进一步区分：

| `score_reason` | 含义 |
| --- | --- |
| `matched` | 有限数值已匹配 |
| `no_matching_record` | 实际读取或查询的数据中没有该精确变异键 |
| `missing_score_value` | 有该变异记录，但所选分数缺失 |

空字符串、`.`、`NA`、`N/A`、`null`、`none` 视为缺失，不填成 0；`NaN`、正负无穷或非数值内容会报错。分数缺失与候选在 gnomAD 中的状态属于不同维度：已观察到的 ALT 可以缺分数，未在该发布版列出的候选也可以有预测分数。

<a id="doc-docs-offline-scores-zh--哪些位点进入-pairstsvgz"></a>

#### 哪些位点进入 `pairs.tsv.gz`

配对要求同位点恰有三个候选行、三行均记为 `n_alt=2`，且不存在 `primary_tie=1`。三行必须分别对应：一个 `is_primary=1` 的 `observed_pass` 主 ALT；一个非主 `observed_pass` ALT；一个非主 `not_listed_in_release` 候选。后两者的分数均须可用。主 ALT 的分数可以缺失，它只作为配对的明确锚点。存在更多已观察到 ALT、主 ALT 并列、候选过滤失败、缺少计数或低于阈值时，不构造这一对比。

输出的方向固定为：

```text
delta_observed_minus_unobserved
    = score(非主、已观察到的 ALT) − score(未列出的候选)
```

字段里的 `unobserved` 只是对 `not_listed_in_release` 的简写。它不能改写成“自然界从未出现”“已被选择清除”或“已经灭绝”。`pairs.tsv.gz` 只有表头而没有数据行是合法结果。程序不计算 P 值，也不从分数差推断选择强度或因果关系。

<a id="doc-docs-offline-scores-zh--6-科学解释的边界"></a>

### 6. 科学解释的边界

<a id="doc-docs-offline-scores-zh--phred-与原始分数"></a>

#### PHRED 与原始分数

AVI PHRED 是全基因组替换的分位数变换。Ensembl 的说明中，PHRED 20 对应预测影响排序最靠前的约 1%；分数越高，模型预测的有害影响倾向越高。它不是“有 99% 概率致病”，也不是变异在每个组织造成的真实效应大小。原始分数与 PHRED 的尺度不同，差值不能跨尺度混用。[Ensembl AVI 分数说明](https://github.com/Ensembl/VEP_plugins/blob/release/116/AVI.pm)

这里可以做的描述是“在这一筛选和匹配方案下，已观察到的次要 ALT 的模型分数高于或低于未列出的候选”。单一分数相近不能证明两个等位基因影响相同功能，更不能证明它们来自同一个祖先分支。

<a id="doc-docs-offline-scores-zh--avi-不能独立检验本项目的频率或保留假说"></a>

#### AVI 不能独立检验本项目的频率或保留假说

Atlas 论文明确使用 gnomAD v4.1 的群体最大 filtering allele frequency 构造训练 AVI 的代理标签。因此，拿 AVI 再去解释同一类 gnomAD 频率、稀有程度或 ALT 占位，存在训练标签与待检验现象重叠的问题。[Atlas 原始论文](https://www.medrxiv.org/content/10.64898/2026.09.16.26363192v1.full)

由此得到的方法学限制是：即使观察到强相关，也不能把它当成独立证据，声称“多功能性使第三等位基因更易保留”已被验证。换一批样本或做普通的染色体留出，并不会自动消除“模型学习了频率代理目标”这一层解释问题。AVI、AVI 特征归因的数量以及受影响预测轨道的数量，也都不等于独立生物学功能的数量。

在本项目中，AVI 适合作为探索性注释与后续实验候选排序。要检验 pleiotropy 与等位基因保留的关系，需先独立定义并测量多功能性，说明标签与评分模型的训练数据关系，并在控制突变机会、检测能力、样本组成和群体历史后进行单独设计的验证。当前离线关联没有实施这些检验。

<a id="doc-docs-offline-scores-zh--未列出ref-和祖源关系"></a>

#### “未列出”、REF 和祖源关系

gnomAD 发布表中没有某个替换记录，可能与未被采到、检测能力、过滤及发布规则有关。已有记录但未通过过滤、计数缺失、或低于本次阈值的候选，均保留为独立状态，不作为 `not_listed_in_release` 对照。评估可检测机会应使用明确的 callability 定义，而不是把所有缺失位置视为可观察的 0。gnomAD v4.1 的 all-sites AN 是相关资源之一。[v4.1 发布说明](https://gnomad.broadinstitute.org/news/2024-04-gnomad-v4-1/)

REF 是组装参考碱基，不自动等于祖先、最常见或在当前样本中确实存在的等位基因。gnomAD 官方说明，不同 ALT 可因拆分后频率统计产生不同 AN。因此，不能靠任取一行 AN 再减去多个 ALT 的 AC 来恢复可靠的 REF 计数。[gnomAD 对多 ALT AN 的解释](https://discuss.gnomad.broadinstitute.org/t/discrepancies-in-an-values-for-multiallelic-sites/796)

本模块的三个候选全部是相对于同一组装 REF 构造的替换。它没有个体基因型、相位、单倍型或时间信息；不判断第三个等位基因由 REF 还是另一个 ALT 突变而来。扫描输出中的祖源分组计数和频率轮廓也只是各组的汇总描述，既不是某个变异的谱系祖先重建，也不能证明第三等位基因更“属于”某个主 ALT。AVI 的标量分数不能补足这些缺失的信息。

<a id="doc-docs-ancient-inputs-zh--身份和纳入规则"></a>

#### 身份和纳入规则

样本 ID 重复、PSAM 样本在公开表中缺失、必要列名被改写、未知 `Data source`、非有限年代都会报错。补充表中不在 PSAM 的额外样本只计数，不加入输出。现代样本按 `Data source = 1. Previously published data (modern)` 判断，**不以年龄 0 自动判断现代**。古代样本的五种官方来源类别在代码中逐项列明。

`include=1` 要求官方 unrelated 标志为 1；古代样本还需要有效大区域。如果将来提供包含精确 `IQS` 或 `Imputation quality score` 列的可追溯表格，则另外要求 IQS 为有限数且严格大于 0.9。当前公开表没有 IQS，因此不能给每个人重新计算这个阈值；程序不会用覆盖度替代 IQS，也不会凭空给人赋予 IQS。

论文上游样本 QC 使用了 IQS > 0.9 等条件；本模块是在公开、已纳入研究的样本表上应用可复核的 unrelated 标志。它不是对原始 reads 或全部上游个体质量控制的重跑。将自定义样本追加进这个格式，不会自动继承论文原始样本的质量保证。

#### 真实公开文件的核对结果

开发时实际读取了官方 PSAM、公开 MOESM3 和 qpAdm 小文件，得到：

- 按 unrelated 纳入 14,439 人，即古代 13,936 人与现代 503 人；1,900 位相关古代样本保留并标为 `include=0`。

<a id="doc-docs-ancient-inputs-zh--3-qpadm-组成表如何处理"></a>

### 3. qpAdm 组成表如何处理

程序只接受一份明确的官方基底：

| 模型 | 必需比例列 | 输出比例列 |
| --- | --- | --- |
| `3way` | `WHG EEF STEPPE` | `qpadm_whg qpadm_eef qpadm_steppe` |
| `4way` | `ANF EHG WHG ICR` | `qpadm_anf qpadm_ehg qpadm_whg qpadm_icr` |

还需 `Genetic version identifier`、`Left or Right`、`pval` 和各分量对应 `.SE` 列。原比例、SE 和 p 值按原字符串保留。代码不把负值改为 0、不把大于 1 改为 1、不重新归一化，也不把最大分量变成一个确定祖源标签。

`qpadm_valid=1` 要求：p 值有限且 `>0.05`、所有比例有限且在 `[0,1]`、`Left or Right` 精确为 `No`。`Yes` 标识参与源/外群集合的角色，不能机械地当成常规目标样本估计。缺行、源角色、p 值低或比例越界只影响组成诊断，**不改变其作为合格地理轨迹样本的 include**。输出另外保留 `qpadm_left_or_right`、`qpadm_model`、`qpadm_pval` 和 `qpadm_*_se`。

论文补充方法的祖源频率推断也使用通过 p 值检验的模型。这里再加范围和角色检查，是为了避免把不适合解释的组成系数当成个体真实比例。3way 与 4way 的参考源集合不同，即使都有 `WHG`，也不能认为数值可逐人直接交换。基于大区域的标准化仍可能受区域内部祖源变化影响；组成诊断并不会消除这一问题。

<a id="doc-docs-ancient-inputs-zh--4-97m5238m-与第三等位基因"></a>

### 4. 9.7M、52.38M 与第三等位基因

论文报告 imputation 后约 52.38M 位点，经 QC 后分析 9,739,624 位点，包括 8,074,573 SNP 和 1,665,051 indel。论文与 README 的总 imputed 位点数存在 1 行差异（52,382,872 与 52,382,873）；实际程序应审计本地 PVAR 行数，不能把这两个文字数字的差异当成生物学发现。

参考面板源于 2,504 位 unrelated 1000 Genomes 个体，并限制为通过 gnomAD v2.1.1 QC 的双等位位点。GLIMPSE v1.0.0 处理双等位常染色体位点；研究 HQ 筛选还有现代面板 MAF、capture/shotgun INFO、批次一致性等要求。因此：

1. 面板中的一个 `REF/ALT` 记录只提供这一对碱基的测定。
2. gnomAD 同位点发现另一个 ALT，而古代 PVAR 没有这个 ALT，应标为 **not represented / unassayed**；不能把每个古代人的第三碱基 dosage 都填 0。
3. `0/1/2` 是同一个 ALT 的拷贝数（或期望 dosage），不是三个不同等位基因。
4. 这个数据适合研究“现代多等位位点中，面板所测定那一个 ALT 的时间轨迹”，不适合估计所有第三碱基第一次出现的时间或完整灭绝率。

研究对 indel 的 genotype likelihood 在 imputation 时设为缺失，令它们完全依赖现代参考单倍型。因而以 SNV 为主的精确匹配更容易解释；若加入 indel，需要明确规范化、坐标和参考序列核对，并在结果中单独标识依赖 imputation 的解释限制。

<a id="doc-docs-ancient-inputs-zh--5-pgenbcf-与-pseudo-haploid-数据不能混用"></a>

### 5. PGEN、BCF 与 pseudo-haploid 数据不能混用

官方 BCF 说明含有 phased imputed `GT`、dosage `DS`、posterior `GP`；只在有 reads 覆盖时提供 `PL`/`AD`。不能假定转换后的 PGEN 一定保留所有这些字段。先用所安装 PLINK2 的 `--pgen-info` 检查，再区分 hardcall 和 dosage；下游输出会记录读取模式。

数据发布还包括另一个非 imputed 1240k TGENO 产品。其多数古代样本是随机 read 形成的 pseudo-haploid 观测，部分高覆盖和现代样本则是 diploid。它与本项目读取的 imputed PGEN 不同，不应把一个 pseudo-haploid 观测误当成两个独立观测染色体。

<a id="doc-docs-ancient-inputs-zh--6-选择统计的方向与边界"></a>

### 6. 选择统计的方向与边界

实际选择统计头部为：

```text
CHROM POS REF ALT ANC ID RSID AF S SE X P_X POSTERIOR FDR CHI2_BE FILTER
```

坐标为 GRCh37。`S` 是 **ALT 的选择系数**；`ANC` 才是祖先状态注释，并可能缺失，不能默认 REF 就是祖先。论文时间变量为 `t = -BP/(2×29)`，因此正 `S` 表示模型中 ALT 朝现代方向受正选择，负 `S` 表示相反方向。迁移和祖源组成变化可能令未经校正的分箱频率不单调。

`X` 是已作研究校准的统计量，不能再次除以论文的膨胀校准常数。`POSTERIOR` 与 `FDR` 也不是简单互补。`AF` 头部说明是 ALT 频率，不能未经核对便称为“现代 EUR 频率”。低频警告应保留。

本项目的分箱计数和固定组成标准化是描述性结果；它们不复制原论文的亲缘/祖源随机效应、时间分层、LOCO 校正和经验校准。不能用几条分箱线性回归替代论文选择模型，也不能把不显著直接解释为中性或平衡选择。方向选择信号、保留第三等位基因、以及 pleiotropy 是不同概念；需要独立的功能广度定义与控制混杂才能检验用户的科学假说。

<a id="doc-docs-ancient-inputs-zh--7-数据验证与测试范围"></a>

### 7. 数据验证与测试范围

自动测试覆盖精确 ID 对齐、全 PSAM 保留、相关个体标记、不能用年龄判断现代、明确 IQS、错误列名/日期/来源、重复 ID、qpAdm 模型混用、负比例不被剪裁及输入失败保护已有输出。另用公开真实 XLSX、PSAM、3way/4way 小文件作集成核对。

没有在开发环境下载完整 52M PGEN/PVAR 或 9.7M 选择统计，也没有替用户运行全基因组 PCA；真实大文件的位点计数、磁盘和执行时间须由本地运行日志报告。测试结果不意味着完整数据的覆盖、批次结构或 imputation 误差已经重新评估。

## 古代时间轨迹：研究定义、实现与解释边界

本文说明 `f/trajectory.py` 的实际行为。新增模块把现代 gnomAD 多 ALT 位点与古代面板中**确实表示的同一 ALT**接起来，输出描述性的频率时间轨迹和可选固定分层标准化。它不重新估计选择系数，不把未检测到的第三 ALT 填成零，也不把时间相关性解释为自然选择的直接证据。

本文没有报告真实古代数据的新发现。程序测试使用了人工构造的小例子与小型 PGEN 文件。

<a id="doc-docs-ancient-trajectory-zh--1-研究单位是具体等位基因"></a>

### 1. 研究单位是具体等位基因

轨迹的键为 `GRCh37:chrom:pos:ref:alt`，另保留 `variant_id` 与原始 `pvar_index`。同一坐标的 A→G 与 A→T 是两个研究单位；它们不能共享计数或选择系数。

本版只接受常染色体 1–22、双倍体、A/C/G/T 单碱基替换。输入的 `pos` 为 1-based。来自 GRCh38 的 gnomAD 位点必须在上游完成坐标转换、链方向转换和目标参考序列核验，再与 GRCh37 PVAR 对齐。不能只按 rsID 或染色体位置匹配；REF 也不自动代表祖先或主要等位基因。

古代研究中的 imputation 参考面板限制了可表示的变异集合。因此第三 ALT 不在 PVAR 中时，首先表示该 ALT 没有被此面板表示；即使同位点另一个 ALT 有完整的 imputed GT，也不能推断第三 ALT 的古代频率为零。[1]

| 输入状态 | 本模块处理 | 允许的解释 |
|---|---|---|
| `assayed_pass` | 读取指定 PGEN 行，按可用 GT/DS 聚合 | 面板中此 ALT 的描述性估计 |
| `not_in_high_quality` | 不读取基因型，只输出 availability | 未进入本次高质量变异集合 |
| `not_represented_in_panel` | 不读取基因型，不输出零轨迹 | 此 ALT 未被当前面板表示 |
| `represented_multiallelic_unsupported` | 保留状态，不读取该多 ALT 记录 | 面板实际表示了此 ALT，但本二等位读取适配器不支持；不能称为未检测到 |
| 已表示、某时间箱无有效调用 | `AN=0, AF=.` | 无可估计频率 |
| 已表示、某时间箱有有效调用但 ALT 总数为零 | `AN>0, AF=0` | 该二等位面板模型下的零估计 |

最后一种情况仍不能证明该位点的所有真实碱基状态都已被完整检测。二等位 imputation 不会自动发现其参考面板之外的第三状态。

<a id="doc-docs-ancient-trajectory-zh--2-样本-qc-与时间表"></a>

### 2. 样本 QC 与时间表

`sample_metadata.tsv` 的必需列为：

```text
sample_id    cohort    age_bp    include    stratum
```

这些是制表符分隔列，不是用空格分隔的自由文本。

- `sample_id` 必须与 PSAM 的 IID 唯一对应。模块要求 metadata 与 PSAM 的 ID 集合完全一致；缺失、重复或额外 ID 都会报错。metadata 可以改变行序，程序按 ID 恢复到 PSAM 顺序。
- `cohort` 必须是 `ancient` 或 `modern`。程序不会把 `age_bp=0` 自动视为现代人。
- `include` 必须是 `0/1`，表达上游完成的样本筛选决定。被排除的样本保留在表中，以便审计。
- 被纳入的古代样本必须有有限、非负的 `age_bp`。时间基准必须由 metadata 制备步骤明确；模块不会把 BCE、CE 或未经校准的 radiocarbon 年自动转换为 BP。
- 被纳入的样本必须有预先声明的 `stratum`，例如论文提供的地理分组。模块不按每个 SNP 的结果重新划分样本。

论文方法对 imputation 质量、重复/近亲及批次差异进行了处理；`NoQC` 文件名本身不能保证已经满足这些条件。`HighQualityVariants.tsv` 是变异集合，不能替代样本 QC。这里沿用上游 `include`，不会因为公开表缺少 IQS 而臆造 IQS 或自动删除所有缺失 IQS 的样本。[1]

`sample_inclusion.tsv` 将每个 PSAM 样本标记为：

- `included`：进入当前时间范围或现代端点。
- `metadata_excluded`：上游 `include=0`。
- `outside_time_range`：已纳入的古代样本，但年龄不在本次时间边界内。

默认时间箱为 `[0,2000)`、`[2000,4000)`、`[4000,6000)`、`[6000,8000)`、`[8000,10000]`。最后一个箱包含 10000；更早样本不会悄悄塞进最后一个箱。现代样本作为独立 `modern` 端点，始终不混入最年轻的古代时间箱。

<a id="doc-docs-ancient-trajectory-zh--3-pgen-读取与原始索引"></a>

### 3. PGEN 读取与原始索引

公开函数为：

```python
sample_ids, variants = iter_pgen_variants(
    pgen_path,
    psam_path,
    selected_variants_path,
    count_kind="hardcall",
)
```

`selected_variants_path` 是 TSV，至少包含：

```text
variant_id    pvar_index    chrom    pos    ref    alt    status
```

`pvar_index` 是**完整原始 PVAR 的数据行序号，从 0 开始，不含表头**。它不是筛选后的行号，不是 SNP 坐标，也不是 variant ID。未表示的 ALT 或已表示但不支持读取的多 ALT 记录用 `.`；可读取的已表示二等位 ALT 必须有非负索引。程序不接受把同一原始 PVAR 行重复分配给两个不同目标；这个读取适配器针对每行一个 ALT 的原始二等位面板。

PGEN 不存储本次研究需要核对的核苷酸标签，因此上游必须确认选中行的 REF/ALT 与原始 PVAR 完全一致。轨迹读取器以 `allele_idx=1` 明确读取该行第一个 ALT，不进行按频率换向或参考/替代交换。

程序使用已核验的官方 Python API：[2]

```python
reader = pgenlib.PgenReader(path_as_bytes, raw_sample_ct=len(sample_ids))
reader.read(original_index, int8_buffer, allele_idx=1)
# 只有显式 count_kind="dosage" 时：
reader.read_dosages(original_index, float64_buffer, allele_idx=1)
```

两种 API 均将缺失值返回为 `-9`，适配器将它转换为 `None`。每个返回的 `dosages` 列表拥有独立内容，保持完整 PSAM 顺序。目标数量可以很少；读取器按原始行号定位读取，不先导出整个 15,000 多人的全基因组矩阵。

依赖采用延迟导入；仅聚合标准化的 Python 输入时不需要 pgenlib。读取 PGEN 时安装：

```bash
python -m pip install numpy pgenlib
```

缺少 `read_dosages` 方法时，明确选择 dosage 的操作会报错，不会自动退回 hardcall。若调用方提前停止迭代，应执行 `variants.close()`，及时关闭 PGEN 文件。

<a id="doc-docs-ancient-trajectory-zh--4-hardcalldosage-与不确定性"></a>

### 4. Hardcall、dosage 与不确定性

默认 `count_kind="hardcall"`，只读取并接受 0、1、2 与缺失；不宣称恢复了原始 genotype likelihood 或 posterior。

对于 hardcall：

\[
AC_{vtg}=\sum_{i\in(t,g),\,GT_i\ne missing} GT_{vi},\qquad
AN_{vtg}=2n_{vtg},\qquad
\widehat p_{vtg}=AC_{vtg}/AN_{vtg}.
\]

对于显式选择的 dosage 模式：

\[
expected\_AC_{vtg}=\sum_{i\in(t,g),\,DS_i\ne missing} DS_{vi},\qquad
\widehat p_{vtg}=expected\_AC_{vtg}/(2n_{vtg}).
\]

`n` 是该变异在该时间箱、分层中非缺失的个体数。`n_eligible` 则是 metadata 中本来应该进入该箱的样本数；`call_rate=n/n_eligible`。缺失调用不当作参考基因型，不进入 `AN`。

`ac` 与 `expected_ac` 分列输出：hardcall 行只填写 `ac`；dosage 行只填写 `expected_ac`。不存在有效调用时频率为 `.`。较低样本数的原始箱仍保留描述性频率与计数，但标为 `bin_status=below_min_samples`，避免隐藏已观察到的数据。默认 `min_samples=10`。

**`read_dosages` 成功不证明文件保存了完整 posterior dosages。** 官方读取方法也可以在没有显式 dosage 的地方使用 hardcall。模块记录 `dosage_evidence`：

- `hardcalls_only`：默认 hardcall 读取。
- `fractional_values_present`：所读记录存在非整数值，说明这不是纯整数 hardcall 输出。
- `integer_only_storage_unverified`：输出都是整数；不能据此判断是否保存了显式 DS。
- `all_missing`：该记录输出均缺失。

`count_kind=dosage` 表示选择了 dosage 读取路径；不能将 `integer_only_storage_unverified` 描述为已验证的完整 imputation posterior。PGEN 本身不能保留 GP 三元概率、read depth 或完整逐调用质量信息；若需要基于 GP 的过滤、完整不确定性传播或重新调用第三 ALT，必须回到保留这些信息的原始数据。[3]

本版没有给这些频率附加朴素二项分布 P 值或选择显著性，也不通过 DS 倒推出 GP。所提供时间点的测年不确定性与 imputation 不确定性没有被传播。

<a id="doc-docs-ancient-trajectory-zh--5-祖源与采样构成分层与固定权重"></a>

### 5. 祖源与采样构成：分层与固定权重

默认输出两组轨迹：`group_type=raw_all` 是整体，`group_type=by_stratum` 是各预先声明分层。时间变化可能来自每个祖源内的变化，也可能来自祖源构成改变，二者不能仅凭总体曲线区分。

可选 `weights_path` 指定固定参照构成：

```text
stratum    weight
North      0.5
South      0.5
```

权重必须有限、非负，合计为 1；0 权重不参与计算。对每个时间箱：

\[
\widehat p_t^{std}=\sum_g w_g\widehat p_{tg}.
\]

只有**每个正权重分层**在该变异、该箱都至少有 `min_samples` 个非缺失调用时，才输出标准化频率。缺乏支持时，`af_standardized=.`，同时列出 `missing_strata` 和 `supported_weight`。程序不会删除缺失分层后重新归一化剩余权重。现代端点也使用同样的支持规则；不能因为现代地理/祖源标注不足而自动假装可比。

这样控制的是用户指定的可观察分层构成，不能自动消除细尺度人口结构、迁移、未观测批次或祖源估计误差。没有指定权重时，`trajectory_standardized.tsv` 只有表头，manifest 明确标记 `not_requested`。

`sample_bin_composition.tsv` 另外记录分箱样本数、古代平均年龄与地区/批次来源计数。对于上游适配器给出的 qpAdm：

- 只在 `qpadm_valid=1` 且 `qpadm_model` 为 `3way` 或 `4way` 时汇总相应比例。
- 3way 使用 WHG、EEF、Steppe；4way 使用 ANF、EHG、WHG、ICR。
- 分模型输出均值和有效样本数，不把 3way 与 4way 混合。
- SE、模型 P 值和 valid 标记不是祖源分量，不参加比例均值。
- `qpadm_valid=1` 若与不合法比例明显冲突，程序报错；不会默默裁剪负数、越界值或重新归一化。

本模块不将 qpAdm 组成描述伪称为原论文的遗传结构调整。

<a id="doc-docs-ancient-trajectory-zh--6-与-selection-summary-的正确连接"></a>

### 6. 与 selection summary 的正确连接

selection summary 的连接属于上游等位基因协调步骤，不由本聚合模块推测。其结果可以与本模块的精确变异键连接，但必须保留原论文的效应等位基因、比较等位基因、参数单位和对齐状态。

原论文作者的方法使用遗传相似性矩阵进入 GLMM；作者公开实现接受 ALT/REF count 与随机效应结构。[4] 这里的总体或分层分箱曲线没有重建该模型。公开 ancient＋EUR1KG 数据也不自动等同于作者使用的全部现代对照数据。

三条解释规则必须保持：

1. 只有完整等位基因对比匹配的 summary 才能注释该 ALT。
2. 同坐标其他 ALT 的 (s\) 不能复制给第三 ALT；相邻连锁位点的选择证据也不是第三 ALT 的直接效应。
3. 方向选择的证据不等同于平衡选择。长期多态、频率接近一半、多 ALT 或平坦轨迹都需要独立的模型比较和控制来解释。

对 pleiotropy 的后续研究可先提出可检验的关联：在突变上下文、现代频率、检测机会、祖源和面板可表示性相近时，多 ALT 位点是否更常有已发表的方向选择背景，以及同位点 ALT 的预先指定功能向量是否更相似或更分化。这里仍有现代频率筛选和古代参考面板筛选造成的 ascertainment，不能将关联直接解释成维持多态的机制。

<a id="doc-docs-ancient-trajectory-zh--7-完整调用与输出"></a>

### 7. 完整调用与输出

```python
from trajectory import iter_pgen_variants, aggregate_trajectories

sample_ids, variants = iter_pgen_variants(
    "ancient_and_eur1kg.pgen",
    "ancient_and_eur1kg.psam",
    "selected_ancient_variants.tsv",
    count_kind="hardcall",
)
manifest = aggregate_trajectories(
    variants,
    sample_ids,
    "sample_metadata.tsv",
    "trajectory_output",
    bins=(0, 2000, 4000, 6000, 8000, 10000),
    min_samples=10,
    weights_path=None,
)
```

| 文件 | 内容 |
|---|---|
| `trajectory_bins.tsv` | 每 ALT、时间箱、整体或分层的计数、分母、频率、样本量状态 |
| `trajectory_standardized.tsv` | 固定权重标准化、完整支持状态与缺失分层 |
| `sample_bin_composition.tsv` | genotype 无关的样本构成诊断 |
| `sample_inclusion.tsv` | 每个 PSAM 样本的最终纳入状态 |
| `allele_availability.tsv` | 所有目标 ALT 的可用性；未表示或 QC 排除不会消失在报告中 |
| `trajectory_manifest.json` | 输入指纹、样本顺序指纹、计数模式、时间边界、来源、参数和解释限制 |

聚合只保留样本表、当前变异向量及少量分箱统计，避免整个 genotype matrix 常驻内存。文件经完整验证后提交；出错时清理本次临时文件。已有同名结果时拒绝覆盖，应使用新的输出目录。

下文的 `allele3.sh pca-plan/pca-time` 是保留的集成接口，共用同一套计算函数。

本模块生成离线 PLINK2 计划，以及一个可以离线打开的交互 HTML。每个点都是元数据中 `include=1` 且具有真实 PCA 坐标的个体。PC1、PC2 来自一套固定的背景标记和基底；BP 年代只作为第三个坐标，目标 ALT 剂量只作为颜色叠加。

不能分别对每个年代重新做 PCA 再把结果叠起来。独立 PCA 的轴可以任意旋转或翻转，尺度也可能不同，肉眼看到的“运动”未必是遗传变化。也不能把年代加入计算 PCA 的矩阵，否则纵向时间信息会进入横向坐标本身。

<a id="doc-docs-pca-time-zh--1-两种固定基底"></a>

### 1. 两种固定基底

| 参数 | 基底训练样本 | 投影样本 | 主要解释限制 |
| --- | --- | --- | --- |
| `joint_balanced`，默认 | unrelated 合格个体，按 cohort × 大区域 × 2,000 年时间组，每组最多 200 人 | 全部 `include=1` 古代与现代个体 | 是“限制大组占比”，不是强制各组人数完全相等；稀少时期仍有较少样本 |
| `modern_projection` | 全部 `include=1` 现代个体 | 同样包含全部合格古代与现代个体 | 基底可能无法充分表达古代变异；投影收缩可能令部分古代个体看起来靠近中心 |

抽样以固定 seed 和 sample ID 的 SHA-256 排序决定，可重复。不会只选择某个目标等位基因携带者作为基底。只使用正式元数据的 cohort，不以 `age_bp=0` 判断现代。基底至少需要 `max(50, PC 数+1)` 人；默认 10 个 PC，HTML 显示前两个。

<a id="doc-docs-pca-time-zh--为什么基底样本也重新投影"></a>

#### 为什么基底样本也重新投影

PLINK2 的原始 `.eigenvec` 与 `--score` 投影分数并非相同单位。官方文档说明，两者的换算涉及 eigenvalue 的平方根，直接叠加会造成尺度混乱。

本流程对 **所有人，包括训练基底样本** 统一运行同一条 `--score ... variance-standardize` 命令，并使用同一份训练基底 `.acount`。HTML 默认读这个共同 `.sscore` 的 `PC1_AVG`、`PC2_AVG`，所以所有点处于同一投影尺度。不会把训练样本的 `.eigenvec` 与其余人的 `.sscore` 混在一起。当前使用训练频率作缺失均值填充，与 `--pca approx` 的均值填充行为一致。

如果用户已经有可信的共享 PCA 坐标，renderer 也接受带 `IID PC1 PC2` 的 `.eigenvec`，或只有 `PC1_SUM PC2_SUM` 的共同 `.sscore`。必须覆盖每一个 `include=1` 的样本；重复 ID、未知 ID、缺失坐标、PC1/PC2 混用 AVG/SUM 都会报错。它无法从一个坐标文件本身证明 PCA 的科学基底，外部文件需提供可追溯的训练样本和标记信息。

官方说明：<https://www.cog-genomics.org/plink/2.0/score#pca_projection>；<https://www.cog-genomics.org/plink/2.0/strat>

<a id="doc-docs-pca-time-zh--2-背景标记与可审阅执行计划"></a>

### 2. 背景标记与可审阅执行计划

输入是公开的原始 PGEN/PVAR/PSAM 前缀、规范样本元数据和 `HighQualityVariants.tsv`。当前计划固定为 **GRCh37**。程序逐行扫描 HQ 表，写出 autosomal、A/C/G/T、双等位 SNV 的 ID 列表，不在 Python 内存里保存全体 9.7M 位点。

默认排除：

- 候选目标位点及各侧 1 Mb（使用已协调至 GRCh37 的目标表）；
- Michigan Genome Analysis Wiki 明确给出的 GRCh37 长程 LD 区间表，共 24 段，包含 chr6:25–35 Mb 的 MHC 粗区间；
- 可选 `--pca-exclude-bed` 的额外 GRCh37 BED 区间。

历史长程 LD 掩码是敏感性分析预设，不保证排除所有特殊 LD。与“这些标记已经被证明中性”是不同的说法。实际写出的 `excluded_regions.GRCh37.bed` 为 0-based、半开区间，供审查和复现；上游候选选择中的 MHC 界线可能更窄，不应将两者当成同一筛选。

随后脚本执行五步：

1. 在固定基底样本上，从 HQ 背景 SNV 中应用 `--maf 0.05 --geno 0.1`，写较小的 `basis_common` PGEN。
2. 在这个基底中执行 `--indep-pairwise 200kb 1 0.1`，得到 `ld.prune.in`。
3. 从原始大 PGEN 中只提取这些 pruned 标记和全部合格样本，写 `all_pruned`。
4. 用其中固定基底样本执行 `--freq counts --pca 10 allele-wts vcols=chrom,ref,alt`（基底超过 5,000 人时增加 `approx`）。
5. 用共同 allele weights 和训练频率对全部合格样本统一打分，得到 `all.sscore`。

MAF/缺失率是在固定基底中计算；LD pruning 使用 hardcall 相关。Imputation 后的高完整度不等于高准确度，`--geno` 不能替代论文的 imputation 质量筛选。PCA 还可能显示 capture/shotgun 差异、覆盖差异、区域和亲缘结构；需用 HTML 的来源、区域和鼠标悬停信息检查。

这避免了先把全部 52M × 全部个体复制成 PCA 输入，但仍需要读取本地大文件。`basis_common` 和 `all_pruned` 可能占用数 GiB；实际大小取决于标记、样本数和 dosage 存储方式。计划阶段本身不运行 PLINK2、不联网、不作全数据性能估计。

长程 LD 来源：<https://genome.sph.umich.edu/wiki/Regions_of_high_linkage_disequilibrium_(LD)>；原理研究：<https://doi.org/10.1016/j.ajhg.2008.06.005>

### 3. CLI 示例

以下假定已经完成 `prepare-ancient` 和 `panel-index`，存在全 PSAM 的规范元数据及经过精确 PVAR 检查的目标表。在项目根目录执行，路径可按实际文件名修改。

<a id="doc-docs-pca-time-zh--只生成计划"></a>

#### 只生成计划

```bash
bash allele3.sh pca-plan \
  --out out/evolve \
  --pgen-prefix /mnt/f/gen/ancient/AncientDNA_plus_EUR1KG_AllVariants_NoQC_GRCh37_autosomes \
  --hq-variants /mnt/f/gen/ancient/HighQualityVariants.tsv \
  --metadata out/evolve/metadata/sample_metadata.tsv \
  --selected-variants out/evolve/panel/selected_variants.tsv \
  --pca-basis joint_balanced \
  --pca-maf 0.05 --pca-geno 0.1 --pca-max-per-group 200 \
  --plink2 plink2
```

查看 `out/evolve/pca/pca_plan.json`、`basis.keep`、`all.keep`、排除区间以及 `commands.sh` 后，可执行本地计划：

```bash
bash out/evolve/pca/commands.sh
```

新计划需要空的 PCA 输出目录。输入和参数完全相同的计划会校验已有计划文件再重用；输入或参数改变时，程序要求另用输出目录，避免覆盖先前分析的出处。脚本运行前检查输入的 size、mtime 和文件首尾散列，以及计划文件完整散列。大 PGEN/PVAR 未作全文件 SHA-256；请勿在执行时修改输入。完整执行后保存 `PCA_COMPLETE` 和输出 SHA-256，可验证后跳过重复计算；中断但未完成的阶段重新执行，不盲用中间文件。

<a id="doc-docs-pca-time-zh--用共同投影结果生成-html"></a>

#### 用共同投影结果生成 HTML

```bash
bash allele3.sh pca-time \
  --out out/evolve \
  --pgen-prefix /mnt/f/gen/ancient/AncientDNA_plus_EUR1KG_AllVariants_NoQC_GRCh37_autosomes \
  --metadata out/evolve/metadata/sample_metadata.tsv \
  --eigenvec out/evolve/pca/all.sscore \
  --pca-basis-label 'joint_balanced；固定HQ背景标记；全部共同投影' \
  --selected-variants out/evolve/panel/selected_variants.tsv \
  --pca-max-variants 12 \
  --count-kind hardcall \
  --html out/evolve/pca/pca_time.html
```

CLI 从目标列表生成最多 12 个目标的 `overlay_targets.tsv`，并记录选择信息；Python renderer 接口本身要求输入已经限定在 1–12 个目标，超过就报错。优先显示哪些候选是一个可审阅的选择，不代表其生物学更真实。若仅有 PCA 坐标而不读目标基因型，Python API 可省略三个 overlay 参数。

集成 `evolve --with-pca` 会明确执行本地 PLINK2 计划并生成 HTML；默认只计划，不悄悄跑大矩阵。原始 `--eigenvec` 名称也用于传入共同 `.sscore`。

<a id="doc-docs-pca-time-zh--4-html-能看见什么"></a>

### 4. HTML 能看见什么

文件内嵌 Plotly 代码和选定数据，不依赖 CDN。可以切换 3D 时间柱和 2D 时间筛选截面；两种视图使用相同 PC1/PC2 范围。时间滑条、古代/现代复选框、来源和区域筛选只改变显示点，不重新计算 PCA 或缩放坐标轴。区域颜色有独立色键，古代圆形/现代菱形仍可区分。

BP 越大越古老，因此古代点在 3D 图上方。现代样本一般在 BP=0 底部；这来自实际元数据，并非把所有 age=0 都强制归为现代。悬停可看 ID、年代、区域、来源、数据类型、capture-target 覆盖和 IQS。没有公开的 IQS 显示 `.`。

选择一个目标后，蓝→橙表示该 **ALT 的 0–2 拷贝数或 dosage**：

| 数值 | diploid hardcall 含义 |
| --- | --- |
| 0 | REF / REF |
| 1 | REF / ALT |
| 2 | ALT / ALT |

三个数值不是三个等位基因。REF 也不是自动的祖先；不得为了“看起来像演化”把最古老层强行画成 REF。若目标第三碱基有独立经过验证的 PVAR 记录，可以作为自己的 REF→ALT 对比显示；是否可测定取决于该目标的 status，不能从另一个 ALT 的拷贝数推断。没有被面板测定或个体调用缺失的值保持未知，用灰色显示，不填 0。

侧边栏按当前过滤后的非缺失个体显示 ALT 的 AC、AN=2n、AF；dosage 模式标注 expected AC。这是 **当前显示样本的描述性频率**，没有按人口比例加权，也不是总体估计或选择检验。只有真实可测定的非缺失值才进入分母。未测定目标不显示伪零频率。

gnomAD 没有本流程所需的个体 PCA 坐标，因而不会生成代表 gnomAD 个体的假点。未来若增加 gnomAD 祖源汇总，只能作为单独汇总面板，并明确其样本来源与古代个体点不同。

## legacy counts.tsv 审计：定义、分母和可解释范围

`audit_counts` 只读取分类汇总表，核对算术并生成可独立打开的离线报告。它不会重新读取 gnomAD VCF，不会修改输入，也不会从汇总表推断选择、pleiotropy 或古代等位基因轨迹。

<a id="doc-docs-counts-audit-zh--1-分类已经核对了原始-producer但表本身仍不是完整出处"></a>

### 1. 分类已经核对了原始 producer，但表本身仍不是完整出处

本模块使用已核验的 legacy `check` 语义：先保留通过 PASS 条件且 `AC > 0` 的 ALT，再按 legacy 起始坐标分组。

| 原始 CATEGORY | 已核对的定义 | 不应额外推断的内容 |
| --- | --- | --- |
| `singleton` | 仅一个保留 ALT，且该 ALT 的 AC=1 | 单凭此标签无法知道 REF 计数、AN、群体或样本量 |
| `non_singleton_biallelic` | 仅一个保留 ALT，且 AC>1 | 不能仅凭名称证明样本中同时存在 REF |
| `tri_allelic` | 两个保留 ALT | 不能自动解释成三个已经观测到的等位状态 |
| `four_plus_allelic` | 至少三个保留 ALT | 标准 A/C/G/T SNP 相对 REF 最多三个 ALT，但 REF 是否出现仍未知 |

因此图表使用 **≥2 retained ALT** 和 **≥3 retained ALT**，分别对应 `tri_allelic + four_plus_allelic`、`four_plus_allelic`。它不会把 `four_plus_allelic` 无条件改名为“四种已观测碱基”。

REF 在这里是参考标签，不是样本中存在该碱基的证据。另一方面，INDEL 分类按起始坐标聚合，没有完整依赖 FASTA 做左对齐；不同表示和锚点可能进入同一组，类别大小不能直接当作规范化后的多态状态数量。SNP 与 INDEL 应分别报告，不能把类别差异直接当作生物学功能差异。

上述语义来自对原始 producer 的核对，**不是仅凭六个表头就能证明**。若要审计另一个项目生成的同名文件，应先确认其代码采用相同定义。提供的 `counts.tsv` 本身没有 release、GRCh37/GRCh38、样本量、群体、完整阈值与原始 VCF 清单等出处元数据，报告明确保留这些未知项。

<a id="doc-docs-counts-audit-zh--2-输入api-与输出"></a>

### 2. 输入、API 与输出

输入为制表符分隔表，要求唯一列名：

```text
CHR TYPE CATEGORY COUNT TOTAL_SITES PERCENT
```

`COUNT` 和 `TOTAL_SITES` 必须是非负整数；`PERCENT` 为 0–100 的普通十进制数，可保留不同小数位。支持 `.tsv`、`.tsv.gz`、`.bgz`。chr1–22、X/Y 可带或不带 `chr` 前缀；归一化后重复的类别会报错。非标准 contig 单独保留，不放入常染色体基线。

在项目根目录可直接运行：

```python
from f.counts_audit import audit_counts

result = audit_counts(
    counts_path="/path/to/counts.tsv",
    out_dir="out/counts_review",
    make_plots=True,
)
print(result["report_path"])
print(result["manifest_path"])
print(result["qc"])
```

CLI 的 `audit-counts` 入口和集成流程的 `--counts-tsv` 选项由主命令提供，具体参数见当前 `bash allele3.sh audit-counts --help`。

生成文件：

| 文件 | 内容 |
| --- | --- |
| `counts_audit.json` | 逐组算术与百分比检查、精确定义、汇总、逐染色体结果、留一比较和解释限制 |
| `counts_summary.tsv` | 常染色体、X、Y、全部已提供 contig 的四类计数和加权比例；存在额外 contig 时另列该范围 |
| `counts_by_chromosome.tsv` | 每条标准染色体和类型的计数、比例、参考分母与描述性比例比；缺失项为 `.` |
| `counts_review.html` | 中文离线报告；如有 PNG，使用 base64 内嵌，无 CDN、脚本或字体下载 |
| `counts_review.png` | 可选的 2×2 科学图；需要 matplotlib |
| `manifest.json` | 输入 SHA-256、输出 SHA-256/大小、生成参数、模块代码散列、QC、解释限制和路径 |

返回字典包括 `manifest_path`、`report_path`、`qc`，另外有 `audit_path`、`summary_path`、`by_chromosome_path` 和可为空的 `plot_path`。

只有画图需要 matplotlib。缺少 matplotlib 时，JSON、两个 TSV 和 HTML 仍然生成，`plot_status=unavailable_matplotlib`；`make_plots=False` 则明确标为未请求。数字结果不因绘图库是否可用而变化。

<a id="doc-docs-counts-audit-zh--3-算术校验规则"></a>

### 3. 算术校验规则

对每个实际出现的 CHR/TYPE 组，必须满足：

1. 四类各出现一次，没有缺类或重复类。
2. 四行 `TOTAL_SITES` 完全一致。
3. 四类 `COUNT` 之和等于该总数。
4. 各项 `PERCENT` 与 `100 × COUNT / TOTAL_SITES` 的误差不超过显示小数精度的半单位。

例如，四位小数允许的最大舍入误差为 0.00005 个百分点；两位小数为 0.005 个百分点。各项分别舍入后，四项之和可能是 99.9999% 或 100.0001%，不应因此误报错误。代码用 Decimal 检查这些关系，机器结果保留精确误差和舍入容差。

若总数为零，四类计数也必须全为零，PERCENT 可填 0 或明确缺失标记；输出比例仍记为 NA，状态为 `zero_denominator`，不会把 0/0 解释成 0%。若整条染色体/类型未出现，状态为 `missing`，计数和比例均不补 0。这两个状态不同。

结构、分类、分母或舍入检查失败时，函数抛出 `ValueError`，不会用失败输入覆盖已有完整结果。

<a id="doc-docs-counts-audit-zh--4-加权比例和留一染色体比较"></a>

### 4. 加权比例和留一染色体比较

汇总比例为：

\[
p=100\times\frac{\sum_c N_c}{\sum_c T_c}.
\]

这里的分母是表内各染色体、各类型的 `TOTAL_SITES`。它不是可调用碱基数，也不是染色体长度。不能通过对染色体百分比做简单算术平均得到这个加权比例。

常染色体 baseline 仅使用实际提供的 chr1–22。若不完整，汇总标为 `partial_coverage` 并列出缺失染色体。X 和 Y 分开列出，不并入这个基线。表没有 Y 时，Y 显示 NA，不能据此推断 Y 没有某种变异。

常染色体的描述性比例比定义为：

\[
R_c=\frac{N_c/T_c}{\sum_{j\ne c}N_j/\sum_{j\ne c}T_j}.
\]

X/Y 的参考则是全部已提供常染色体。参考分母为零或参考比例为零时，不计算有限比值。其他非标准 contig 不自动指定比较基线。

这些比例比没有校正可调用性、祖源组成、ALT 频率、序列背景、重复表示、QC 或其他混杂。它们用来描述表中的差异，**不是统计富集检验**。本模块不计算 P 值或置信区间。

SNP 与 INDEL 的 totals 可能对应部分相同的基因组坐标。因此即使两个总数可以相加，所得数也不能未经验证地称为“唯一位置数”。

<a id="doc-docs-counts-audit-zh--5-图的解读"></a>

### 5. 图的解读

2×2 图的列为 SNP、INDEL；行为 ≥2 ALT、≥3 ALT 的条件百分比。常染色体用每列对应颜色，X/Y 用橙色菱形，在横轴上与常染色体隔开。灰色 NA 表示未提供或分母为零，没有画伪零点。

虚线是该类型已提供常染色体的加权百分比，自动标注常染色体内的最高和最低比例。四个面板各自有明确百分比纵轴；不应把不同面板同一视觉高度当成相同数值。图注解释 REF 和 INDEL 限制，不展示未经支持的选择或功能结论。

<a id="doc-docs-counts-audit-zh--6-复用覆盖与输入保护"></a>

### 6. 复用、覆盖与输入保护

输入始终只读，生成前后核对 SHA-256。输出先写临时目录，再逐个原子替换，最后发布 manifest。消费者应使用 manifest 内的输出散列确认结果一致性。

相同输入、设置、代码和绘图库版本下，已有输出散列全部匹配则直接复用。如果输入或设置变化，只替换这个模块先前 manifest 声明的自有输出。没有对应 manifest 的同名文件不会被覆盖；输出路径与输入冲突也会报错。重新运行并关闭画图时，只删除之前由本模块声明拥有的旧 PNG，不删除其他文件。

## 从现代多 ALT 到古代轨迹与分子功能：研究设计

<a id="doc-docs-evolution-design-zh--1-核心问题与研究单位"></a>

### 1. 核心问题与研究单位

本项目把问题分为三个层次：**哪些位置能观察到多个非参考碱基；这些位置已被研究的等位基因对比有怎样的历史；额外碱基的预测分子效应更接近哪一方。** 现有程序可以连接这三类证据，形成可复查的候选集；它没有证明多效性维持平衡，也没有从古代面板恢复尚未被表示的第三等位基因。本文是研究方案，不报告真实数据的新发现。

`REF` 是指定参考组装中的碱基，`ALT` 是相对于它的其他碱基。REF 不等于祖先、正常、多数或有利；ALT 编号不表示出现次序。现代扫描的 `primary_alt`、`secondary_alt` 只按各自 AC/AN 在 ALT 内排名。`n_alt=2` 说明符合条件的两个非参考碱基被观察到；如果没有一致调用集合上的 REF 计数，不能称为已证实三种碱基共同存在。

古代连接另外定义 `anchor_ref`、`anchor_alt`：它们是论文某一 REF→ALT 选择对比在 GRCh38 上的对应碱基。`extra_alt` 是现代观察到、位于这两个碱基之外的额外 ALT。参考组装变化时，anchor_ref 可能不同于 GRCh38 REF。`extra` 是相对于这一对比的标签，不是历史上的第三次突变。

同一条染色体同一位置不能同时是 A 和 G，因此同位点等位基因的互斥或负相关本身不能证明竞争淘汰。重复突变、CpG 上下文、人口历史和取样都会影响多等位观察；试图用多 ALT 数量直接识别平衡选择，会混合这些机制。人类 triallelic 的突变机制研究及其人口历史模型提供了必要的背景。[1,2]

<a id="doc-docs-evolution-design-zh--2-已有文件能提供什么"></a>

### 2. 已有文件能提供什么

Akbari 等的论文研究古代等位基因频率随时间的方向性变化，并用遗传结构模型处理相关性。公开数据中的现代部分与论文全部现代样本并不相同；下面以作者数据说明和公开补充表为准。[3,4]

| 文件 | 本项目中的作用与边界 |
|---|---|
| gnomAD sites VCF | 提供现代 ALT 的 AC、AN、祖源分组频率及位点注释；没有逐人基因型、单倍型或古代出现时间。 |
| `AncientDNA_plus_EUR1KG_AllVariants_NoQC_GRCh37_autosomes.{pgen,pvar,psam}` | 15,836 名古代个体加 503 名现代欧洲 1KG 个体的面板；包括近亲。NoQC 不能视为分析就绪。PVAR 定义核苷酸和原始行号，PSAM 定义样本顺序。 |
| `HighQualityVariants.tsv` | 作者通过变异 QC 的集合，含 SNP 与 indel；本版再限制为常染色体 SNV。它不能替代样本筛选或逐调用质量控制。 |
| `Selection_Summary_Statistics_01OCT2025.tsv.gz` | 提供具体 GRCh37 REF→ALT 对比的 S、SE、POSTERIOR、FILTER 等。`AF` 保留为 `selection_pooled_af`，不能冒充现代频率或某个古代时间点。 |
| 公开 `41586_2026_10358_MOESM3_ESM.xlsx` | 已可取得所需样本 ID、以 1950 年为基准的 BP 年龄、宽地理分区、无近亲标记、来源和覆盖度。无需等待封存的完整考古元数据，也不因公开表缺少 IQS 而虚构该值。 |
| 3way / 4way qpAdm 表 | 分别描述 WHG/EEF/STEPPE 或 ANF/EHG/WHG/ICR 组成。两套基底不能混为同一组比例；模型适配性和比例不确定性需要保留。 |
| 古代 imputed BCF 与 CSI | 可补充 GP、DS、PL、AD，适于评估已表示等位基因的调用与填补不确定性。若记录的模型只有 REF/ALT，这些字段不会自动恢复未建模的第三状态。 |

作者公开的二等位 imputation 参考面板决定哪些变异有机会进入分析。某个 extra 不在 PVAR 中，首先是**未被该面板表示**，不能解释为古代不存在或频率为零。多 ALT PVAR 记录若超出当前读取器支持范围，也单列为“已表示但不支持读取”，不会当作缺失于面板。[3,4]

gnomAD 拆分多等位记录时的 downcoding 可造成同位点不同 ALT 的 AN 不同。每个 ALT 必须保留自己的分母；即使 AN 数字相等，也不足以证明调用集合相同。因此当前程序不由 `1−ΣALT_AF` 重建 REF 频率。all-sites AN 有助于定义可检测分母，但不能直接替换 split-ALT 的 AN 并宣称已恢复完整多等位联合计数。[5,6]

<a id="doc-docs-evolution-design-zh--3-连接前先固定坐标碱基和效应方向"></a>

### 3. 连接前先固定坐标、碱基和效应方向

需要与输入一致的 **GRCh37 FASTA、GRCh38 FASTA、各自索引及双向 chain**。GRCh37 应核对作者 hs37d5 坐标和参考碱基；已有 GRCh38 序列不能代替这一步。程序要求唯一映射、往返位置一致，核对两端参考碱基，负链时互补所有相关碱基；歧义映射和参考不符保留拒绝原因。不能只按位置或 rsID 连接。

v3.1 的默认 `selection-first` 先索引全部论文 SNV 坐标，按原始现代 build 做精确位置交集，再对命中位置执行上述完整检查；它不按选择强度、频率或 FILTER 做前置候选裁剪。GRCh37 现代输入先直接匹配坐标，再在命中位置检查双向链。与原 `modern-first` 的有效 allele-contrast 多重集合相同，映射 QC 范围和行顺序不同；新 manifest 明确区分这些范围。变更只减少无关位置的完整参考验证及大型现代 JSON 索引，不改变选择系数方向和 extra 定义。

选择系数仅属于完整匹配的 anchor 对比。依照本流程采用的作者方向约定，S>0 时 anchor_alt 是估计向现代增加的一方，S<0 时为 anchor_ref；S 的符号不是“突变一定有害或有益”的标签。不能把 anchor 的 S 复制给 extra，也不能因为 extra 的功能更接近增加方，就给它赋予相同 S。论文的 ANC 可用于带来源的祖先注释，但 REF 或最早观测样本都不能单独确定突变起源。

PGEN 读取使用**未筛选完整 PVAR 的零基数据行号**，并明确读取该行 ALT。基因型顺序按 PSAM 与元数据 ID 对齐。现代端点来自公共 EUR1KG 的实际计数；gnomAD 全体、gnomAD 祖源分组、EUR1KG、selection pooled AF 始终分别命名，不能串成一条未经协调的时间曲线。

<a id="doc-docs-evolution-design-zh--4-当前可检验的假说及条件范围"></a>

### 4. 当前可检验的假说及条件范围

<a id="doc-docs-evolution-design-zh--41-现代分布观察机会能解释多少差异"></a>

#### 4.1 现代分布：观察机会能解释多少差异

第一个描述问题是：在至少观察到一个合格 ALT 的位置中，观察到 ≥2 ALT 的比例如何随染色体、窗口和上下文变化？研究量为 `P(n_alt≥2 | n_alt≥1, 上下文, 频率, 检测条件)`。主扫描比较多个 AC 阈值，并按上下文、主要 ALT 替换、AF 档及 AN 档建立留出染色体背景。它估计的是条件观察概率，不是真实突变率。高于背景的 O/E 是待解释的残差，不能直接命名为选择信号；仅一条染色体或局部区域时不能伪造跨染色体训练期望。

<a id="doc-docs-evolution-design-zh--42-古代选择背景与额外-alt-的功能关系"></a>

#### 4.2 古代选择背景与额外 ALT 的功能关系

当前候选总体是“**现代多 ALT 位点与已发表精确选择对比的交集**”。默认强信号为 POSTERIOR≥0.99，弱信号为≤0.5，后者并未被证明中性。两组都在每个 anchor 对比内按同一规则选择 AC 最高的 extra；默认要求 extra AC≥5，并排除指定复杂区域与 MHC。强信号每个物理邻近区块保留一个，再在不同区块中匹配弱信号。

匹配条件包括规范化上下文、selection pooled MAF 档、extra 的现代 AF/AN 档，以及编码相关注释档；无注释单列为 unknown。匹配在查看功能结果之前完成，未匹配者明确保留。物理区块并非实际 LD 分块。已匹配 extra AF 的候选对不能再用来检验“强选择组 extra AF 是否更高”。

可预先定义功能结局 C 为 extra 接近估计增加方的程度，以配对差值 `ΔC=C强−C弱` 为研究量；在预定义匹配总体中，原假设为 `H0:E(ΔC)=0`，备择假设可预先声明为双侧差异或有方向的增加。当前区间、符号翻转检验及多重校正只作探索性汇总；观察性匹配并不保证组别可交换或区块独立。

**这个设计不能回答“方向选择位点是否更容易产生第三 ALT”。** 交集中的所有位点已经具有多个现代 ALT，没有合适的单 ALT 对照。要检验全局富集，必须另建包含单 ALT、多个 ALT 及可检测性信息的合格位点总体，并在相同取样、祖源、突变机会及质量条件下估计关联；还要区分“突变产生”与“产生后存留并被发现”。

<a id="doc-docs-evolution-design-zh--5-时间轨迹与-pca时间分别回答什么"></a>

### 5. 时间轨迹与 PCA×时间分别回答什么

轨迹默认覆盖过去一万年，每两千年一箱；现代样本是独立端点。Hardcall 的 `AC=ΣGT`、`AN=2×非缺失人数`；显式 dosage 模式输出 `expected_AC=ΣDS`。缺失调用不作 REF，AN=0 时 AF 缺失；只有已表示且有有效调用时，零 AC 才可报告为该面板下的零估计。公开 PGEN 不保留完整 GP；读取 dosage 成功也不证明每条记录存有原始连续 DS。[7]

同时输出总体、地区分层、样本量、调用率和 qpAdm 构成。总体变化可能完全由迁移或取样构成变化造成。可提供固定权重，计算 `p标准化(t)=Σw地区×p(t,地区)`；任一正权重地区缺少足够调用时输出缺失，不删掉它再重分配权重。该方法只控制指定分层，不能替代论文的遗传结构 GLMM，也未传播测年与填补误差。

PCA 使用背景常染色体 SNP，过滤 MAF、缺失率并进行 LD pruning，排除目标附近、MHC 和长 LD 区域。默认参考基底对年代×地区×队列各组限制人数，并不保证各组权重相等；可另用现代样本拟合，作为敏感性分析。**所有绘图样本使用同一套载荷、频率标准化及投影分数单位**，不能每个年代重新拟合 PCA 再把位置连接起来。[8]

PC1、PC2 表示这套基底下的遗传结构；年龄作为第三轴或显示窗口，目标 ALT 的 0/1/2 剂量只是颜色叠层，绝不是三种等位基因。可以观察携带者是否集中于某些遗传背景、其分布是否随时期改变；不能把点云运动当作一个人群的谱系轨迹，也不能把 PC 位移直接解释成选择。现代基底可能漏掉古代差异，投影可能收缩；覆盖度、capture/shotgun 来源、填补质量和地区都应切换检查。未表示 extra 的叠层必须显示不可用；确有合格精确记录的 extra 则可以展示。

<a id="doc-docs-evolution-design-zh--6-分子效应向量与-pleiotropy-假说"></a>

### 6. 分子效应向量与 pleiotropy 假说

少量 Atlas 查询用于比较同位点碱基的预测分子响应。必须固定模型、scorer、窗口、组织/细胞面板和精确特征轴，保存原始有符号分数与缓存来源；不同单位的 scorer 分开分析。相同特征数不足以证明轴相同。GRCh38 REF 的零向量仅表示“相对参考序列的效应差为零”，不表示正常、祖先或绝对表达为零。参考组装变化时，两个 ancient anchor 都可能需要相对于 GRCh38 REF 的预测。

令增加方与减少方的向量为 `v+`、`v−`，额外碱基为 `ve`，可定义 `C=(||ve−v−||−||ve−v+||)/(||ve−v−||+||ve−v+||)`：C>0 表示在该面板和距离定义下更接近增加方。另报告投影方向与正交残差，以区分沿相同响应方向变化与出现不同响应。全零方向、缺轴或非有限值保留不可估计状态。弱信号 anchor 的“增加方”方向本身也较不确定，必须作方向稳定性敏感性分析。

受影响轨道数只是**预测响应广度**，依赖阈值、轨道冗余、组织数量和模型能力，不能直接当作独立性状数量，更不能当作适合度。Atlas AVI 的训练使用 gnomAD 频率代理标签，因此用 AVI 与同源频率关联，不能称为独立验证。[9]

“多效性有助于维持多态”可改为机制假说：同一等位基因在不同性状、性别、年龄或环境中存在适合度收益与代价，并在特定遗传和生态条件下阻止固定。但多效性也可能加强净化选择；拮抗效应本身不保证稳定平衡。确认性设计应以明确的人口历史、迁移、漂变及检测模型为背景，对比额外包含杂合子优势、频率依赖或时空选择的指定模型，并用独立数据检查其预测。方向选择、长期多态、约 50:50 或平坦曲线都不能单独完成这一证明。

<a id="doc-docs-evolution-design-zh--7-后续验证与真正缺少的数据"></a>

### 7. 后续验证与真正缺少的数据

**第一步：独立复现。** 固定研究总体、阈值、匹配方法、组织面板和主要结局，报告所有失败及不可用状态。先检查已知 anchor 的等位基因方向和轨迹是否与论文一致，再评估 extra；这属于流程阳性对照，不等于发现新机制。预留整条染色体或独立队列作确认，不能在同一批候选上反复选面板后仍使用未经选择的显著性解释。

**第二步：补齐检测分母。** 全基因组多 ALT 密度需要 all-sites AN 或与扫描采用相同掩码的 callable BED；按祖源、样本数、上下文、覆盖度和区域质量建立机会集。BED 的存在不自动修复 ALT 联合计数。确认性分析还需 LD 结构、区块不确定性、参考面板可表示性和选择统计功效的敏感性分析。[6]

**第三步：验证古代 extra。** 需要目标古代样本的 BAM/CRAM、索引、匹配参考 FASTA，以及损伤、污染、覆盖和样本身份信息；在候选区域重新评估允许多个碱基的 genotype likelihood，并检查比对质量、参考偏倚、末端脱氨、批次及低复杂度。作者为新数据给出 ENA `PRJEB106907`，可从目标样本和目标区域开始，而非下载全部测序数据。[4] 已有二等位 BCF 的 GP/DS 可帮助检查 anchor，但增加文件精度不会把模型之外的第三碱基“补出来”。1240k 的伪单倍体数据也不能直接按本模块的双倍体 AN 公式处理。

**第四步：现代携带者与功能验证。** 可选加入保留多等位状态的原始 1KG 基因型、相位和样本祖源，用来显示真正携带 extra 的现代个体；需单独核对版本、REF/ALT 与多等位表示。公共 EUR503 属于古代 imputation 所用 1KG 参考来源，其与古代结果的一致性不是独立复制。更强证据来自独立高覆盖队列，以及相关细胞/环境下的等位基因编辑、表达或剪接实验；要支持平衡机制，最终还需要可连接到适合度的表型与模型。

## 可选的 AlphaGenome Atlas 稀疏查询

本模块只为已经筛选好的少量候选位点补充预测效应。gnomAD 全基因组扫描、第三等位基因检出和分布统计均不依赖它。`build_plan` 完全离线；只有显式调用 `run_sparse` 或集成后的 `atlas-query` 命令才会连接服务。

查询使用 **Atlas 预计算数据库的 `GetDenseVariantScores`**，不调用 AlphaGenome 的模型推理接口。每个位点查询相对于当前 GRCh38 REF 的三个其他碱基，REF 本身的效应向量隐式为零。默认最多 2,000 个候选位点、6,000 个唯一 `REF→ALT` 变异，超过上限会拒绝执行，不会悄悄截断候选列表。

没有候选位点是合法结果：保留完整 TSV 表头即可生成空计划。空计划的查询和几何摘要均离线成功完成，不要求 SDK 或 API key，结果表保留表头。

<a id="doc-docs-sparse-atlas-zh--1-输入约定"></a>

### 1. 输入约定

候选 TSV 一行一个位点，必须具有以下列；额外的 `group`、`match_set`、`locus_block` 等列会保留在计划和结果中。

| 列 | 含义 |
|---|---|
| `site_id` | 唯一位点标识 |
| `chrom`、`pos` | 已映射到 GRCh38 正链的染色体与 1-based 坐标 |
| `ref` | 该位置的当前 GRCh38 参考碱基 |
| `anchor_ref` | 古代数据比较中的第一个碱基，已映射到当前正链 |
| `anchor_alt` | 古代数据比较中的第二个碱基，已映射到当前正链 |
| `extra_alt` | 当代额外观察到、且不在上述二者中的碱基 |
| `s` | 以 `anchor_alt` 相对 `anchor_ref` 为正方向的估计系数 |
| `posterior` | 原始后验置信指标，要求为 `[0,1]` 内的有限数值；原样保留其含义 |

所有四个碱基字段必须为单个 `A/C/G/T`。`anchor_ref`、`anchor_alt`、`extra_alt` 必须互不相同，但 `anchor_ref` **不需要等于**当前 `ref`；`extra_alt` 也可以等于当前 `ref`。例如当前 REF 为 A，古代比较为 C/T，当代额外观察到 A，这一输入完全合法。

模块不做 liftover、不猜测 A1/A2 的方向，也不靠 API 验证上游的参考序列。候选生成阶段必须先完成坐标、链方向和 GRCh38 REF 验证。若额外提供 `build`/`assembly`/`genome_build` 列，只接受 `GRCh38` 或 `hg38`；若提供 `strand`，只接受正链声明。数字染色体的前导零会归一化，例如 `chr01` → `chr1`。只接受主染色体名称；具体某个位置是否在 Atlas 可用范围内，由查询结果明确记录。

`s>0` 表示 `anchor_alt` 为估计增加的一方；`s<0` 表示 `anchor_ref` 为估计增加的一方。仅因坐标翻链而互补碱基，不会自动改变该比较方向。如果上游交换了两个 anchor 的身份，则需要同时反转 `s`。`s=0` 时不分配增加/减少标签。低 posterior 位点仍标为估计方向，不能据此断言选择方向已经确定。

<a id="doc-docs-sparse-atlas-zh--2-精确的-python-接口"></a>

### 2. 精确的 Python 接口

```python
from sparse_atlas import build_plan, run_sparse, summarize_geometry

plan = build_plan(
    "candidates.tsv",
    "atlas_plan",
    max_sites=2000,
    max_variants=6000,
    scorers=None,          # 默认六个有方向的 scorer
    ontology_terms=None,  # 默认保留全部返回的 tracks
)
# 此时仅写 atlas_plan/plan.json，没有读取 API key，也没有发请求。
print(plan["n_sites"], plan["n_variants"], plan["plan_path"])

# 下面是独立、显式的联网步骤。API key 从环境变量读取；不要写进代码。
query = run_sparse(
    plan["plan_path"],
    "atlas_results",
    api_key_env="ALPHAGENOME_API_KEY",
    max_variants=6000,
    workers=2,
    retries=3,
    timeout=60,
    requests_per_second=2.0,
    max_consecutive_failures=3,
)

# 这个步骤只读本地缓存；不需要 API key。
geometry = summarize_geometry(
    plan["plan_path"],
    query["cache_dir"],     # 也接受 atlas_results 根目录
    "atlas_geometry",
    effect_thresholds=(0.1, 0.5, 1.0),
)
```

`run_sparse` 也接受 `api_key_file`。密钥只用于构建传输层，不写入计划、缓存、日志或 provenance。完整缓存再次运行时不读取 key、不创建 SDK 客户端。

规划只依赖 Python 标准库，几何摘要需要 NumPy。实际查询额外需要 AlphaGenome SDK；本实现核对的版本为 `alphagenome==0.10.0`。SDK 及其 gRPC/AnnData 依赖应当作为可选依赖安装，主扫描环境不需要安装它们。

默认六个 scorer 是 `ATAC`、`DNASE`、`CHIP_TF`、`CHIP_HISTONE`、`CAGE`、`PROCAP`。可显式指定其他 scorer；服务端缺少的 scorer、无方向的 scorer 等情况在几何结果中保留明确状态。ontology 参数使用 `UBERON:...`、`CL:...`、`CLO:...` 或 `EFO:...` CURIE。官方过滤器对没有 ontology 元数据的 scorer 不施加该筛选，因此不能把 ontology 参数解释成所有返回数据都严格属于某个组织。

<a id="doc-docs-sparse-atlas-zh--3-查询预算重试和中断"></a>

### 3. 查询预算、重试和中断

预算按整个计划的唯一变异计数，包含已经缓存的变异。每个位点固定三次首次查询；2,000 个位点对应 6,000 个 `GetDenseVariantScores` RPC，而不是 2,000 次。`query_variants` 在官方 SDK 内部同样逐变异请求，因此这里直接控制每个 RPC，避免隐藏的批处理开销和无法定位的失败。

默认两个 worker；全局限制每秒最多启动两次请求，重试也占用该速率。每个缺失变异最多尝试 `retries+1` 次。默认每次 RPC deadline 为 60 秒，退避为 1、2、4 秒，较多重试时最多 30 秒。可重试的状态仅为 `UNAVAILABLE`、`DEADLINE_EXCEEDED`、`RESOURCE_EXHAUSTED`、`ABORTED`。鉴权、权限、非法参数、接口不支持等错误立即停止发出新请求；连续三个变异耗尽重试也会停止。有限数量的已在途请求可能完成，成功结果仍会缓存。

传输层禁用了 gRPC 隐式重试，以免官方配置中的五次尝试和应用重试次数相乘。首次建连只等待给定 timeout，不进行额外隐藏请求循环。

查询进度在 `query.json` 中记录，包含实际 RPC attempts、成功/待完成变异数和错误代码。部分失败先写进度，再抛出 `RuntimeError`；重跑同一个计划和输出目录会复用所有完整结果，只尝试尚未成功的变异。未完成缓存不会被解释为零效应。

连接失败、额度不足或运行时间不能从候选数量单独推断。官方明确说明查询速率会随需求变化；本项目没有使用真实 key 进行性能测速，不承诺几千次请求的固定耗时。

<a id="doc-docs-sparse-atlas-zh--4-原始缓存和出处"></a>

### 4. 原始缓存和出处

`atlas_results/cache/catalog.json` 记录查询设置、SDK 版本、endpoint 和缓存 namespace。每个唯一变异有一个以内容摘要命名的目录，包含：

| 文件 | 内容 |
|---|---|
| `response.pb` | 服务端 `DenseVariantScores` protobuf 原始序列化结果，无损保存 |
| `arrays.npz` | raw float32 数组；若存在，quantiles 另存为独立数组 |
| `metadata.json` | 全部 obs/var 表格、原始索引与 dtype、interval、scorer signedness、SDK scorer 配置，以及去除重复分数字节后的 protobuf 结构 |
| `COMPLETE.json` | 文件 SHA-256、variant identity 和 namespace，最后原子提交 |

缓存键包含 variant、requested scorers、ontology 条件、GRCh38、SDK 版本、endpoint 和本模块 schema。更改查询设置或 SDK/endpoint 后不能混用原目录。完整缓存文件缺失或校验失败会明确报错，避免把损坏数据作为有效结果。输出目录有进程锁，防止两个同目录任务同时重复提交缓存。

Atlas 当前接口不暴露可以指定的 dataset release pin。本模块记录 endpoint、SDK、时间、fetch session 和 metadata hash，**不伪称服务端数据永久固定**。一次中断后续跑可能跨越多个查询 session，结果保留全部相关 session。标签和 interval 一致只能检查可观察的结构兼容性，不能证明服务端模型权重在两次查询之间没有变化。需要严格冻结时，应归档整份本地缓存并以其摘要作为分析输入。

<a id="doc-docs-sparse-atlas-zh--5-几何量的定义"></a>

### 5. 几何量的定义

对每个 scorer 独立计算。设在相同 GRCh38 REF 背景下，古代第一碱基、第二碱基和额外碱基的 raw effect 向量分别为 `a`、`b`、`e`。当某一个碱基恰好是当前 REF 时，它的向量为同形状的零向量。

向量特征由完整的生物学标签标识：obs 中的 gene/junction 元数据与 var 中的 track 元数据的组合。obs 的 variant/interval 不作为特征身份，因为它们分别表示输入变异和计算区间；interval 在另一项检查中必须一致。文件中的位置索引保留用于审计，但不替代生物学标签。标签顺序不同会重新对齐；标签集合不同、标签重复而无法唯一对齐、interval 不同，均停止该 site/scorer 的几何比较，不取任意交集，不填零，不依据名称猜测。

结果包括：

- `atlas_distance_to_anchor_ref = ||e-a||₂`
- `atlas_distance_to_anchor_alt = ||e-b||₂`
- `atlas_anchor_delta_l2 = ||b-a||₂`
- `atlas_projection_fraction_from_anchor_ref = ((e-a)·(b-a)) / ||b-a||²`
- `atlas_projection_raw_from_anchor_ref = ((e-a)·(b-a)) / ||b-a||₂`
- `atlas_signed_cosine_from_anchor_ref = ((e-a)·(b-a)) / (||e-a||₂ ||b-a||₂)`
- `atlas_orthogonal_residual_l2 = ||(e-a)-t(b-a)||₂`，其中 `t` 是上述 projection fraction。

projection fraction 为 0 时投影位于 `a`，为 1 时位于 `b`；它可小于 0 或大于 1，不截断为概率。cosine 保留正负号。额外碱基与起点的效应向量相同时，cosine 未定义，但 projection 和 residual 可以为零。`a=b` 时，方向性指标全部留空，状态为 `degenerate_anchor_delta`；距离和 breadth 仍然有效。

根据 `s` 的符号，另外输出额外碱基到“估计增加”“估计减少”碱基的距离，以及从估计减少一方向估计增加一方的 projection 和 cosine。它们描述预测分子效应的几何关系，不能直接解释为促进或阻碍适应。

默认六个 scorer 的 raw 值为 `log2((sum ALT + 1)/(sum REF + 1))`。除 `CHIP_HISTONE` 使用 2,001 bp 中心窗口，其余五个使用 501 bp。其他 scorer 可能按 gene 返回，可能使用自然对数、绝对差或其他量纲。即使同为 raw 分数，也不跨 scorer 拼接向量、不做任意 z-score 标准化、不把 quantiles 当成 raw effect 的替代品。

<a id="doc-docs-sparse-atlas-zh--6-predicted-response-breadth"></a>

### 6. Predicted response breadth

`breadth.tsv` 对每个成功比较的 site/scorer、三个候选碱基和每个阈值 `τ` 输出：

`atlas_predicted_response_breadth = count(|raw_effect| > τ) / number_of_features`

这是给定预测维度上超过阈值的比例。阈值严格使用 `>`；等于阈值时不计入。raw effect 相对的是当前 GRCh38 REF，因此 REF 的 breadth 必为零。每个阈值都保留分子和分母；非空的完整共同轴是必要前提。

`atlas_role` 的三个值为 `anchor_ref`、`anchor_alt`、`extra`；其中 `extra` 对应输入的 `extra_alt`。这里的 breadth 随所选共同参考而变化，不能解释为该碱基自身的绝对功能广度。REF 的零值是对比定义产生的，绝不意味着参考碱基没有生物学功能；当各个位点的 REF 与古代 anchor 的关系不同时，直接跨位点比较 raw breadth 还会引入参考角色差异，应分层或预先规定共同的对比问题。

一个 track 不等于一种独立功能：多个 track 可能来自同一组织、同一生物学过程或相关实验。因此该字段命名为 **predicted response breadth**，不称为功能数或经过验证的 pleiotropy 指标。raw 值的阈值和不同 scorer 的 breadth 也应分开解释。

<a id="doc-docs-sparse-atlas-zh--7-输出与验证边界"></a>

### 7. 输出与验证边界

`geometry.tsv` 为每个候选位点和 scorer 留一行，即使结果不可计算。常见状态包括 `ok`、`missing_variant`、`missing_scorer`、`unsigned_scorer`、`ambiguous_axes`、`axis_mismatch`、`interval_mismatch`、`nonfinite_raw`、`degenerate_anchor_delta`。`breadth.tsv` 只包含通过标签/区间/方向性和有限值检查的结果。`geometry.json` 保存阈值、状态计数、出处、fetch sessions 和输出文件摘要。

本模块用模拟传输验证了预算、每位点三 ALT、原始缓存、重试停止、鉴权失败、断点续跑、空候选、标签重排序、非当前 REF 的古代 anchor、REF 作为 extra、正负/零 `s`、退化 anchor、缺失/无方向/不兼容输出等边界。测试不使用真实 key、不发 API。

另有一项可选的真实 SDK 离线契约测试：使用实际 `GetDenseVariantScoresRequest` 与 `DenseVariantScores` protobuf，构造包含 ATAC raw/quantiles、gene/junction、ontology/biosample 以及部分缺失元数据的合成响应，再经过实际适配器、官方 AnnData 转换函数、缓存写入和读回。该测试禁止创建 gRPC channel，不提供任何 key，已经通过。验证环境为 Python 3.12.14、AlphaGenome 0.10.0、AnnData 0.11.4、gRPC 1.84.0、protobuf 7.36.2、NumPy 2.3.5、Pandas 2.2.3、SciPy 1.17.0、Zarr 2.18.7；依赖位于隔离的临时目录，未改变主扫描环境。安装了 SDK 的环境可运行 `python -m unittest discover -s tests -p test_sparse_atlas_sdk.py -v`；没有 SDK 时该项自动跳过。

这验证了真实包的构造器、枚举、数组解码和元数据转换兼容性，仍未验证 live 服务的可用性、实际数据覆盖或吞吐量。
