# grid

PRS 基准、LD-block 拟合与透明参考人计数。`grid.sh` 运行 count；CSx、Disco、PRSformer 使用各自入口。支持 local/HPC，先用 `--plan-only` 预览。结果在 `count_abm/final/`；个体证据仅保留于 `_LOCAL_ONLY`。

在本目录查看参数和示例：

```bash
bash 1.pca.sh -h
bash 2.csx.sh -h
bash 3.disco.sh -h
bash 4.prsformer.sh -h
bash grid.sh -h
bash install.sh -h
```

路径优先使用命令行覆盖；共享默认配置位于 `../0f/0os.sh`。
`2test/` 保留回归测试或入口自检依赖，不要作为缓存删除。

HPC 阶段按资源分开申请，依赖成功完成后才启动下一阶段：

- `4.prsformer.sh`：共享 CPU 准备与自检 → 每个 trait/method 的 GPU 训练和推理 → CPU 报告。`all` 包含 PRSformer 和 PRSformer2；3 个 trait 共 13 个任务。报告核对本次 GPU 任务保存的模型、预测和输入校验和，不重新训练或要求 CUDA。
- `grid.sh`：CPU 共享输入/LD-block 与几何准备 → GPU 半径与邻居计数 → CPU 评估、architecture、final。`prepare` 单独调用也拆成 CPU 几何与 GPU 半径；`--device cpu` 可令计数全走 CPU。
- job name 标出 trait、模块、CPU/GPU 和阶段。`--job-cores/--job-memory-gb/--job-hours` 只控制 CPU；`--gpu-cores/--gpu-memory-gb/--gpu-hours/--gpu-threads` 单独控制 GPU。GPU 队列可用 `--gpu-queue` 指定，默认 `2v100-32-sc`；实际提交前应重新查看 `queueinfo`。

例如（资源与队列应按数据和实时空闲情况调整）：

```bash
bash 4.prsformer.sh all --traits height,ldl,t2dm --submit hpc \
  --queue 73x --gpu-queue 2v100-32-sc --gpu-cores 8 --gpu-memory-gb 160 \
  --gpu-threads 2 --plan-only
bash grid.sh all --traits height,ldl,t2dm --submit hpc \
  --queue 73x --gpu-queue 2v100-32-sc --plan-only
```
