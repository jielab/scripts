<a id="overview--运行"></a>

### 运行

上游 CSx 的目标 SNP 清单由 `2.csx.sh` 自动从 `--dir-gen` 下各染色体的
`.pvar`、`.pvar.zst` 或 `.bim` 生成，永久保存为该基因型目录下的 `ukb_array.bim`
（当前为 `/mnt/f/gen/ukb/37/typ/ukb_array.bim`），来源与校验记录保存在旁边的
`ukb_array.bim.json`。它不依赖分析目录缓存，也不会转换或改写 `.pgen`。
生成清单保留双等位 A/C/G/T SNP，BIM 等位基因顺序为 ALT、REF；重复 SNP ID 会报错。
清单包含目录内所有可用常染色体，`--chrs` 的子集运行不会缩小它。
脚本按内容校验复用；来源变化或生成文件损坏时重建。
`--check` 也会准备这份元数据，但不运行推断或评分。
已有自定义目标清单时使用 `--bim-prefix PREFIX`，脚本不会覆盖它。

```bash
cd /mnt/d/scripts/grid
./4.prsformer.sh --traits height,ldl,t2dm
./grid.sh all --traits height,ldl,t2dm --device auto
```

默认执行 `blocknet → twins → assess → architecture → final`，也可显式使用 `./grid.sh all`。
`abm` 仅是 `assess` 的兼容别名。GRID 不训练 PRSformer；CPU 不要求 NATTEN。
运行前自动检查科学约束；共享输入缺失时明确提示先运行
`./4.prsformer.sh prepare --traits height,ldl,t2dm`，不会隐式启动 benchmark 或准备。
共享表型读取兼容 UKB 合并阶段的 `all.rds`：若缺少 `ldl`，使用已清洗的
`bb_LDL` 原值，不做单位换算或药物校正。若同时缺少 `t2dm.Yr2e/Yt2e`，
使用 `date_attend/date_lost/date_death/fod_icd10_t2dm/cnt_icd10_t2dm` 调用
`../0f/phenotype.R` 中与上游 `phe4gwas` 相同的 `t2e()`，再构造基线 0/1 标签。
同日诊断计为基线病例；随访后发病例在基线为对照；有疾病证据但无日期者保留缺失。
已有表型列和显式列名优先；只缺一列的 T2DM 终点对会报错。
ABM 与 PRSformer 共用此读取逻辑，准备记录保存实际来源和定义，原始 RDS 不会改写。
SMOKE 只读取现有可信输入，缺文件直接报告路径，不隐式开始全量准备或 block 构建。
`all` 任一模块失败即停止，全部 GRID 阶段成功才生成 final 汇总。
单独的 `./grid.sh final --traits height,ldl,t2dm` 不要求两个 PRSformer 已完成：
它汇总已有且校验通过的当前结果，在 `final/performance_status.tsv` 中将缺失模块
标记为 `not_completed`。已有结果若校验失败仍会报错。
Shiny 由 `./grid.sh shiny` 单独打开。

默认使用 `--predictor blocknet --representation csx_ldblocks_fixed --device auto`。
配置默认读取脚本目录的 `config/abm.json`，也接受 `--config config/`。
CPU/CUDA 是 ABM 的设备选项。PRSformer 的正式 neighborhood attention 需要 CUDA。
两种 PRSformer 在同一 GPU 上按顺序运行。
代码仅维护 FINAL 实现。没有 `abm_GPU` 入口；使用 `abm --device cuda`。
显式 CUDA 不可用时会报错，`auto` 才可选择 CPU。

需要逐项运行时：

```bash
./4.prsformer.sh prsformer --traits height,ldl,t2dm
./4.prsformer.sh prsformer2 --traits height,ldl,t2dm
./grid.sh blocknet --traits height,ldl,t2dm
./grid.sh twins --traits height,ldl,t2dm
./grid.sh assess --traits height,ldl,t2dm
./grid.sh final --traits height,ldl,t2dm
```

`prsformer` 对外名称为 **PRSformer**，使用 PRSformer backbone；每个性状独立训练一个模型。
`prsformer2` 对外名称为 **PRSformer2 exploratory**，使用 separate calibration，保留该 backbone，调整损失归一、学习率、停止规则、初始 head，
并独立划分 prediction calibration；它重新训练独立模型。
两个模块共享 `prsformer/cache` 的基因型、样本表、SNP 表和冻结划分，
`prsformer2` 不依赖 PRSformer 已训练模型或预测结果，可以单独启动。
`--traits height,ldl,t2dm` 按填写顺序依次训练三个独立模型，各自选择最佳轮次、早停、预测和保存。
批量指定性状与使用相同配置逐个指定性状使用相同的模型目录和续训记录；重复运行会逐性状验证、跳过完成项或继续未完成项。
共享数据始终按 `height,ldl,t2dm` 准备；`--traits height,ldl` 只选择要独立训练和评估的性状，
不会缩小共享样本队列或改变缓存签名。独立队列的 standalone 准备仍按所选性状执行。
`./4.prsformer.sh --traits height,ldl,t2dm` 默认依次执行 prepare、prsformer、prsformer2。
显式模块可单独运行；任一模块失败即停止，不再启动后续模块。
模块内任一性状失败也立即停止，已经完成的性状结果保留。
只跑两个 benchmark 时使用：

```bash
./4.prsformer.sh --traits height,ldl
# 只预览两个模块，不开始训练：
./4.prsformer.sh --traits height,ldl --dry-run
```

以上顺序为 PRSformer height → PRSformer ldl → PRSformer2 height → PRSformer2 ldl。
训练、比较、汇总和查看器只读取独立性状目录，绝不回退到旧联合模型、预测或报表。
单性状结果尚未完成时显示缺失；旧的 `prsformer/run/`、顶层发布结果和
`prsformer2/<hash>/` 不能用于当前分析。清理旧模型时保留 `prsformer/cache/` 共享数据。

共享基因型被清理后，首次训练会从原始 PGEN 自动重建约 132 GiB 的矩阵，
第二个模块复用它；不要删除整个 `prsformer` 目录中的冻结元数据。
ABM 内部拟合 `csx-linear`、`csx-blocknet` 及 Clinical、MoE 比较器。
所有模型在合并的 build/tune_model/calibration 分区拟合；race/ancestry 只作为
描述与分层验证标签，不参与训练集划分、供体筛选、twin 搜索、校准或预测路由。
评估对照只按冻结的 baseline-risk 分箱匹配，并排除同一家族/组，不要求同祖源。
整体训练/校准集仍须满足拟合所需的标签数，不再为每个祖源设置最低病例数。
四列 CSx 和多群体 LD maps 是应用于每个人的遗传特征，不是按 race 分类训练。
`3.disco.sh` 是独立的已发表方法复现，生成 `2disco.scores.rds`；ABM 不调用它，
也不在内部使用它的名称。历史上游结果保留原始方法名，不能改名为 ABM 的结果。

本次合并训练协议使用 `abm.assessor.2`，旧 assessor/匹配报告不能直接作为新协议使用。
`f/migrate_abm_pooled.py` 仅对已审计的旧版本迁移缓存：校验原始阶段文件与数学依赖，
保留未改变的主模型、Clinical/MoE 预测和 twin support；旧 support 通过硬链接保留，
不复制大数组。新缓存确认可用后清理冗余预测器缓存及不再使用的插值临时输入，
撤下旧 CURRENT 指针；冻结的历史模型与报告保留。用户重跑 ABM 时重新生成
assessor、无祖源限制的匹配和报告。其他依赖若发生变化，迁移会拒绝复用。
`--module-only` 仍可解析，但不再是独立运行的门槛。`moe + csx_scores` 不读取 LD 配置、
BED、tokens 或 block receipt；只需要真实四列 CSx 和共享 side features。

重复命令会校验完成文件并恢复中断任务。PRSformer2 的角色文件保持内容和时间戳不变，
已完成训练但未完成校准的任务会恢复校准，已完成模型可恢复预测或汇总。
共享基因型在各性状 block 准备和抽样复核完成后自动释放。保留文件位于分析根目录的 `cache/` 和 `prsformer/cache/`，
日志在 `logs/`，不在 `/tmp` 中保留 GRID 分析结果。

ABM 的 `radius_geometry.npy` 在半径估计结束后立即删除；整队列 `geometry.npy`
在 support 完成、结果与校验清单写入后自动释放。`SCRATCH_RELEASED.json` 记录释放文件
及其原始校验值，原 `COMPLETE.json` 不变，断点复用仍校验所有保留文件。
Python 异常或 Ctrl-C 会关闭 mmap 并清理本次未完成的 geometry 数组；强制杀死进程或断电后，
下次进入同一 support 缓存会重建并清理。部署需要的 `donor_geometry.npy` 和 block scores
继续保留。原始共享基因型及每个性状的补充基因型不再长期保留：先完整校验原数组，
独立重算固定的 32 个真实个体，再保存这些个体的全部 dosage 列及绑定校验记录
`dosage_probe.npy` / `DOSAGE_PROBE.json`。后续复核用相同个体、相同剂量值重算，
同时仍完整校验 block 数组、样本顺序、权重和 LD 边界，不跳过科学验证。
每个性状退出时自动释放已具备有效 probe 的补充矩阵；配置中的全部性状均有 probe 后，
再释放共享矩阵。未完成的 PRSformer/PRSformer2 训练、被进程占用或锁定的文件保留。
`4.prsformer.sh` 导出 `GRID_KEEP_SHARED_INPUTS=1`，PRSformer2 完成后继续保留共享矩阵。
GRID 后续完成并验证所有性状的 block 输出后，才允许按既有校验规则释放。
原完成清单不改写，释放记录写在 `genotypes.released.json`。重新训练或构建新的 block
需要完整矩阵时从原始 PGEN 自动重建，并核对原校验值、保留原 cohort/variant 元数据。

历史文件可用 `./grid.sh cleanup` 预览，`./grid.sh cleanup --apply` 校验并清理；
`--config` 在此模块指向 `abm.blocks.json`。首次清理会生成缺少的 32 人复核文件。
CSx 的 LD 暂存副本在 HDF5 关闭后删除，染色体 `.sscore` 在合并成功后删除；
个体 posterior moments 发布后也删除各染色体中间表。`final` 只读取并校验已完成结果，
写入聚合汇总与索引，不做训练、重拟合或缓存清理；清理使用独立 `cleanup` 模块。
block scores 生成失败也会关闭并删除未发布的 `.tmp` 大数组。
`./grid.sh` 的 GRID 计算流程还会在启动时、每个性状结束时（包括后续阶段异常时），
自动检查本次请求性状的历史 support 缓存，补清理已完成且无人使用的临时数组；
即使所有计算阶段都直接复用，也会执行。不需要额外清理参数；`--dry-run` 不清理。
历史缓存校验失败或仍被占用时保留文件并记录原因，不中断当前分析。

旧运行的已完成 support 可单独清理（默认仅列出候选；`--apply` 完整校验后删除）：

```bash
PYTHONPATH=f python -m abm_core.storage --analysis-root /mnt/d/analysis/grid
PYTHONPATH=f python -m abm_core.storage --analysis-root /mnt/d/analysis/grid --apply
```

清理只处理上述两个临时数组，跳过未完成、加锁或仍被进程打开／映射的缓存。

<a id="overview--配置与阶段"></a>

### 配置与阶段

`config/abm.blocks.json` 管理 LD block 和网络参数；自定义分析根目录时需要同步指定
其中的输入、缓存和输出路径。共同名单由准备阶段按当前输入和参数生成：

```text
/mnt/d/analysis/grid/
  cache/abm/          # split.rds、common.keep、families.tsv.gz、prsformer.split.tsv.gz
  prsformer/cache/   # 共享基因型、数据表与准备记录
    roster/          # 从共同名单生成的 PRSformer 输入
  abm/               # ABM 模型与结果
    FINAL/           # 按性状保存的模型、预测与评估
    ld_block_report/ # LD 分块清单、权重质控与分块重建报告
  prsformer/<trait>/ # model.pt、predictions.rds、split.rds、图表、PUBLISHED.json；run/ 保存检查点与评估
  prsformer2/<trait>/# CURRENT.json 指向该性状的 <hash>/；模型与预测位于 <hash>/_LOCAL_ONLY/
  local/kinship/      # 本地亲缘连通分量和 QC；不进入 final 或查看器
  final/             # 汇总与查看器索引（含六份 paper_*.tsv）
  logs/              # 运行日志
    validation/      # 历史验证日志、审计记录与测试产物；不进入结果索引
```

LD 分块报告由 `config/abm.blocks.json` 的 `output_root` 指定，默认保存到
`abm/ld_block_report/<layout>/<trait>/blocks/`；用于计算的分块矩阵仍在
`cache/abm/blocks/`。旧的根目录 `block_inputs/` 已迁入此报告目录，
根目录 `validation/` 已迁入 `logs/validation/`。

同一分析目录的续跑复用其已经生成的名单与划分，并核对各模块的样本 ID、分组、
测试集及准备记录校验和。人数和测试集身份取自当前输入；原审计参照为 N=243372、
`twin_core.id_hash` = `2e6273256eb7bf254acab815429a067d0468557ab070008930dc872b8eb80adc`。
该算法对排序后的 ID 按换行连接，不能与 `ordered_ids_sha256` 直接比较。
需要改变队列或划分时使用新的分析目录，避免与已有结果混用。

ABM 按 trait 顺序分别运行七阶段：
`prepare → fit_predictors → build_support → fit_assessor → freeze_predictions → evaluate → report`。
每阶段按源代码、参数和输入绑定结果；文件损坏会报错，不会静默重训。

ABM 的加权 SNP 可能比 PRSformer 缓存更全：当前 PRSformer 使用 `37/hap`，
CSx 使用 `37/typ`。`config/abm.blocks.json` 的 `dosage_supplement_dir` 指定
补齐缺失 SNP 的 PGEN 目录，当前设为 `/mnt/f/gen/ukb/37/typ`；自定义数据应改为
对应的 CSx 目标目录。省略此项时沿用 `prepare.json` 中的 `options.dir_gen`。
补齐时按样本 ID 对齐，并严格核对 SNP 坐标和等位基因，来源记录在独立缓存中。
已缓存 SNP 继续使用 PRSformer 剂量；block 重建做严格校验，与全量 CSx 分数另作诊断比较。
修正补齐来源后可重跑原 ABM 命令，复用已有准备结果，无须重新转置基因型。

```bash
# 运行公开的冻结模块
./grid.sh blocknet --traits height,ldl,t2dm --device auto
./grid.sh twins --traits height,ldl,t2dm --device auto
./grid.sh assess --traits height,ldl,t2dm --device auto

# 只预览执行计划
./grid.sh --traits height,ldl,t2dm --dry-run
```

ABM 结果位于 `abm/FINAL/<trait>/<predictor>_<hash>/`；
PRSformer 位于 `prsformer/<trait>/`，PRSformer2 位于 `prsformer2/<trait>/<hash>/`，
总汇总位于 `final/`。只读取完成的当前结果，不回退到其他目录。
分析输出中的个人数据和模型位于分析目录下各运行目录的 `_LOCAL_ONLY/`；
查看器只读取汇总表。

<a id="overview--科学合同"></a>

### 科学合同

ABM 以固定训练参考集内、固定遗传距离半径中的全部 eligible twins 数量，分别估计
基线的预期误差与候选的绝对预期增益。主 head 仅使用 count，不强制单调，不是个人 R²/AUC。
半径用 tune_model X 冻结；K=128 只限制保留邻居摘要，不限制半径内的总 count。
主 geometry 为 CSx 加权 LD blocks，不含 PC、临床或结局残差。

build 拟合预测器，tune_model 选择参数。calibration_fit 按 group 固定划分为 prediction 50%、
head 25%、policy 25%。选择和匹配在读取 test Y 前冻结。默认六档 coverage，主操作点 50%；
只有绝对预期收益超过冻结门槛才使用候选。缺失 Y 不删除 test 行、不改变选择。

三预测器共享四个 CSx score、十个 match PC、age/sex/PC1/PC2；协变量缺失时报错。
T2DM 是 baseline_t2dm_from_Yr2e_Yt2e，不能解释为 incident/survival endpoint。
当前已观察过的 test 仍是探索性验证；family、GWAS overlap 和表型来源状态按证据记录。

报告包含固定预测器、benefit policy、配对比较、predictability/benefit 曲线、cohort flow、
count 校准和 A/B/C/D 诊断。置信区间用原始 group bootstrap，生产配置 1,000 次。
校准 bin 的区间不是个人未来误差的保证范围。

<a id="overview--输入完整性缓存和报告"></a>

### 输入完整性、缓存和报告

block producer 在 flush 和重构检查后记录完整 NPY SHA256、shape、dtype、轴顺序、
ordered IDs/groups、token 内容与顺序、channels、layout/weights identity 和科学版本；
completion 最后写。没有 group 时明确记录未提供，在可信 ID 合并处绑定 group/source evidence。
consumer 在重构 probe 前检查完整 bytes；32 人 probe 仅检查计算含义。
没有可信凭证的数组不能补写 sidecar 后变成 verified。受影响的 trait/layout 从现有有效
genotype/weights 定向重建到 `cache/abm/blocks/producer-bound/`；原数组保留。
已有可信 producer binding 的产物可验证后原位复用。不会整体删除 analysis/grid。

support identity 绑定真实四列 CSx 数值/顺序/ID，或已验证 raw blocks，以及 group 和 role/bank
成员关系；不包含 test Y 或 case count。仅 group evidence 状态改变时复用距离、刷新注释。
predictor cache 单独绑定 side values、训练/调参/预测校准标签、roles/groups、实际 block 输入、
实现与依赖版本。改变输入会重拟合相关 predictor；改变 assessment loss 复用数学上未变的
predictor/support，重新拟合 head/diagnostics/rules 并冻结评价。

默认 height/ldl=MSE、t2dm=Brier；binary assessment 也支持显式 LogLoss。
head、unavailable、diagnostics、observed calibration、gain/policy 使用同一个 loss。

## UPSTREAM

Source: https://github.com/YunfengRuan/DiscoDivas
Commit: ee8e5d996e6fc6ffaf04255e1cf0fa8ecce68524
License: MIT (f/disco/LICENSE).
Program: f/3.disco.R; moved without algorithm changes during layout consolidation.

The official distance-matrix inversion, distance interpolation, shrinkage and
PCA residualization are retained. Local correctness fixes:
- Label target PC columns using the number actually selected (`npca`).
- Write IDs from the final merged `dat`, keeping each score attached to its ID.
  The upstream `IID` variable can refer to a different ordering/subset.
- Read PCA/PRS IDs as character to preserve leading zeros and matching types.
- Convert PRS tables to data.frames before merging and numeric column arithmetic;
  the `regress.PCA=FALSE` branch otherwise retains data.table indexing semantics
  and can fail when joining integer PRS IDs to character interpolation IDs.

The wrapper validates finite PCs/scores, unique IDs, complete PRS sample overlap,
center order, positive distances and finite output before publishing.

## 冻结后的区域维度分析

`./grid.sh architecture --traits height,ldl,t2dm` 仅读取 CSx provenance 指向的既有
后验权重、`config/abm.blocks.json` 和 GRID 原始 GRCh37 LD 边界。
复用 `block_inputs.py` 的分配规则，不读取个体表型、不训练、不修改 CURRENT。
`all` 的顺序为 blocknet → twins → assess → architecture → final。
单独运行时 `--config` 指定区块配置 JSON；`all --config` 使用同目录的 abm.blocks.json。

主分析固定为区块内 Σβ²，敏感性分析固定为 Σ|β|，包括所有零质量区块。
主指标为 N_eff/B（N_eff=1/Σp²）；先在各发现人群内归一化，再对四个人群等权汇总。
同时输出 top 1/5/10% 质量占比、Shannon 有效区块数及 Gini。
`architecture/` 提供人群表、性状表、top25 区块、gain 对照表及 PNG/PDF 图。
只有表格验证成功后才写 ARCHITECTURE_COMPLETE.json，使用路径、大小和 mtime_ns
记录输入身份，不增加完整文件 SHA256 扫描。缺少 final 性能表时 gain 为 not_available。
`final` 只读取已完成结果，生成 paper_regional_dimensionality.tsv，不重新分配区块。

这是“拟合 PRS-CSx 后验信号的有效区域维度”，不等于区域遗传力或真实遗传架构；
还反映发现 GWAS 功效、LD、收缩和不确定性。仅三个性状，不拟合回归、不计算跨性状
相关性 P 值。按维度从低到高严格对应 gain 从高到低才标记描述性方向一致；
否则报告区域集中度不能充分解释差异。两种质量定义排序不一致时明确标记。
不根据结果调整模型、区块、阈值或质量定义。既有 1csx.scores.rds、2disco.scores.rds
及其他科学数据接口保留原名；代码改名不触发科学重跑。
