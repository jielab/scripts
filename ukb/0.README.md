# ukb

UKB 表型、基因型及关联分析，分别使用 `phe.sh`、`gen.sh`、`assoc.sh`。个体数据与结果保留在私有目录。

在本目录查看参数和示例：

```bash
bash assoc.sh -h
bash gen.sh -h
bash phe.sh -h
```

路径优先使用命令行覆盖；共享默认配置位于 `../0f/0os.sh`。

## local / HPC 与 GWAS 导出（2026-11-05）

`gen.sh`、`phe.sh` 统一从 `../0f/0os.sh` 读取路径。主目录默认 `hpc`；
用 `--submit local` 显式选择本地，`--submit auto` 按 LSF 环境判断。
`--dir-dat`、`--dir-big`、`--dir-tmp` 以及原有输入/输出参数仍可覆盖默认值。
每次运行先在输出目录的 `jobs/` 下创建独立 `.cmd`，local 用 bash 执行，
HPC 用共享 `submit_jobs.py` 提交 bsub 并保存 job ID。
`--write-cmd` 或 `--run-cmd FALSE` 只生成命令；`--wait TRUE` 等待 LSF 验证完成。
`gen.sh --dry-run` 等同 `--write-cmd`，旧 `--background` 等同 `--submit hpc`。
`liftGen`、`pgs`、`snp`、`apoe` 均使用相同入口；作业内不会再次提交 bsub。

```bash
cd /work/sph-huangj/scripts/ukb
# 重用现有 all.rds/bbc.rds，只重新生成 GWAS 表型。
bash phe.sh --submit hpc --steps phe4gwas \
  --phenotype-dir /work/sph-huangj/phe/ukb \
  --queue 33 --memory-gb 32 --walltime 4:00
# 先查看命令：给上面的命令追加 --write-cmd。
# 本地执行：改用 --submit local，路径自动切换到 0os.sh 中的本地配置。
```

资源参数：`--queue`、`--slots`、`--memory-gb`、`--walltime`、`--threads`。
33 队列的预约核数按共享 CPU/RAM 规则上取整；32 GiB 预约 10 核，160 GiB 预约 40 核。
分析线程默认 4，`--pgs-threads` 较大时预约核数也随之增加。
可用 `--dir-jobs` 单独指定命令和 LSF 日志目录。HPC `.cmd` 必须通过 bsub 执行。

HPC 默认 Python 是 `SHARED_PYTHON`，R 使用共享路径中的 `LE8_RSCRIPT`；
可分别用 `UKB_PYTHON`、`UKB_RSCRIPT` 或 `--rscript` 覆盖。
local 继续使用 PATH 中的 Rscript。R 入口直接加载实际需要的包，不安装 tidyverse 元包。

新版 `ukb.phe` 前五列为 `FID IID ethnic.c center batch`；
`batch` 来自 p22000 / `gen_batch`，编码为 `b` 加原整数（例如 `b-11`、`b6`），
缺失仍为 `NA`。保留 PC1–10。
在原有结局之外新增 ad、amr、asthma、copd、cvd_afib、cvd_htn、epilepsy、masld、mi、ra、sle2
的 `.t2e` 和 `.Yt2e`，使用各疾病 ICD-10 首次日期及计数，规则与 t2dm 相同。
行政随访截止仍为 2023-04-01，时间单位为年；基线病例及有诊断证据但无有效日期者不算新发对照。
GWAS 文本不再输出任何以 `r2e` 或 `bi2e` 结尾的列（包括 `.Yr2e`）。
完整队列及内部衍生变量继续保存到 `Rdata/all.rds`，GWAS 导出仍限定 White 队列。
缺失必需 PC 或疾病来源列时会明确报错，不覆盖旧 `ukb.phe`。

验证：

```bash
python3 -m unittest discover -s 2test -p 'test_*.py' -v
Rscript 2test/test_gwas_export.R
```

## 重建表型和组学（2026-11-02）

处理流程和 date-check 默认直接使用 WSL PATH 中的 `Rscript`，读取正常的
用户 R 配置和包库，无需设置 `RSCRIPT` 环境变量；旧的该变量不影响默认选择。
不再包含 Windows R 适配。需要其他 Linux R 时仍可显式使用 `--rscript`。
使用系统 `/usr/bin/Rscript` 时，仅在 R 子进程中清除继承的
`PROJ_LIB`、`PROJ_DATA`、`GDAL_DATA`，避免 conda 的旧数据库干扰系统 sf。
不修改当前 shell 的 conda 环境，也不覆盖自定义 R 的配置。
以下命令只在手动执行时重建真实数据；任一步失败立即停止。

```bash
cd /mnt/d/scripts/0LOCAL/ukb
(
  set -e
  ./phe.sh --steps prep_raw,extract_fod,extract_pheno,extract_multi \
    --datasets vip,bbc,img,met,death \
    --reextract-fields p87,p20002,p20003,p20008,p22009,p22182,p40002,p41270,p41271,p41272,p41280,p41281,p41282 \
    --run-r FALSE
  GP_REBUILD_FULL_FST=TRUE SRD_YEAR_CAP=2026 ./phe.sh \
    --steps data_qc,vip_phe,ses,move,death,srd,icd,fod_ref,gp_prep,gp,biom,hla_pca,pgs,merge,phe4gwas \
    --icd-sources icd10,icd9,opcs4,srd --make-phewas FALSE
)
```

使用本机现有原始导出和 common 定义，强制更新 multi 提取和完整 GP 缓存。
重建 phe0/phe、SES、迁移、死亡、各疾病来源日期/计数、BBC/Prot/Met/Img、
HLA/PCA、gen/pgs、all.rds 和 ukb.phe。PGS/gen 从现有评分和基因型摘要
重新整理，不启动新的评分或基因型计算。merge 继续使用已有 diet.rds。
独立的 diet*.rds、PheWAS.rds、prot.pgs.rds、met.pgs.rds、prs.rds 不在本次范围。
drug 步骤也不运行：当前未提供其蛋白-药物映射输入，且它不是 all.rds 的依赖。
不需要先删除 Rdata；流程覆盖所管理的输出。
`move` 先保存计算完成的 `move.rds`，再绘图；底图加载失败时自动重试无瓦片地图。
绘图仍失败会明确记录并继续后续数据处理，旧完整图片保留；坐标或数据计算错误仍会终止。

`SRD_YEAR_CAP=2026` 是原始年份合法性边界；行政随访截止仍是 2023-04-01。
原始导出缺少 vip 映射中的可选 p23651（met.flagged），本次不虚构补值；
BBC 71、Met 251、Img 2145 个映射字段及必需 ICD/SRD 字段已核对存在。
这不代表已从 UKB 下载更新的数据 release。

重建成功后，在同一个 shell 运行完整日期审计：

```bash
./phe.sh date-check --Y cvd_afib,cvd_cad
```

报告分别写入 `/mnt/f/analysis/ukb/phe/cvd_afib/date-check.html` 和
`/mnt/f/analysis/ukb/phe/cvd_cad/date-check.html`。默认包括本机 GP/HES 原始证据。
